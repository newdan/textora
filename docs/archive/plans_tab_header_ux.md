# edit+ Tab Header 箭头区交互优化落地实施方案

本方案针对 edit+ 编辑器“左侧集中箭头、右侧新建按钮”的特殊布局，旨在消除空间割裂感，实现一套顺滑、符合直觉的 Tab 溢出管理体验。

## User Review Required (用户审核事项)
- **视觉映射策略**：由于操作在左侧（点击箭头），而效果在右侧（新 Tab 划入），为了弥补空间感，计划通过**两侧的边缘渐隐遮罩**和**平滑抽屉式动画**来建立视觉连结，请确认此设计方向。
- **溢出菜单位置**：计划在最右侧 `[+]` 按钮旁边增加 `[🔽]` (全部列表) 按钮。这会占用一定空间，请确认该入口放在 `[+]` 左侧还是右侧更符合现有的 UI 规范？

## Open Questions (待确认问题)
1. **动画基础设施**：当前 edit+ 的 UI 渲染层（Rust 侧及视图框架）对平滑滚动动画（Easing / Smooth Scroll）的支持度如何？是否有现成的插值或动画 API 可以直接调用？
2. **弹出层组件**：针对 Stage 5 的“所有 Tab 列表”，目前系统库中是否有可直接复用的 Menu / Popover 组件？

---

## 实施阶段划分 (Implementation Stages)

遵循 `AGENTS.md` 中“阶段切分、原子化实现、独立验证”的原则，我们将工作分为 5 个 Stage。

### Stage 1: 视觉组件与静态布局占位
**目标**：完成箭头、遮罩、菜单入口的静态 UI 渲染。
**原子工作**：
- [ ] 在 Tab Header 左侧渲染集中的 `[<]` 和 `[>]` 控件，作为固定独立区域。
- [ ] 在左侧箭头区右侧添加向右延伸的渐隐遮罩（Faded Edge）。
- [ ] 在右侧 `[+]` 新建按钮左侧添加向左延伸的渐隐遮罩。
- [ ] 在最右侧（`[+]` 旁）添加下拉菜单 `[🔽]` 占位图标。
**验证阶段**：
- 调整窗口宽度，确认遮罩和控件渲染符合预期，不会因 Tab 数量变化而发生布局坍塌。

### Stage 2: 滚动状态计算与箭头联动
**目标**：实现 Tab 滚动边界的精确计算与箭头可用状态管理。
**原子工作**：
- [ ] 核心计算：实时获取 `Total_Tab_Width` 与 `Viewport_Width`，以及当前的 `Scroll_Offset`。
- [ ] 状态逻辑：当 `Scroll_Offset <= 0` 时， `<` 左箭头置灰（Disabled，不隐藏）。
- [ ] 状态逻辑：当 `Scroll_Offset >= (Total_Tab_Width - Viewport_Width)` 时， `>` 右箭头置灰。
- [ ] 遮罩联动：处于左/右极值时，隐藏对应侧的渐隐遮罩。
**验证阶段**：
- 拖动 Tab 或改变窗口大小，验证到达最左侧或最右侧时，箭头置灰状态精准、实时切换。

### Stage 3: 步长控制与平滑滚动动画
**目标**：点击箭头产生连贯、符合预期的平滑滚动。
**原子工作**：
- [ ] 步长计算：设定单次点击 `<` 或 `>` 时，滚动的距离偏移量为 `Viewport_Width` 的 70% 左右。
- [ ] 边界约束：确保单次滚动后，`Scroll_Offset` 不会超出最大或最小合法范围。
- [ ] 平滑动画：将滚动偏移量与动画插值器结合，实现平滑位移效果（而非瞬间跳变）。
**验证阶段**：
- 疯狂点击左右箭头，验证滚动步长合理，且不会越界；过渡动画流畅。

### Stage 4: 焦点跟随的智能滚动 (Auto-Scroll to Active)
**目标**：外部切换 Tab 时，Header 自动响应滚动。
**原子工作**：
- [ ] 监听系统级别的 Active Tab Change 事件。
- [ ] 坐标判断：计算被激活的 Tab 的 `left` 和 `right` 坐标是否在当前的 `[Scroll_Offset, Scroll_Offset + Viewport_Width]` 可视区内。
- [ ] 智能位移：若在可视区外，自动计算出新的 `Scroll_Offset`，优先将其滚动到可视区中央，并触发平滑动画。
**验证阶段**：
- 使用快捷键（如切换上一个/下一个 Tab）从可视区切换到隐藏区的 Tab，验证 Header 是否自动滚动并居中展示该 Tab。

### Stage 5: 高级交互补齐（触控板与溢出菜单）
**目标**：补齐多模态交互和极端情况（多 Tab）管理手段。
**原子工作**：
- [ ] 触控板/滚轮：监听可视区的 `Wheel` 横滑事件，直接修改 `Scroll_Offset` 并更新 UI（优先响应硬件输入）。
- [ ] 溢出菜单：实现 `[🔽]` 图标的点击事件，展开 Popover，展示当前窗口所有打开的 Tab。
- [ ] 列表跳转：点击列表中的某一项，触发 Tab 切换事件，借由 Stage 4 的能力自动滚动并激活该 Tab。
**验证阶段**：
- 双指横向滑动触控板，列表应丝滑跟随；打开 30 个文件，通过 `[🔽]` 菜单可快速找到并跳转对应 Tab。
