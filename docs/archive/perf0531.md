# 性能优化执行方案

> 基于 `docs/editor_performance_playbook.md` 第 4/8/9/10 节，针对三个热点的原子化优化。

---

## 阶段 1：advance_cache 增量更新

**目标**：将 `shape_visible_lines` 中每帧 `clear + 重建 advance_cache` 改为脏标记驱动的增量更新，降低高帧率 + 超长行场景的 CPU 开销。

### 接口设计

```rust
// crates/app/src/app.rs — App 结构体新增字段
/// 行级脏标记：内容变化、viewport 变化时置 true
advance_cache_dirty: Vec<bool>,          // len == doc line count
/// 帧间可见行 keys，用于判断是否需要重建
prev_visible_keys: Vec<(u64, u64)>,      // (offset, length) pairs
```

### 步骤

| # | 内容 | 涉及文件 | 说明 |
|---|------|----------|------|
| 1.1 | 在 `DocumentView` 新增 `dirty_line_range(start, end)` 方法，编辑后调用标记受影响行 | `crates/app/src/document_view.rs` | 用区间而非逐行标记，减少调用次数 |
| 1.2 | 在 `App` 新增 `advance_cache_dirty: Vec<bool>` 字段，初始化时全 true | `crates/app/src/app.rs` | 初始全脏，首次帧全量构建 |
| 1.3 | 修改 `shape_visible_lines`：用 `(offset, length)` 做 key 比对上帧，命中且未脏则直接复用上帧 `advance_cache` 条目 | `crates/app/src/app.rs` | 核心改动点 |
| 1.4 | 帧结束后将本帧可见行 keys 存入 `prev_visible_keys`，清脏本帧可见行 | `crates/app/src/app.rs` | |
| 1.5 | 在 resize / 设置变化 / 滚动时将所有可见行标脏 | `crates/app/src/app.rs` | 覆盖所有失效源 |

### 边界情况 & 测试建议

- **边界**：快速滚动导致每帧可见行完全不同 → 退化为全量重建（正确性保障）
- **边界**：光标所在行 wrap 行数变化但 offset/length 未变（仅光标移动）→ advance 仍需重建该行
- **测试**：在 1 行 10MB 文件中打字，对比优化前后帧时间
- **测试**：连续快速滚动 + 打字混合操作，验证 advance_cache 不出现 stale 数据

## 阶段 2：超长行 wrap 结果缓存优化

**目标**：减少 `first_line_visual_lines` / `last_line_visual_lines` 的 `clone()` 分配，对极端长行做上限裁剪。

### 接口设计

```rust
// crates/app/src/app.rs — 新增结构体
struct CachedVisualLines {
    /// 最多缓存 MAX_WRAP_SEGMENTS 个段，超出按需重算
    segments: Vec<(usize, usize, f32)>,
    /// 原始 segment 总数（可能 > segments.len()）
    total_count: usize,
    /// 标记是否被截断（用于滚动时按需重算）
    truncated: bool,
}

const MAX_WRAP_SEGMENTS: usize = 512; // 足够覆盖 4K 屏幕单行，超出部分不缓存
```

### 步骤

| # | 内容 | 涉及文件 | 说明 |
|---|------|----------|------|
| 2.1 | 定义 `CachedVisualLines` 结构体和 `MAX_WRAP_SEGMENTS` 常量 | `crates/app/src/app.rs` | |
| 2.2 | 将 `first_line_visual_lines` / `last_line_visual_lines` 类型改为 `CachedVisualLines` | `crates/app/src/app.rs` | |
| 2.3 | 修改 wrap 循环：超过 `MAX_WRAP_SEGMENTS` 时只保留前 N 段，设 `truncated = true` | `crates/app/src/app.rs` 在 `shape_visible_lines` 的 wrap 循环处 | |
| 2.4 | 对 `last_line_clusters` / `first_line_clusters` 同步做上限裁剪 | `crates/app/src/app.rs` | |
| 2.5 | 在使用 `first/last_line_visual_lines` 的下游逻辑中处理 `truncated` 标记（如光标定位、滚动计算） | `crates/app/src/app.rs` | |

### 边界情况 & 测试建议

- **边界**：`MAX_WRAP_SEGMENTS` 设太小导致光标在行末时定位失败 → 需确保光标所在 segment 一定在缓存范围内
- **边界**：resize 后之前被截断的行需要重算 → resize 时清除 truncation 标记
- **测试**：1 行 1MB ASCII 文件，快速滚动，观察内存分配峰值
- **测试**：CJK 混合宽度字符长行，验证截断后光标定位正确

## 阶段 3：行索引增量重建

**目标**：编辑后仅重建受影响区间的行索引，避免对整个文档全量扫描。

### 接口设计

```rust
// crates/app/src/document_view.rs — DocumentView 新增方法
impl DocumentView {
    /// 增量更新行索引：给定插入/删除的字节偏移和变化长度，
    /// 找到受影响行，局部重建后续行的 offset。
    fn update_line_index(&mut self, edit_offset: usize, delta: isize);
}
```

### 步骤

| # | 内容 | 涉及文件 | 说明 |
|---|------|----------|------|
| 3.1 | 在 `GapBuffer` 新增 `line_break_positions()` → 返回 `&[usize]` 的行起始偏移集合（增量维护） | `crates/core/src/buffer/gap_buffer.rs` | 在 insert/delete 时同步更新 |
| 3.2 | 在 `DocumentView` 新增 `update_line_index(edit_offset, delta)` 方法：二分查找受影响行，从该行起重建 offset | `crates/app/src/document_view.rs` | |
| 3.3 | 修改编辑命令执行路径：替换 `rebuild_line_index_from_tb` 调用为 `update_line_index` | `crates/app/src/document_view.rs` 在 `execute_edit_command` 后 | |
| 3.4 | 保留 `rebuild_line_index_from_tb` 作为 fallback（打开文件时仍用全量重建） | 不改动 | 兼容性 |
| 3.5 | 新增单元测试：在 10 万行文件上做单字符插入/删除，验证行索引正确性 | `crates/app/tests/` | |

### 边界情况 & 测试建议

- **边界**：在文档首行/末行插入换行 → 索引边界正确
- **边界**：删除跨越多行的选区 → delta 为负数，后续行 offset 全部前移
- **边界**：Undo/Redo 后行索引恢复正确
- **测试**：10 万行文件，随机位置连续插入字符 1000 次，对比全量重建耗时
- **测试**：插入含 `\r\n` 的多行文本块

## 依赖关系 & 顺序

```
阶段 1 (advance_cache) ──┐
                         ├── 可并行开发，互不依赖
阶段 2 (wrap 缓存)  ────┤
                         │
阶段 3 (行索引增量) ────┘
         │
         ▼
阶段 4 (压力测试)  ← 在阶段 1-3 完成后运行，验证优化效果
```

阶段 1/2/3 相互独立，可并行推进。阶段 4 在所有优化完成后统一验收。

---

## 验收标准

| 指标 | 优化前（预估） | 目标 |
|------|----------------|------|
| 1 行 10MB 文件滚动帧时间 | >16ms | <8ms |
| 10 万行文件单字符插入后重绘 | 全量重建行索引 | 仅重建受影响行，耗时 O(affected) |
| 超长行 resize 内存峰值 | O(max_line_clusters × visible_rows) | O(MAX_WRAP_SEGMENTS × visible_rows) |
