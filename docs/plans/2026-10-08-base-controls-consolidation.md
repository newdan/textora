# 基础控件逻辑收敛

## 范围与边界

- `ui` 持有 `TextBox`、`Button`、`Label` 的交互、计时、文字排版与通用容器行为。
- `app` 与 `notora-app` 只提供纯展示输入、控件标识和业务动作映射；`ui` 不依赖产品状态。
- 分阶段修改，每阶段先用针对性测试固定现有问题，再实现并确保编译通过。

## 阶段

1. 修正 Notora 外壳按钮的激活语义：按下只建立按压状态，松开仍在按钮内才触发动作；弹窗和工具栏事件不能穿透到底层。
2. 使表单和搜索栏中的 `TextBox` 使用自身光标闪烁计时；让容器向运行时提供最早期限，并在数据刷新时保留同一控件的编辑状态。
3. 在 `ui` 提供可复用的按钮排列与事件路由能力，替换设置侧栏和同步页重复维护的按压、悬停索引。
4. 将三处一致的表单 `Label` 排版收敛成共享样式；让需要动态更新、裁切或换行的文案通过组件绘制。
5. 搜索栏内部的图标、文字操作改用 `Button`，产品搜索动作仍由搜索栏负责映射。

## 验证

- 每阶段运行受影响 crate 的定向测试和编译检查。
- 完成后运行 `cargo fmt --all`、`./scripts/verify.sh`；需要本机回环端口的同步测试在允许该权限的环境下补跑。
