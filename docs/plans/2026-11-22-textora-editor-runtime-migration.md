# Textora 共享编辑器宿主迁移

Textora 和 Notora 共用 `EditorRuntime` 的文档会话及编辑表面能力。Textora 应用层负责标签栏、侧栏、搜索焦点、菜单、同步及工作区持久化，以 `TabId` 和控件输入结构连接共享层。现有快捷键、Markdown 编辑意图、撤销分组及文件格式是迁移的兼容要求。

## 子任务与验收

1. **产品壳归属**。将 `UiShell` 和其专用 Dock 占位控件迁到 Textora，保留布局、焦点、覆盖层、辅助功能和现有测试。用架构检查验证共享宿主的边界。
2. **编辑事务**。以 Textora 的预验证和增量缓存失效为基础，统一两产品的事务执行。先验证非法的编辑后选区会导致部分写入，再验证拒绝事务时正文、版本和通知均保持一致。Textora 的输入路由使用运行时编辑接口，并保留剪贴板转换和产品层通知。
3. **滚动和指针**。共享标准编辑、插件与画布的处理逻辑，以产品壳的焦点、命中区域和平台事件作为输入。复查折行命中、连续点击、滚动条与画布缩放的现有测试。
4. **帧提交和编辑表面**。两产品共用 GPU 帧提交。将绘制入口逐步收敛到运行时，逐项验证 Textora 异步排版、搜索高亮、预编辑与画布覆盖层的兼容性。
5. **验收**。运行 `./scripts/verify.sh`，并检查产品接线中的低层状态访问是否仍有行为依赖。原生窗口交互需在真实窗口中验证。
