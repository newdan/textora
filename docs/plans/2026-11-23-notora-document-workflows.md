# Notora 文档工作流收敛

本记录对应《中长期架构演进计划》的专题 A。

## 标签附件

`DocumentRuntime` 按 `TabId` 持有 `TabWorkflowAttachment`，记录加密状态、解锁会话、保存诊断和一个挂起操作。关联笔记 ID 的进程内解锁缓存继续支持关闭标签后重新打开。自动保存仍由独立调度器跟踪。标签注销统一取消自动保存并移除附件。

一次挂起操作占用标签直到完成、取消或被新修订替代。另存、冲突重试、移入回收站、移动笔记和更新标题以枚举区分。保存完成按标签与内容修订号匹配。新编辑会释放尚未提交保存的旧操作。移动和移入回收站提示旧操作失效，标题更新会基于新修订重试。已关闭标签的保存完成事件不会重新创建附件。

回归测试覆盖替换预览后释放旧保存错误、关闭标签后释放挂起状态、同一标签上的挂起操作争用及新编辑替代旧移动请求。

## 产品事件与外部文件

- `NotoraApp` 直接公开组合根并接收 winit 平台事件。组合根从产品事件队列取出完成结果，按最早的有效期限唤醒。Reducer 效果仍按顺序执行，后续动作仍进入原有 FIFO。
- 文件另存完成后直接产出路径规范化请求。冲突重试收到磁盘版本后核对标签、路径和内容修订，再开始相应保存。公开的打开和保存请求类型保留原模块路径。
- 外部文件后台读取后将 `LoadedDocument` 直接安装到当前选择。重复打开恢复已注册的标签。现有选择代数、编辑标题提交及会话持久化规则继续生效。

## 索引唤醒与文件操作

- 索引线程阻塞读取索引命令、文件监视事件和关停指令的统一通道。仅当文件存在确认有截止时间时使用定时等待。监视器故障后，索引命令继续可用。索引线程可以在平台监视器注册阻塞时独立退出。
- 外部文件的冲突副本完成事件归属文档，即使没有笔记库也可以保存。工作区笔记的副本结果仍按工作区代数处理。
- 笔记目录移动与标题改名复用 Markdown 入链检查、变更日志、文件移动和回滚。Catalog 更新失败时恢复源文件。进程在 Catalog 路径提交后中断时，启动恢复确认目标文件并完成日志。

## Reducer 和壳层刷新

- `NotoraState::reduce` 按导航、卡片、工作区、外部文件、编辑器和对话框分派。原有变体的效果顺序保持一致。标题失焦仍由只读状态判断决定。
- 导航行和动作映射、编辑器的目录与标签动作映射在输入不变时跨帧共用。目录草稿、导航范围、目录结构、活动文档或正式标签变化会刷新受影响的输入。
- 编辑器头部从 Catalog 的结构化星标和正式标签标识渲染，卡片摘要仅用于卡片展示。

专题 A 的全仓验证通过。Notora 通过 479 项库测试，`notora-core` 通过 135 项。
