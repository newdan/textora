# Textora Lite 输入延迟测量

## 指标

应用内延迟从 `App::do_window_event` 入口计到携带该输入的帧从 `present()` 返回。分阶段记录事件处理、重绘等待、帧构建、获取纹理、编码、提交和帧尾时间。此时 GPU 和显示合成仍可能在处理该帧。15 ms 是指定场景下应用内延迟的 P95 目标。验收屏幕可见时间需另行测量。

按键和 IME 提交以活动编辑区同一文档的编辑代数变化为准。预编辑以运行时接受且状态变化为准。同一帧的各事件保留自己的起点及类别。若后续 IME 事件在同一帧提交前替换了预编辑，日志标记 `superseded=1`。按类别统计延迟时排除这些行，并记录覆盖数。按帧统计首个输入的等待时使用 `index=0`。正常重绘但提交未成功时，输入等待后续成功提交，并累加 `skipped_redraws`。切换活动标签或采集缓冲达到上限会丢弃待测样本，下一组成功写出的记录携带 `discarded_inputs`。

帧尾耗时和无障碍发布、IME 坐标更新的分项单列。帧尾工作如果延后了下一输入回调，对应等待发生在下一次计时开始前。

## 操作与归档

1. 用 `./scripts/bundle-textora-lite-mac.sh` 生成 Lite 包。每轮使用新的 `TEXTORA_INPUT_LOG` 文件，以便同一次采集的帧编号能和场景对应。关闭诊断环境变量时，无计时日志与后台写入线程。
2. 用 Computer Use 逐键操作临时文档。短文档使用约 100 行，采集至少 200 次普通编辑键。切换至系统中文输入法，逐键拼写并选词，采集至少 100 次可结算的预编辑和 50 次提交。记录工具输入方式、设备、macOS 版本、窗口大小和可确认的刷新率。
3. 用约 10,000 行的临时文档分别在中部和尾部重复普通与 IME 输入。冷字形另起进程，记录首次输入与再次输入的耗时。对自动输入工具发不出实际 IME 事件、无法确认冷字形或样本不足的场景如实标记。
4. 按场景、类别、刷新率汇总样本数、P50、P95、最大值以及超过 15 ms 的阶段分布。P99 对样本量更敏感，少量提交仅用于初筛。优化前后保持文档、输入法、设备和场景一致，根据基线热点决定要改的代码。

## 基线与复测

在 Apple M4 Pro Mac mini、macOS 26.3.1 上用 Lite 优化构建采集。Computer Use 逐键发送按键，中文使用桌面上已启用的拼音输入法实际组合和选词。主要采样窗口为 800 × 600 逻辑像素。系统未报告物理显示器刷新率。A/B 使用同内容文件，各自从干净工作区启动。大文档长度约 720 KB，中部和尾部的编辑位置及按键序列一致。短文档两次试打的初始光标相差几个字符。每个场景每个构建采集一轮，以下为应用内延迟，单位为 ms。

| 短文档 | ImePreedit | 244 → 245 | 10.67 → 10.01 | 14.31 → 15.04 | 14.92 → 15.16 | 15.08 → 15.38 |
| 短文档 | ImeCommit | 51 → 51 | 11.60 → 11.16 | 25.60 → 15.45 | 38.25 → 19.74 | 38.25 → 19.74 |

| 大文档中部 | ImePreedit | 297 → 297 | 5.08 → 9.00 | 14.89 → 14.04 | 15.35 → 15.23 | 15.63 → 15.30 |

每轮记录 0 次跳过提交及 0 条缓冲丢弃。表中 IME 样本已经排除同帧内被覆盖的预编辑。约 50 次提交的 P99 仅供观察尾部样本。

编辑事务的两处字素边界校验都从文档起点扫描，每次按键重复遍历前面的内容。两处现已复用从最近 LF 后开始的校验，与原导航规则在 CRLF、组合附标、旗帜和 ZWJ 序列上做逐字节对照。大文档尾部 IME 提交的处理阶段 P95 从 12.51 ms 降至 2.85 ms。大文档中部普通键的排队阶段 P95 从 199.26 ms 降至 3.21 ms。修复后短文档仍有两项略超过 15 ms，大文档中部的 IME 提交也略超。剩余慢样本主要在重绘排队与获取纹理。

首次输入“囊”及重复输入 10 次，优化前提交首样本 15.41 ms、后续中位数 15.01 ms，优化后为 12.46 ms、14.05 ms。优化后首样本帧构建 1.47 ms，后续中位数 1.40 ms。该对照用编辑区首次出现作为冷字形近似，未记录图集命中状态。

另用相同短文档与按键序列试验 `desired_maximum_frame_latency=1`。普通键、预编辑、提交的 P95 分别为 12.30、15.05、15.65 ms。默认值 2 对应 11.53、15.04、15.45 ms。交付包使用默认值 2 和 `AutoVsync`。

优化后的 `./scripts/verify.sh` 已通过。原始日志及采样分析脚本保存在本机临时目录 `/tmp/textora-f489-input-study`。

## IME 重绘去重

三项待复测中，短文档预编辑的 18 个超标样本都只有一个输入事件，纹理获取的中位耗时为 9.88 ms。短文档提交的 5 个超标样本中，重绘排队的中位耗时为 10.87 ms。大文档中部提交的 5 个超标样本中，重绘排队与纹理获取的中位耗时分别为 4.98 ms、6.18 ms。

预编辑变更会立即调用 `window.request_redraw()`，同时设置运行时的重绘标记。应用此前在绘制完成后才消费该标记，导致已满足的请求再安排一帧。应用现在在渲染入口消费旧标记，同时保留帧内新增请求。回归测试覆盖从发出请求到尝试绘制时的标记状态。复测沿用前次输入序列和默认表面配置。

回归测试在修复前失败、修复后通过，全量 `./scripts/verify.sh` 通过。修复版已打包并启动。采集时桌面锁屏，复测日志仍为空，三项 P95 等待实测。
