- [x] A 公共规则：`crates/ui/src/typography.rs`、对应测试、`lib.rs` 导出。产物为字节边界 gap 与 Natural/Verbatim；覆盖文字类别、技术 token、保护范围与不同字号。验证 `cargo test -p textora-ui typography`。
- [x] B 源码语义：`crates/markdown/src/typography.rs`、对应测试、`lib.rs` 导出。复用 `ParsedMarkdown` 的事件及源范围，输出正文源区间并提供区间切片；代码、语法、HTML、metadata、自动链接保护。验证 `cargo test -p textora-markdown typography`。
- [x] C 统一几何：在 UI 排版中把 gap 纳入实际换行宽度，去除跨行 gap，并产生可共用的 cluster 几何。以可控字宽验证临界换行、光标边界和重复执行。
- [x] D TXT 状态协议：设置及文档状态携带策略与语义范围，失效逻辑包含策略/范围版本。单独验证内容不变时切换策略的重排。
- [x] E TXT 前台接入：替换旧补齐入口，长行子区间携带上下文，缓存与渲染共用最终几何。验证临界行宽与命中位置。
- [x] F TXT 后台接入：请求携带同一状态，worker 和 fallback 采用共同规则，校验后台与前台边界。
- [x] G Markdown 样式布局：在整形后、换行前按正文语义加间距，样式段和投影共用输出；跨样式只加一次。独立覆盖段落、列表、表格与代码。
- [x] H Markdown 源码接入：源范围传递到 TXT 编辑路径，按文档修订更新而非逐帧解析，正文优化而标记保留。
- [x] I 用户入口：接入自然/原样设置及持久化，清理旧规则的正文调用，验证切换、恢复和无文本修改。
- [x] J 综合验收：相关 crate 测试、基准比较与 `./scripts/verify.sh`，审查全量改动和风险。

每项实施前由负责的 Luna 明确不超过 3 文件的细分范围和实际 API，主智能体检查衔接。上述集成阶段如果涉及更多文件，继续拆分协议、调用方、测试三个方向，不一次性跨模块无边界修改。
