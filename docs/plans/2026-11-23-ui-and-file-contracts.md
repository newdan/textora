# 控件坐标、文件保存与字形相位

## 控件

- Dock 的填充组件和吸边组件使用局部坐标。Dock 将父坐标转换为局部指针位置，并为绘制与无障碍节点加回布局偏移。标签栏直接写入父级 `DrawList`，溢出菜单使用转换后的窗口坐标。
- 滚动条接收文档显示行或连续像素。表单直接提供可见高度、内容高度和当前像素偏移。
- 编辑工具栏通过 `EditorToolbarAction` 传递命令与菜单状态。弹出菜单的分隔线没有关联命令。
- 侧栏宽度以逻辑像素保存，布局、动画和命中测试按当前 DPI 转换。设置文件继续读取原有 `sidebar_width` 键，缺省值沿用 220 逻辑像素。

## 文件与字形

- 两个保存入口共享独占暂存、只读检查、Unix 权限保留、文件同步、原子替换和父目录同步。条件保存使用磁盘修订号复查，并返回对应本次提交内容的修订号。跨设备重命名错误会在重新解析的目标目录中再暂存一次。
- 行尾扫描跨读取分块保留待匹配的 CR。GBK 与 GB18030 共用解码器，通过四字节序列判定文件是否使用扩展编码。
- 字形定位、字形图集、源码编辑和画布标签共用四分之一像素相位。图片顶点记录负 U 的编码和预乘色采样约定。

## 验证

- `cargo fmt --all -- --check`、`cargo check --workspace --all-targets` 和 `./scripts/verify.sh` 均通过。整仓复验中 UI 通过 1,173 项、文本核通过 170 项、渲染通过 31 项。
- `cargo test -p textora-sync` 在允许本地回环端口后通过 29 项库测试和 1 项契约测试。真正启动 Syncthing 的可选用例保持默认忽略。
- Textora 与 Notora 的原生二进制均构建成功。原生窗口的操作记录与待补验项目见 [Textora 共享编辑器绘制迁移](2026-11-23-editor-runtime-paint-convergence.md#验收记录)。
