# 编辑器标签生命周期与工作区恢复

本记录对应《中长期架构演进计划》的 1.3。

## 标签生命周期

- Textora 通过 `EditorRuntime::install_prepared_tab` 和 `activate` 打开或切换标签。`ActiveDocumentChanged` 驱动延迟加载、视口更新和工作区持久化。重复激活没有工作区变更时，不产生写盘效果。
- 关闭请求和保存后确认分别进入 `request_close` 与 `confirm_close`。`CloseRequested` 包含固定或待保存原因，产品层负责展示对话框。收到 `TabClosed` 后，产品层清理本地状态。异步保存结束时，宿主会再次检查脏状态，避免把后续编辑一并关闭。
- 关闭活动标签和切换标签前，由宿主取消原编辑器的指针捕获。Notora 的内部关闭流程也使用标准确认接口。宿主确认关闭后，Notora 清理文档注册和自动保存状态。

## 工作区恢复

Textora 将持久化文档逐项恢复到空的 `EditorRuntime`，由宿主管理文档和视图的配对注册。恢复保留草稿、工作区顺序和视图状态。后台文件标签维持延迟加载，恢复时先校正越界的活动索引，再加载该标签正文。所有标签装载后激活目标标签。启动恢复期间不触发额外持久化。

## 验证

恢复相关的 22 项 Textora 测试通过，覆盖视图切换、脏草稿、工作区活动索引越界和最近文件打开。

完整的 Textora 宿主迁移切片通过 `./scripts/verify.sh`，其中 Textora 库通过 878 项，共享壳层通过 529 项并忽略 1 项。
