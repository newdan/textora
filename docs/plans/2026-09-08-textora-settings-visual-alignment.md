# Textora 设置界面风格对齐

目标：参考仓库内 Notora 设置页，统一分类、间距、控件比例与窄屏排列。

架构：继续由 app 组合通用设置与同步页；ui 只接收 SettingsViewInput，沿用现有基础表单、主题语义和类型化动作。

## 子任务一：设置表单

- 修改 `crates/ui/src/widgets/settings_view/widget.rs`：外观仅保留主题；字体、字号和行高移入编辑器；简化说明并明确 Enter 提交。
- 侧栏采用 152/104 逻辑像素，紧凑阈值 520；内容内距 20/12，侧栏间隔 12，与 Notora 一致。
- 分段按钮等分可用空间；按表单内容宽度切换双列与上下排列，行高同步调整。缩放只改几何，保留文本编辑状态。
- 在同模块测试中覆盖分类归属、按钮边界、1x/2x DPI、窗口缩放后输入提交；更新分类迁移影响的已有测试。
- 验证：`cargo test -p textora-ui settings_view -- --test-threads=1`。

## 子任务二：产品弹层对齐

- 修改 `crates/app/src/textora_settings_overlay.rs`，同步侧栏与表单间距，让通用设置页和同步页在宽窄窗口均对齐。
- 更新模块内布局期望，验证外观、编辑器、界面、同步分类及事件路由。
- 更新 `crates/app/src/app_lifecycle.rs` 的端到端测试：点击编辑器分类后，再验证字号输入和 Enter 提交。
- 验证：`cargo test -p textora-app settings -- --test-threads=1`。

## 最终验证

运行 `cargo fmt --all`、`./scripts/verify.sh`。检查最终 diff 中 UI/app 依赖边界和未使用代码。记录实际验证结果与环境限制。

- `./scripts/verify.sh` 全部通过：架构边界、格式、Clippy，以及 4912 项测试通过、0 失败、5 项忽略。
