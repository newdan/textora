# 接手成本治理实施计划

> Status: active
> Owner: 项目维护者
> **执行方式：** 每项独立审查和验证。当前架构从 [新人接手指南](../onboarding.md) 进入；本文件只记录迁移顺序，不是另一份架构说明。

**目标：** 让读者能沿实际数据流定位行为，不必先辨认别名、历史实验或整套运行时回调。

**边界：** 不改变文件格式、标签 ID、事件顺序、编辑和保存语义。产品保留自己的交互策略，`ui` 继续只接收纯数据和通用交互输入。跨层工作合并前运行 `./scripts/verify.sh`，不以本机通过代替其他 CPU 后端验证。

## 一、去噪与命名

- [x] 将五份根目录历史草稿移到 `docs/archive/`，在文档索引指向唯一的当前架构指南。用 `cmp` 确认归档内容未改动。
- [x] 在各消费包及基准、测试中使用 `textora_core`。Cargo 包名仍为 `textora-core`；Rust 标准库的 `core` 与 `ui::core` 不受影响。用 `cargo check --workspace --all-targets` 检查全部目标。
- [x] 退出 Textora 的四个重命名导入：`dirty_snapshot`、`workspace_store`、`input`、`tab`。用实际定义处的路径替换，不动公开的开发支持 API。
- [x] 核对低层职责。`stdext` 提供 UTF-8 字节解码和通用内存填充；编辑器内核用这份解码器实现面向文档的字素和光标导航，其 SIMD 包涉及换行、行坐标和搜索。目前没有两份等价实现可删。`memchr2` 的通用扫描归属可单独调整，但不要在本轮搬运仍有旧 LoongArch 分派的实现；需要该目标的编译基线和既有页边界、首命中、首次并发初始化用例。

## 二、拆文件并收窄 Notora 回调

- [x] 外置运行时、状态、工作区控制器、渲染与文本框的内联测试，保持原测试模块名和覆盖。渲染按输入模型、事件路由、绘制拆分；文本框按存储、输入和绘制拆分。两个组件的生产文件低于 800 行，渲染层叠顺序断言指向迁移后的绘制文件。
- [x] 让 `PersistenceRuntime` 消费持久化完成结果：设置完成只更新持久化状态并安排刷新；会话持久化失败仍通过产品动作报告。工作区启动完成直达已有处理函数。对 `NotoraProductEvent` 保持同一条 FIFO，不另建队列。
- [x] 移除 `DocumentCommandTarget`。组合根按原顺序消费 `DocumentOutcome` 与命令；保存重试直接调用 `DocumentRuntime`，另存为只借用 `ActionRuntime` 与 `DocumentRuntime` 并返回关闭或报错动作。
- [x] 移除文档和工作区完成事件的整机回调及共用回调 trait。工作区事件仍在 `NotoraProduct` 按作用域过滤；解锁代次与当前冲突由 `ActionRuntime` 匹配，文档写入仍由 `DocumentRuntime` 校验标签与修订号。回归测试交错发送持久化和文档事件，验证 FIFO 及过期选中代次过滤；另存关闭测试让真实保存 worker 写入，再处理完成事件。
- [x] 移除 `NotoraEffectTarget`。产品 effect 在组合根直接调用相应组件或产品协调方法，返回的后续动作仍进原队列；壳层 effect 继续使用只借用所需组件的 `RuntimeShellEffectTarget`。
- [ ] 单独复现并处理既有另存边界：写入后、路径规范化前目标消失时，目前报错路径不清除待关闭标记，下一次关闭可能仍被视为保存中。本轮不改变该行为。

## 三、迁移领域边界

- [x] 将加密笔记创建、冲突副本和解锁组件移至 `notora-app`；敏感输入原语与可复用表单组件仍留在 `ui`。思维导图样式面板组件与已存在的面板会话代码一同归到共享壳层，暂保留原控件事件协议。
- [x] 将 `mmf` 与 `mindmap_view` 作为一组移入 `textora-mindmap`；Markdown 解析和流式投影不反向依赖画布。两者在文本内核共用字素边界算法，不改分段规则或字体排版策略。
- [ ] 在宿主对齐时再解开思维导图面板停靠、标签状态与主题动作协议的耦合；保留对旧主题 ID、路线优先级和画布编辑/拖拽的支持。
- [x] 纯文本点击共享纵向可视行查找和横向字符簇查找。保留字节与字素偏移、各自的零宽簇和浮点中点规则，以及 Textora 的可视行亲和性。回归覆盖分数滚动、折行、多字节簇、零宽簇和中点舍入。
- [x] 纯文本选区共用源码行字节范围和 Shift 单击的锚点初始化，Textora 内部按词与按行拖选只保留一份锚点计算。保留折行亲和性、多击与 Shift 的优先级、无命中处理和拖选折返策略。回归覆盖多字节源码行、空行、文件末尾和拖选折返。
- [x] Textora 纯文本、只读预览和自绘视图共用 [`MouseState::record_editor_press`](../../crates/appkit-shell/src/mouse_state.rs)，不移动各分支的计数时机。与共享壳层的时距边界和重置条件已核对，见下表；不合并状态机。
- [ ] 继续对齐两端宿主，不整批替换 `mouse.rs`、插件拖拽或窗口事件链。共享机制不接管 Textora 的同步、菜单或 Notora 的笔记自动保存、首帧恢复、退出刷盘。
- [x] 双产品已用隔离配置和临时纯文本文件走查编辑器焦点、点击、已有焦点时的拖选和已保存窗口关闭。Notora 从文件卡片直接起拖的首次异常另记，见 [2026-11-20 原生窗口走查](../native-window-walkthrough-2026-11-20.md)。
- [x] 原生复测双产品脏文件窗口关闭及切回后键盘编辑。Textora 退出前保存到源文件，Notora 保留源文件并写可读快照；Textora 的原光标位置未在本次观察中保留。
- [x] Notora 失败序列已追踪到原生窗口失焦：坐标正确，产品路由切到编辑器，但输入上下文仍为 `Inactive`，未建立捕获。见[事件追踪](../native-window-walkthrough-2026-11-20.md#notora-原生拖选事件追踪)。
- [x] 真实鼠标验证窗口持续获焦时可从卡片列表焦点直接起拖，松手保留选区。独立拖选也精确选中 `efgh`，不根据失焦的自动化重放改变业务行为。
- [ ] 双产品的真实中文 IME 预编辑和候选提交待补测。自动化输入未进入候选状态，不以普通按键或粘贴代验。

### 编辑区多击规则核对

| 条件 | Textora 的 `MouseState` | 共享壳层的 [`PointerClickTracker`](../../crates/ui/src/core/widget.rs) |
| --- | --- | --- |
| 两次按下的间隔 | 截断到整毫秒再比较；实际小于 501 ms 可续计 | 直接比较 `Duration`；实际不超过 500 ms 可续计 |
| 两次按下的距离 | 上次按下为基准，有限坐标下欧氏距离不超过 5 物理像素；最多三击 | 同左 |
| 超出时距或距离 | 本次按下成为新一轮第一击 | 同左 |
| 主动重置 | 释放和窗口失焦不会清除此计数；到达计数点的自绘按下即使后续命中画布控件、拖拽对象或无编辑目标，也照常计数 | 窗口失焦时清空；在有已绘制编辑区时，转入画布控件或画布拖拽、文本选区未能建立或放置、以及未通过指针输入门槛的按下都会清空 |

共享壳层的[指针入口](../../crates/appkit-shell/src/editor_runtime/editor_pointer.rs)若没有已绘制编辑区，会提前返回，不清点击历史；正常释放也不清。这里的 5 像素只用于多击识别，不是 Textora 插件拖选的 5 逻辑像素门槛。
