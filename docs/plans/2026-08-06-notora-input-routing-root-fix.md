# Notora 输入路由根因修复方案

## 背景

Notora 将编辑器输入迁移到 `appkit-shell::EditorRuntime` 后，最近连续出现了 mmap 展开/收起无效、hover 消失、语义光标缺失，以及滚动条与缩放行为不稳定等问题。这些现象不是独立的控件缺陷，而是产品 UI、共享编辑器运行时和插件画布之间的输入契约没有完整迁移。

本方案覆盖鼠标移动、按下/释放、编辑器选择、画布控件、源对象拖动、系统光标、覆盖式滚动条、滚轮平移和锚点缩放。目标是建立单一且可测试的路由协议，不再由产品层复制旧 Textora 的分支逻辑。

## 根因

1. `EditorRuntime` 原先只处理文本选择和画布拖动，没有在移动事件中同步 `PluginMessage::SetCanvasPointer`，因此 mmap 渲染器收不到 hover 坐标。
2. 画布控件命中仅存在于旧应用路由，共享运行时没有执行 `CanvasControl` 的编辑计划，导致展开/收起点击无效。
3. Notora 的 `NotoraEventRoute` 只返回消费状态和产品动作，丢弃 `EventCtx::cursor_hint`。滚动条、分隔条、按钮等 UI 控件虽然正确设置了光标提示，窗口层却永远收不到。
4. mmap 的 `TextCaret`、`SourceObject`、`CanvasControl` 和拖动状态需要不同系统光标；这类编辑器语义反馈仍留在旧 `crates/app`，共享运行时没有输出协议。
5. 鼠标移动采用“产品消费后才进入编辑器”的单一路径。指针进入滚动条或其他控件时，插件无法收到 `None` 清除旧 hover；反过来若简单地总是转发，编辑器默认光标又可能覆盖产品控件光标。
6. 滚轮与捏合缩放在产品层直接计算 `1 + delta`。该公式不满足正负输入互逆，线滚轮一次就可能产生 2 倍或接近零的突变，也在产品之间复制了平台事件换算。

## 目标契约

### 路由分层

- `ui` 控件只负责自己的命中、hover、捕获状态和 `cursor_hint`，不访问产品状态。
- `EditorRuntime` 负责编辑器区域内的文本选择、插件 hit-test、插件画布指针、画布控件编辑和源对象拖动，并输出产品无关的 `EditorOutcome`。
- Notora 只组合两路结果并应用到窗口。它不解释 mmap 类型，也不复制插件命中规则。

### 鼠标移动

一次移动必须同时完成两件事：

1. 产品 UI 更新自身 hover，并返回可选系统光标。
2. 编辑器运行时将屏幕坐标同步给当前自绘画布；指针不在编辑器且没有编辑器捕获时同步 `None`。

最终光标优先级固定为：产品 UI 明确提示 > 编辑器捕获状态 > 插件命中语义 > 编辑器区域默认文本光标 > 默认箭头。产品控件的光标不能被编辑器回退值覆盖。

### 捕获

- 产品滚动条捕获和编辑器捕获是两个独立状态，各自由所有者结束。
- 捕获期间的移动和释放必须继续送达捕获所有者，即使指针已经离开原始矩形。
- 编辑器画布指针在编辑器捕获期间可以位于矩形外；窗口失焦时必须清空。
- 非捕获移动仍要送达编辑器运行时，用于在进入产品控件时清除插件 hover。

### 坐标

- 插件 hit-test、`SetCanvasPointer` 和缩放锚点统一使用窗口屏幕坐标。
- 覆盖式滚动条在产品 UI 内部接收相对画布矩形的局部坐标。
- `CanvasViewportSnapshot` 是屏幕坐标与内容坐标转换的唯一实现；产品层不得自行换算画布滚动位置。

### 滚轮与缩放

- 无命令修饰键：滚轮转为 `PanBy`；行单位通过共享常量换算为像素，像素单位保持触控板精度。
- 命令或控制修饰键：垂直滚轮转为指数缩放因子，正负等量输入互为倒数。
- 捏合：同样通过共享指数换算，不再使用 `1 + delta`。
- `CanvasViewportSession` 继续负责最小/最大缩放约束和锚点稳定，输入层只生成合法动作。
- 非有限输入必须被拒绝，极端单次输入必须限幅。

## 分阶段实施

### 子任务一：插件指针与编辑器语义光标

涉及 `appkit-shell` 的运行时契约、指针处理和测试，限制在三个文件内。

- 为 `EditorOutcome` 增加可选系统光标输出，并定义合并时后到的明确值覆盖前值。
- 一次插件 hit-test 同时驱动语义光标和按下动作，避免产品识别 mmap。
- 鼠标移动同步或清空 `SetCanvasPointer`。
- 覆盖 CanvasControl、TextCaret、SourceObject、ClearFocus、拖动捕获、移出编辑器和窗口失焦测试。

### 子任务二：Notora 产品控件光标与路由优先级

涉及 Notora 的事件路由、应用组合和测试，限制在三个文件内。

- `NotoraEventRoute` 保留 `EventCtx::cursor_hint`。
- MouseMove 同时计算产品与编辑器反馈，产品光标最后应用。
- MouseDown/MouseUp 保持产品消费优先，但捕获所有者始终收到释放。
- 覆盖按钮、分隔条、画布滚动条、编辑器画布之间的切换测试。

### 子任务三：共享画布手势换算

涉及共享画布视口和 Notora 事件适配两个文件。

- 在 `canvas_viewport` 提供纯函数，将行滚轮、像素滚轮和捏合量转换为动作。
- 使用指数缩放和语义化灵敏度/限幅常量。
- 覆盖正负互逆、零输入、非有限输入、Shift 横向平移和屏幕锚点稳定测试。

## 回归矩阵

| 场景 | 插件 hover | 系统光标 | 捕获/动作 | 视口 |
|---|---|---|---|---|
| mmap 节点正文 | 节点高亮 | Text | 文本定位 | 不变 |
| mmap 节点空白 | 节点高亮 | Grab | 可开始拖动 | 不变 |
| mmap 展开按钮 | 控件高亮 | Pointer | 应用折叠编辑 | 不变 |
| mmap 拖动中移出编辑器 | 持续更新 | Grabbing | 持续并正确释放 | 不变 |
| 指针进入画布滚动条 | 清空 | Default | 滚动条可捕获 | 拖动更新 |
| 指针进入分隔条 | 清空 | EwResize | 分隔条可捕获 | 不变 |
| 普通滚轮 | 保持 | 保持 | 不触发编辑 | 平滑平移 |
| 命令滚轮/捏合 | 保持 | 保持 | 不触发编辑 | 锚点稳定缩放 |
| 窗口失焦 | 清空 | 不要求 | 所有编辑器捕获结束 | 不变 |

## 验证门槛

每个子任务先运行对应 crate 测试；全部完成后依次执行 `cargo fmt --check`、架构检查、workspace clippy、workspace tests 和 `./scripts/verify.sh`。任何新增失败必须定位到具体契约，不通过额外布尔状态或重复产品分支兜底。
