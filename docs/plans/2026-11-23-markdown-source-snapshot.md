# Markdown 源码快照与解析复用

文档缓冲区继续负责可写文本与编辑事务。宿主发送的只读文本转为 Markdown 快照，视图、引擎、布局和解析结果共享其字符存储。快照按需生成解析事件和结构树。相同字节的再次同步可以复用解析，原有事务版本用于检查编辑请求。

## 实施阶段

1. 在真实编辑视图上记录解析调用，覆盖编辑计划、候选表格验证和视口重排。共享从宿主转移来的源码分配。
2. 将编辑规则和语义命令接到快照。源码范围、围栏类型和原始段落边界继续供编辑规则使用。布局复用解析事件，并按需加上编辑用空段落。仅编辑规则需要未改写的结构树时才在快照内缓存它。候选编辑和 IME 替换文本各自持有独立快照。
3. 经插件消息返回表格操作能力和源码字距的保护范围。Textora 与 Notora 从有快照的视图取结果，纯源码模式继续从文档读取。整体替换文档或恢复 Markdown 编辑视图时主动同步源码，以处理缓冲区 generation 被复用的情况。
4. 运行 Markdown 默认和精简配置的测试，并执行 `./scripts/verify.sh`。检查重排不会重解析原文，候选表格验证只解析候选文本一次。
