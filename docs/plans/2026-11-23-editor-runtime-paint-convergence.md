# Textora 共享编辑器绘制迁移

本记录对应《中长期架构演进计划》的 1.1。基线是收尾提交 `5df4c22`。

## 实施切片

1. **帧提交。** Textora 与 Notora 统一由 `EditorFrame::drain_into` 写入基于平台与主题的 Gamma，GPU 提交只上传顶点并呈现。
2. **宿主绘制契约。** `EditorPaintOptions` 接收已准备的插件内容几何、纯文本起点、搜索高亮及光标策略、后台预排版宽度。宿主统一生成内容与装饰顶点，并按编辑区裁剪。Notora 沿用默认策略。
3. **Textora 渲染接入。** 产品层同步插件交互状态、解析画布滚动条并布局窗口控件，随后将编辑表面交给宿主。源码编辑的行号背景、高亮、光标和预编辑使用共享绘制。保留产品层提供的目录间距、侧栏留白和插件内容矩形。
4. **清理重复状态。** 后台纯文本排版的结果消费与预排进入共享绘制流程。Textora 通过宿主已绘制的光标几何定位源码输入法候选窗。

## 验收记录

- 行号栏回归覆盖 2× 缩放与固定侧栏同时存在时的顶点坐标。
- 画布回归覆盖当前帧应用同步后的滚动条输入，并发布共享编辑区边界。
- 共享绘制定向测试 8 项通过。目录修复后的 `./scripts/verify.sh` 通过，其中 Textora 库测试 879 项、Notora 库测试 479 项。
- 2026-11-24 在 macOS 原生 Textora 窗口中确认了亮暗主题正文、目录跳转和折行后的粗体中文点击。插入一个汉字、撤销、重新插入并保存后，以字节比较确认仅修改了预期字素位置，Markdown 标记与源码换行保持一致。
- 走查发现从 Markdown 带着目录切到源码时，目录会挡住源码行首。新增复现测试并确认失败后，修复目录可见性与 Dock 布局失效逻辑。原生窗口复验确认切到源码时目录收起、行号与行首完整，切回 Markdown 时恢复目录且标题跳转正常。
- Textora 源码视图的浅色和深色主题均确认查找框获得焦点后正文光标变淡。查找词进入搜索框，正文中只高亮一处匹配，磁盘文件字节保持一致。
- Notora 使用独立临时配置打开外部 Markdown。按 [编辑走查](../onboarding.md) 缩窄窗口、在折行后的粗体内插字、撤销、重新插字并保存，随后切到源码确认逻辑行和 Markdown 标记完整。亮暗主题正文均已查看，两个产品保存的样例逐字节一致。接入窗口后的首次点击未移动到预期位置，撤销后复验通过，再次缩放后的首次点击也命中了目标。
