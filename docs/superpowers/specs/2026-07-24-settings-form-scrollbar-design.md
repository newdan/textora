# 设置表单滚动条设计

## 目标

解决设置弹窗高度不足时，长表单内容被裁剪且缺少可见滚动提示的问题。

- 设置弹窗默认高度从 440 逻辑像素提高到 560 逻辑像素。
- 继续使用现有居中弹窗布局，并保留窗口高度 90% 的上限。
- 在通用 `FormView` 中集成现有纵向 `ScrollbarWidget`。
- 短表单不显示滚动条；长表单支持滚轮、拖动滑块和点击轨道翻页。

## 非目标

- 不修改同步资料库的数据加载、持久化或 Syncthing 控制逻辑。
- 不创建新的滚动条控件或滚动条主题。
- 不增加横向滚动。
- 不改变表单行、表单分区或同步页的业务结构。

## 方案

### 弹窗高度

`crates/app/src/settings_overlay.rs` 中的设置弹窗首选高度改为 560 逻辑像素。现有
`min_margin` 和 `max_height_ratio` 保持不变，因此较小窗口仍会自动缩小弹窗，避免越界。

### FormView 组合

`FormView` 新增一个内部持有的纵向 `ScrollbarWidget`。滚动条使用
`SCROLLBAR_RESERVE_PX` 作为右侧交互宽度，覆盖绘制在表单视口右边缘，不压缩表单分区
和控件的布局宽度。

当 `content_height <= viewport_height` 时：

- 将滚动条布局设为零矩形。
- 保持 `scroll_offset` 为零。
- 不绘制滑块，也不拦截表单事件。

当 `content_height > viewport_height` 时：

- 滚动条高度等于 `FormView` 视口高度。
- 用千分之一像素作为滚动位置的统一单位，将视口高度、内容高度和 `scroll_offset` 按同一
  比例映射到 `ScrollbarInput`；这样 `ScrollbarWidget` 的最大滚动范围与 `FormView` 的
  浮点像素范围误差控制在 `0.001px` 以内。

### 事件与状态

`FormView` 仍是滚动状态的唯一所有者，`ScrollbarWidget` 只接收输入并输出
`ScrollbarAction`：

- `DragTo(position)`：将 `scroll_offset` 设置为目标位置并限制在有效范围。
- `PageUp` / `PageDown`：按一个视口高度向上或向下滚动。
- `StartDrag` / `EndDrag` / `HoverChanged`：由滚动条维护交互状态，`FormView` 消费事件并请求重绘。
- 鼠标滚轮继续走现有 `FormView::scroll_by` 路径；滚动后立即同步滚动条输入。

拖动期间，即使指针离开滚动条矩形，事件仍优先发送给滚动条，直到收到鼠标释放。
非拖动状态下，滚动条只在自身右侧交互区域内优先处理事件；表单其余区域沿用现有分区
和控件事件路由。

### 绘制

先在现有裁剪区域内绘制表单分区，再把绘制偏移移动到右侧滚动条矩形并调用
`ScrollbarWidget::paint`。滚动条沿用现有编辑器主题：

- 空闲时只显示细滑块。
- 悬停或拖动时显示完整轨道和加宽滑块。
- 内容未溢出时不显示。

## 测试

采用测试驱动实现，至少覆盖：

1. 设置弹窗首选高度为 560 逻辑像素。
2. 内容未溢出时，`FormView` 不启用滚动条。
3. 内容溢出时，滚动条输入与视口高度、内容高度和当前偏移一致。
4. 滚轮滚动后，表单偏移和滚动条位置同步更新。
5. 拖动滑块会更新表单偏移。
6. 点击轨道上方或下方会按一页滚动，并限制在有效范围。
7. 滚动条拖动期间可在指针移出视口后正常结束捕获。

实现后运行 `cargo fmt`、相关 `textora-ui` 与 `textora-app` 测试，并执行编译检查。
