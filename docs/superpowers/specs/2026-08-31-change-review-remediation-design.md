# 近期修改整体修复设计

日期：2026-08-31  
范围：2026-08-29 以来提交审查中确认的六项正确性问题

## 背景

近期的多击文本选择、Markdown 前向删除护栏与块布局重构引入了六个测试盲区：

1. 双击或三击建立选择后，鼠标微移会退化为字符粒度。
2. 短 Setext 下划线（`=`、`==`、`--`）未被 Delete 护栏保护。
3. 嵌套容器会重复补偿同一个源码空行 run。
4. 代码块内形似围栏的普通代码行会被 Delete 错误拦截。
5. marker-like 普通段落会被宽松前缀匹配误判为独立块。
6. 多输出块精排把累计位置变化当作槽位自身高度变化再次传播。

本设计采用“修正三个边界模型”的方案：选择粒度属于指针选择会话；Markdown 块边界必须按完整语法判定；布局 delta 只表达当前槽位自身的尺寸变化。

## 目标

- 修复六项已确认问题，并为每项增加先失败、后通过的回归测试。
- 保持现有编辑器、插件和 `BlockSource` 公开 API 兼容。
- 让纯文本编辑器与自绘插件共用同一套多击拖动语义。
- 让 Markdown Delete 护栏只保护真实结构，不阻止普通文本编辑。
- 同一个嵌套空行 run 在一次布局中只补偿一次。
- 多输出布局与一次性完整布局的块位置、总高度保持一致。

## 非目标

- 不重写 Markdown 解析器，不改变 pulldown-cmark 版本。
- 不调整产品视觉规范、块间距数值或键位设计。
- 不扩展新的多击手势。
- 不处理本轮审查之外的全量 Markdown 增量解析性能问题。

## 设计

### 1. 指针选择会话保存粒度

在共享编辑器运行时中，把按下时确定的点击类型转换为选择粒度：

- 单击：按 grapheme 扩展；
- 双击：按完整词扩展；
- 三击：按完整物理行扩展。

选择粒度必须成为 `MouseCapture::TextSelection` 会话的状态，而不是只作为按下事件的临时参数。后续 `MouseMove` 使用会话粒度更新选择；`MouseUp`、焦点丢失、捕获取消或新手势开始时清除会话状态。

纯文本和自绘插件仍通过统一的 `place_pointer_selection` 路径更新文档模型。插件消息继续在最终选择落点确定后同步，避免插件布局和文档光标分离。

### 2. Markdown Delete 使用完整行语法

边界分类从宽松 `starts_with` 提升为完整物理行判定，并保持至多三个前导空格的 CommonMark 约束：

- Setext 下划线：一个或多个同类 `=`/`-`，其后仅允许空格或 Tab；
- thematic break：至少三个同类 `*`、`-` 或 `_`，标记之间可有空格或 Tab，行内不得出现其他字符；
- ATX 标题、列表、引用和表格继续沿用已有语义化判定；
- `---not-a-rule`、`===not-setext`、`***plain` 等普通文本不得触发护栏。

代码块体内的前向删除不能只看下一行前三个字符。分类器需要取得当前 fenced code block 的 opening fence 签名，并用同一规则验证候选 closing fence：字符必须一致、长度不得短于 opener、尾部只能是空白。非匹配字符、过短围栏或带非空白后缀的行均视为普通代码内容。

### 3. 嵌套空行 run 只消费一次

`LayoutCtx` 在一次布局过程中记录已经补偿过的源码空行 run。run 以稳定的源码行边界标识，而不是以容器类型标识；列表、引用和其他包装层看到相同 run 时，只有第一次调用增加 `(N-1) * line_height`，后续调用为零。

记录仅在存在编辑源码时启用，不改变预览和估算路径。相邻的不同空行 run 必须分别补偿，不能用单个全局布尔状态代替。

### 4. 多输出布局只传播自身高度差

`relayout_multi_output_group` 仍一次排布整个源块，以保证组内间距上下文一致，但每个槽位的修正值只表示该槽位内容高度相对估算高度的变化。组内输出的绝对 `rect.y` 不能再进入后续槽位的高度 delta。

实现时应从连续输出几何中分离：

- 槽位自身的内容高度；
- 前置槽位变化造成的累计位置偏移；
- 整组结束后需要传播给组外后续块的净高度变化。

写回的 `LaidOutBlock` 保持未包含 `y_delta` 的估算坐标约定，最终显示位置仍统一由 `rect.y + y_delta[slot]` 得出。`total_height` 只增加整组净高度差一次。

## 错误与退化处理

- 无法取得有效源码行或 opening fence 签名时，不消费 Delete，回退原生字符删除路径。
- 多输出数量与预估槽位数量不一致时保留现有安全边界，不越界写入；测试要求正常自定义 `BlockSource` 路径数量一致。
- 选择会话状态缺失时按单击粒度处理，不复用上一次手势的点击类型。

## 测试策略

所有生产修改遵循 TDD，每类问题先增加最小失败测试并确认失败原因：

1. appkit-shell：双击微移保持整词、双击拖动按词扩展、三击微移保持整行、三击拖动按行扩展；纯文本与插件路径至少各覆盖一种。
2. augmenter：`=`、`==`、`--` Setext Delete 被保护；合法长形式保持通过。
3. augmenter：不同字符、短于 opener、带非空白后缀的伪围栏允许默认 Delete；真实 closing fence 仍被保护。
4. augmenter：marker-like 普通段落可合并；合法 thematic break 仍被保护。
5. layout/block：列表→引用→段落的同一空行 run 只增加一个行高；不同 run 独立增加。
6. layout/types：首个输出精排高度发生变化时，多输出增量布局与一次性完整布局的位置和总高度一致。

完成后先运行受影响 crate 的定向测试，再运行 `cargo fmt --all -- --check`、Clippy 和项目完整验证脚本 `./scripts/verify.sh`。

## 架构约束

- `ui` 只保留纯指针点击/粒度数据结构，不依赖 `DocumentView`、Workspace、Commands 或 Events。
- 文档选择状态与插件消息转换继续由 appkit-shell 应用层负责。
- Markdown 语法判定留在 `textora-markdown`，不向 UI 层泄漏解析状态。
- 不新增组合布尔状态；互斥选择粒度和边界类型使用枚举表达。

## 完成标准

- 六项回归测试均经历可解释的 RED→GREEN。
- 受影响 crate 的测试通过，无新增警告。
- `./scripts/verify.sh` 完整通过。
- 最终独立代码审查无 Critical 或 Important 问题。
