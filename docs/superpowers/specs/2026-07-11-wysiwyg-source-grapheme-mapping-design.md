# WYSIWYG 源码 Grapheme 映射修复设计

## 背景

Markdown WYSIWYG 将源码折叠为视觉文本：软换行渲染为空格，块级标记与内联标记按光标上下文显示或隐藏。现有部分路径仍用“行起点 + 视觉字节偏移”反推源码位置，假定二者连续。

该假定在引用块的多行内容中失效：源码中的换行与下一行 `> ` 标记不会出现在折叠后的视觉文本中。它会让点击命中、方向键移动与光标坐标回投到错误的源码字节。含多字节字符和内联样式的行则可能让不同路径采用不同边界单位。

## 目标与范围

- 所有 WYSIWYG 光标路径以 Unicode grapheme cluster 为唯一可停靠单位。
- 每个视觉 grapheme 显式映射到其真实的源码 byte 边界；不再通过视觉文本偏移推导跨越软换行或块标记后的 byte。
- 点击命中、水平/垂直导航、光标绘制共用该映射。
- 覆盖引用块软换行与含粗体、多字节 `—` 的列表项；不改变 Markdown 文本语义或渲染样式。

## 方案

在布局阶段保留每个逻辑文本片段的源码 byte 边界映射。对于解析时折叠的软换行，映射在视觉空格后跳转至下一段真实源码文本起点，从而跳过源码换行和后续块标记。映射构造完成后统一压缩为 grapheme 边界表，并将其写入 `FlatLineSourceMap`。

鼠标命中将 x 坐标先转换为视觉 grapheme 索引，再从表中读取 byte。导航与光标位置反查同样仅查询这张表；渲染字形 cluster 只提供像素 advance，不再决定源码边界。

## 验证

1. 用目标文件的最小引用块片段复现：点击第一行引用文本，以及从相邻行用上下方向键移动，都必须落在该行的合法源码边界。
2. 用含粗体与 `—` 的列表项复现：点击、左右键和“光标位置→命中位置”往返均只产生 grapheme 边界，且往返 byte 一致。
3. 运行 Markdown crate 定向测试与工作区编译；若影响范围允许，再运行项目验证脚本。
