# mmap 单路径渐细连接线与几何缓存设计

## 背景

当前 mmap 连接线通过沿中心线约每个像素绘制一个圆角矩形采样点来模拟圆头、圆角转弯和渐细轮廓。每个采样点都会进入通用圆角矩形 tessellation；在画布裁剪区内，还会对生成的每个三角形执行四边裁剪。

现有性能日志显示，一帧主 `drain` 生成约 98 万顶点并耗时 137–154 ms，而字形缓存完全命中。性能瓶颈因此位于连接线几何生成与裁剪，不在刷新率或字形栅格化。

## 目标

1. 每条静态 mmap 连接线只提交一个通用 tapered-path 绘制命令。
2. 使用单个渐细三角网格替代每像素圆点串，使顶点数量与中心线路径段数相关，而不与屏幕像素长度相关。
3. 保持现有中心线、全程渐细宽度、圆角转弯和圆头在肉眼上完全一致。
4. 保留 0.5px 羽化抗锯齿；允许羽化边缘存在极小像素差异。
5. 静态连接线几何在布局和缩放不变时只 tessellate 一次，滚动帧复用缓存。
6. 保持画布裁剪精确，并为完全位于裁剪区内或外的网格提供快速路径。
7. 不破坏拖拽引导线、悬停颜色、拖拽子树置灰和现有画布视口行为。

## 非目标

- 不新增专用 GPU Shader、渲染管线或绑定状态。
- 不为所有 `DrawList` 命令建立通用场景缓存。
- 不缓存随指针实时变化的拖拽引导线几何。
- 不改变 mmap 布局算法、节点位置、连接线中心线路由或主题配置含义。
- 不修改 app 层以理解 mmap 节点、布局树或连接线语义。

## 方案比较

### 方案 A：通用 tapered mesh 命令与 mmap 几何缓存

在 `ui` 定义纯数据的 tapered-path/mesh 输入，由 `app` 渲染后端生成或提交三角网格；mmap 只负责中心线、宽度、颜色和缓存生命周期。

优点：保持跨层解耦；支持逐顶点羽化颜色和精确裁剪；静态几何可跨滚动帧复用；后续其他画布组件也可使用。

缺点：需要同时修改 `ui`、`app` 和 `markdown` 三层，并明确缓存失效协议。

### 方案 B：mmap 直接生成 `FillTriangle`

由 mmap 将连接线拆为许多普通三角形命令。

优点：接口改动较小。

缺点：现有 `FillTriangle` 只有单一颜色，无法正确表达羽化；抗锯齿、裁剪和顶点拓扑职责泄漏到 Markdown 层；每个三角形仍是独立命令。

### 方案 C：专用连接线 Shader

向 GPU 提交少量控制点，通过专用 Shader 生成或计算连接线覆盖。

优点：CPU 成本最低，扩展上限最高。

缺点：需要新增管线、Shader、绑定和跨平台验证，显著超出本次性能修复范围。

本设计采用方案 A。

## 分层架构

### `ui`：纯几何与绘制数据

`ui::tapered_path` 提供不依赖 GPU 的路径 tessellation，把中心线、首尾宽度、zoom 和羽化宽度转换为可共享的 `TaperedMesh`。`ui::core::paint` 提供对应的 `DrawCmd` 变体。数据只包含纯路径或网格数据、颜色以及本帧平移，不包含 mmap 节点、布局树、文档或 app 状态。

通用接口必须满足：

- `DrawList` 偏移通过 helper 统一应用，调用方不得手动绕过容器偏移。
- 命令支持单个路径、统一颜色和逐顶点透明度羽化。
- 可复用几何使用 `Arc` 共享，克隆 `DrawList` 时不复制整个网格。
- tessellator 输出局部像素空间位置与 alpha 乘数，不输出 NDC 或 app 层 `GlyphVertex`。

### `app`：网格提交、变换和裁剪

`paint_backend` 负责把已 tessellate 的 `TaperedMesh` 转换为 `GlyphVertex`：

- 计算屏幕空间位置并转换为 NDC。
- 将命令颜色与网格顶点的 alpha 乘数合成为逐顶点颜色。
- 根据当前最终裁剪矩形选择完全包含、完全排除或局部裁剪路径。
- 局部裁剪沿用现有 Sutherland–Hodgman 多边形裁剪，并插值位置、颜色和纹理坐标。

`app` 不缓存 mmap 语义，也不识别连接线来源。

### `textora-markdown`：路径生成和缓存生命周期

`mmf::canvas` 保留现有 `connector_centerline()`，并调用 `ui::tapered_path` 构建通用网格。`MindmapView` 在当前 Ready 布局旁持有静态连接线网格缓存，并在渲染时把缓存网格、颜色与滚动平移映射为通用 UI 命令。

动态拖拽引导线继续实时构建，但改用同一个 tapered-path tessellator；由于每帧只有一条短路径，不建立缓存。

## 几何规则

### 中心线

继续使用现有 `connector_centerline()`：

- 父节点到共享转向轴的水平段保持不变。
- 两个四分之一圆弧继续各使用 8 个采样段。
- 转向轴到子节点的最终水平段保持不变。
- 缺少足够圆角空间时继续退化为现有直线路径。

### 宽度

沿中心线累计弧长计算全局进度 `progress = covered_length / total_length`，并使用现有公式在线性空间从 `head_width` 插值到 `tail_width`。宽度不得按单个路径段重新开始插值。

### 主体三角带

每个中心线点计算局部切线和单位法线：

- 起点使用首段方向。
- 终点使用末段方向。
- 中间点使用归一化的入射与出射方向和；近似反向或退化段使用有效的相邻方向。

左右边界由中心点沿法线偏移半宽得到。相邻截面组成两个主体三角形。连接处使用受限 miter；miter 超过当前半宽的安全倍数时退化为圆形连接扇面，避免尖刺和自交。

现有圆弧已经细分为 8 段，因此正常 mmap 转弯主要走平滑截面，不产生可见折角。

### 圆头

首尾分别生成朝路径外侧的半圆扇形。扇形半径等于对应端点半宽，角度细分依据屏幕半径并设语义化上下限。圆头覆盖现有圆点串的端部包络。

### 羽化

主体外边界和圆头外缘增加 0.5px 屏幕空间羽化带：

- 内缘顶点使用原始颜色。
- 外缘顶点保持 RGB，alpha 设为 0。
- 羽化宽度不随缩放变化。

因此缓存必须区分 zoom；滚动平移不影响羽化几何。

## 缓存设计

### 缓存内容

缓存保存静态连接线在当前 zoom 下、与滚动平移无关的局部三角网格：

- 主体三角带。
- 圆形连接补片。
- 首尾圆头。
- 0.5px 羽化带。
- 局部包围盒。

网格不固化主题颜色或拖拽透明度。颜色在提交 `DrawCmd` 时传入，使悬停颜色与子树置灰不触发几何重建。

### 缓存键

缓存与当前 Ready 布局共同存活，键只包含对同一布局仍可能变化的几何输入：

- `zoom.to_bits()`。
- tapered tessellation 版本或等价的明确几何配置值。

源码 generation、折叠状态、活动标题投影、主题几何和 DPI 变化都会先使布局失效，因此不在缓存键中重复组合多个布尔状态。

### 失效条件

以下操作同时清除布局、命中图和连接线网格缓存：

- 接收新的文档源码 generation。
- 标题预编辑导致投影文字尺寸变化。
- 主题中的 mmap 几何常量变化。
- DPI 变化。
- 折叠状态或其他会重建布局的结构变化。

以下操作不清除缓存：

- 纯水平或垂直滚动。
- 指针悬停变化。
- 光标闪烁。
- 仅颜色变化且布局几何未变。
- 拖拽子树透明度变化。

zoom 变化创建新缓存并替换旧 zoom 缓存，不保留无界多级 zoom 历史。

## 裁剪设计

每个 tapered mesh 携带局部包围盒。应用本帧缩放和平移后，与最终累计裁剪矩形比较：

1. 完全位于裁剪区外：跳过整条网格。
2. 完全位于裁剪区内：直接变换并输出全部三角形，不分配临时裁剪数组。
3. 与裁剪边界相交：先按三角形包围盒区分完全内、完全外和相交；只有相交三角形进入多边形裁剪。

裁剪插值必须保留羽化 alpha，且继续过滤面积小于既有 epsilon 的退化三角形。

## 数据流

```text
MMF LayoutNode
  → connector_centerline()（内容空间，保持现状）
  → 当前 zoom 下构建/命中 ConnectorMeshCache
  → DrawCmd::TaperedMesh（共享网格 + 本帧平移 + 颜色）
  → paint_backend 包围盒裁剪快速路径
  → 局部变换、必要时边界三角形裁剪
  → GlyphVertex
  → 既有 GPU 提交流程
```

滚动只改变命令携带的平移或等价视口变换，不重复计算法线、宽度、圆头、圆角连接和羽化网格。

## 异常与退化输入

- 少于两个有效点、非有限坐标、非正宽度或总长度低于 epsilon：不生成命令。
- 连续重复点：在 tessellation 前去重。
- 单段短路径：仍生成带两个圆头的渐细胶囊形状。
- 180 度反向折返：禁止无限 miter，退化为圆形连接补片。
- 空裁剪区：直接丢弃网格。
- 局部裁剪产生共线多边形：继续通过面积 epsilon 过滤。

## 测试策略

### UI 几何与命令测试

- `DrawList` 对 tapered mesh 只产生一个命令。
- helper 正确应用容器偏移。
- `Arc` 网格在 `DrawList::clone()` 后共享而非深复制。
- 1000px 直线路径的顶点数量保持固定数量级，不随像素长度线性增长。
- 水平路径中心线被主体覆盖，头宽和尾宽符合输入。
- 首尾半圆外沿存在，圆头方向正确。
- 羽化外缘 alpha 为 0，内缘保持原 alpha。
- 退化点、重复点、短路径和反向折返不产生 NaN、无穷值或退化尖刺。

### 渲染后端测试

- 完全位于裁剪区内时不进入局部裁剪路径，并保持全部顶点。
- 完全位于裁剪区外时输出为空。
- 穿过裁剪边缘时所有输出顶点位于累计裁剪区内，羽化颜色连续。

### mmap 几何与缓存测试

- 每条静态连接线只生成一个 tapered mesh 命令，不再生成每像素圆角矩形。
- 现有中心线端点、共享转向轴和 8 段圆弧保持不变。
- 宽度沿整条路径从 head 到 tail 单调变化。
- 同一布局和 zoom 连续渲染命中同一个 `Arc` 网格。
- 滚动后仍命中缓存，只改变本帧平移。
- zoom、源码 generation、主题几何、DPI 和标题预编辑变化使缓存失效。
- 悬停颜色、光标闪烁和拖拽置灰不使缓存失效。
- 动态拖拽引导线使用单路径命令但不进入静态缓存。

### 集成与性能验证

- 运行 `cargo test -p textora-ui --lib`。
- 运行 `cargo test -p textora-app --lib -- paint_backend`。
- 运行 `cargo test -p textora-markdown --lib -- mmf`。
- 运行 `cargo test -p textora-app --lib -- mmap_`。
- 运行 `cargo check -p textora-app`。
- 作为重大渲染修改，最终运行 `./scripts/verify.sh`。
- 使用原复现 mmap 在 profiling/release 构建滚动，确认主 `drain` 不再生成约 98 万顶点；目标为连接线相关顶点降至数千级，主 `drain` 进入 60Hz 的 16.7ms 帧预算，并以 120Hz 的 8.3ms 作为优化观察线。

## 文件与阶段拆分

本修改涉及 4 个文件以上，必须拆为三个可独立审核的子任务：

### 子任务 1：通用 tapered mesh 纯几何与命令

- 新建 `crates/ui/src/tapered_path.rs`：纯几何 tessellation、羽化网格和对应测试。
- `crates/ui/src/core/paint.rs`：共享网格命令与 helper。
- `crates/ui/src/lib.rs`：公开纯 UI tapered-path 模块。

该阶段只建立通用纯 UI 能力，不引用 app 或 mmap 类型。

### 子任务 2：通用网格提交与裁剪

- `crates/app/src/paint_backend.rs`：颜色合成、屏幕变换、NDC 转换、裁剪快速路径和对应测试。

该阶段只消费 UI 纯数据，不新增 mmap 专用状态或分支。

### 子任务 3：mmap 迁移与缓存

- `crates/markdown/src/mmf/canvas.rs`：连接线路径输入、动态引导线迁移和几何测试。
- `crates/markdown/src/mindmap_view.rs`：静态缓存所有权、复用和失效测试。

该阶段删除旧的每像素 `draw_tapered_sample()` 圆点串实现。app 层不新增 mmap 专用状态或分支。

## 验收标准

1. 中心线、全程渐细宽度、圆角转弯和圆头与现有视觉在肉眼上完全一致。
2. 仅允许 0.5px 羽化边缘出现极小截图像素差异。
3. 静态连接线滚动帧命中几何缓存，不重复 tessellate。
4. 裁剪区内、区外和跨边界三种情况均正确，无新增裁剪边框、尖刺或越界顶点。
5. 单条连接线只提交一个 tapered mesh 命令。
6. 顶点数量与中心线路径段数相关，不随路径像素长度线性增长。
7. 所有目标测试、`cargo check` 和 `./scripts/verify.sh` 通过。
