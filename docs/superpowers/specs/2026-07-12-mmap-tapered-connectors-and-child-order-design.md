# MMF 渐变父子连线与拖放子节点排序设计

日期：2026-07-12  
状态：已确认

## 背景与根因

现有 MMF 连线保持“父端较粗、子端较细”的视觉语言，但每层节点的横坐标固定为 `depth × level_indent`。当某层卡片标题较长、卡片宽度超过层级步长时，其子卡片会落在父卡片右边缘左侧。渐变连线因而反向、穿过卡片，看起来不再是正常的父子连接。

跨节点拖放目前把节点作为目标的最后一个子节点追加，未使用释放位置决定目标子节点序列中的插入点，因此兄弟顺序与用户的垂直拖放意图不一致。

## 目标

- 保持现有平滑、由父端向子端逐渐变细的连线样式。
- 无论标题宽度，直接子节点始终位于父卡片右边缘之外，连线始终向右延伸。
- 拖入另一节点时，按释放高度插入其直接子节点序列的正确位置；拖到末尾才追加。
- 保持一次拖放一个源码事务、一个 Undo 单元，并完整保留子树、属性、备注和标题层级关系。

## 非目标

- 不把连线替换为等宽的共享树干或折线。
- 不修改同级拖放的前置、后置规则。
- 不新增跨文档、多节点或自动滚动拖放。

## 设计

### 阶段一：宽卡片的渐变父子连线

`mmf::layout` 先测量各深度的最大卡片宽度，再计算每个深度的左边界。相邻层的距离取现有 `level_indent` 与“上一层最大卡片宽度加上有语义名称的最小连线水平间隙”两者中的较大值。正常宽度的布局保持现有密度；宽卡片时，下一层仅向右扩展到足以容纳平滑连线的位置。

现有 `LayoutNode::connector_from` 和 `connector_to` 已表示直接父节点右侧与子节点左侧，`canvas` 继续使用当前的圆角中心线和渐变宽度绘制，不改为共享主干。布局测试锁定长父标题下 `connector_from.x < connector_to.x`，渲染测试锁定渐变宽度仍从父端向子端收窄。

### 阶段二：跨父节点的子序列插入

拖放计算在判定“移动为目标节点子节点”后，读取目标的直接子节点并按其卡片垂直中心排序：

- 指针在第一个中心线之前：插入第一个子节点之前；
- 指针位于两个相邻中心线之间：插入后一个子节点之前；
- 指针在最后一个中心线之后，或目标没有子节点：追加为最后一个子节点。

`MindmapDragPreview` 保存目标父节点范围和可选的“后继子节点”范围；预览插入线绘制在该后继子节点上方，目标父卡片仍被高亮。`mmf::edit` 新增跨父节点的“插入到指定子节点之前”移动目标：以该子节点的标题级别重定源子树，插入位置为该节点子树起点；追加仍沿用目标父节点子树末尾。两种路径都只产生一个 `EditTransaction`。

同父节点时维持原有“锚点上方为前置、下方为后置”规则和无操作判定，避免改变已确认的同级排序体验。

## 测试与验收

- 长标题父节点与子节点布局：子节点左边缘严格位于父节点右边缘之后，渐变连线从左向右绘制。
- 渐变连线渲染：父端宽度大于子端宽度，现有圆角采样风格不变。
- 目标已有多个子节点：分别拖到首个子节点之前、两个子节点之间和末尾，源码顺序与预览插入线一致。
- 目标没有子节点：拖动节点成为第一个子节点。
- 现有同级前置、后置、无操作、子树保留和单步 Undo/Redo 测试继续通过。

## 实施拆分

1. `layout.rs` 与 `canvas.rs`：先写宽卡片连线失败测试，再实现动态层级横坐标，保持渐变绘制。
2. `mindmap_view.rs` 与 `mmf/edit.rs`：先写跨父节点指定位置插入失败测试，再实现预览与原子事务。

最终运行 `cargo fmt --check`、`cargo test -p textora-markdown --lib` 与 `cargo check -p textora-markdown`；如改动影响 app 的拖放预览协议，再追加 `cargo test -p textora-app --lib -- mmap_` 与 `cargo check -p textora-app`。
