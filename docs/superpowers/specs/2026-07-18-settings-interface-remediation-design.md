# 设置界面交互与视觉修复设计

## 目标

修复侧栏设置入口、设置参数控件和文本输入，使设置页的行为及视觉密度与 macOS 设置应用保持一致。

## 范围

- 侧栏底部“设置”直接打开现有模态设置页，不再创建设置弹出菜单。
- 设置页的参数选择按钮使用当前主题的语义色，浅色主题中未选中按钮必须保持可读。
- 左侧分类导航使用紧凑 macOS 设置列表密度：每项 28 逻辑像素高、相邻项目间距 2 逻辑像素、水平内缩 8 逻辑像素。未选中项透明且无边框；只有选中项显示高亮背景。
- 开关控件显示为固定 36×20 逻辑像素，垂直居中且对齐表单控制列右边缘，不因父级可用宽度而拉伸。
- 设置页文本框在点击后接收普通键盘事件和 IME 事件；文本提交仍按既有校验与持久化动作处理。

## 设计

### 侧栏入口

保留现有 `SidebarAction::OpenSettingsMenu` 与应用动作名称以避免扩大事件协议变更。应用分发层接到该动作时直接调用 `App::open_settings_overlay()`；不再进入构造 popup menu 的 chrome 分支。原有菜单项目不再成为侧栏按钮的可达路径。

### 主题化参数按钮与导航

设置页在布局时从 `SettingsTheme` 生成两类 `ButtonStyle`：

- 参数按钮保留描边。未选中态的前景和描边来自主题主文字/控件边框，选中态使用主题 accent 背景与适合 accent 背景的浅色前景。
- 分类导航不绘制未选中态背景、边框或悬浮背景；选中态使用 accent 的低饱和高亮背景。尺寸和内缩仅作用于分类导航，不改变参数按钮的尺寸。

所有颜色均来自当前主题或由主题 accent 推导，不能继续使用深色主题专用的固定 RGBA 常量。

### 开关布局

`Switch` 继续接收父组件分配的矩形以支持命中测试，但其轨道几何独立计算为固定的 36×20 逻辑像素：Y 轴居中，X 轴对齐输入矩形右边缘。拇指以轨道几何计算，保证触摸、键盘切换及高 DPI 行为保持一致。

### 键盘和 IME 路由

`UiShell::forward_key` 已经优先将按键发送给活动模态 overlay；应用生命周期目前只在搜索框获得焦点时调用该函数。窗口键盘处理将先尝试把按键交给活动模态 overlay，并将返回的设置动作分发给应用。IME 处理同样分发返回的设置动作，而非仅重绘。未打开模态页时保持现有编辑器和搜索框行为。

## 错误处理与状态

无效数值仍由 `SettingsView` 保留验证提示；输入过程中的 `TextEdited` 只更新控件显示，确认提交后才映射为设置动作。模态页始终捕获其内的未处理按键，避免输入落入编辑器。

## 验证

- 应用层测试：侧栏设置动作创建一个模态设置 overlay 而非 popup。
- 设置页测试：浅色主题参数按钮的未选中文本颜色不是固定浅色；分类导航使用规定的几何和无未选中背景/边框。
- 开关测试：分配宽控制列时，轨道仍为 36×20 且右对齐。
- 生命周期或 UI shell 测试：设置文本框获得焦点后，字符键与 IME 提交均到达设置页；提交动作被分发。
- 运行定向 UI/app 测试、`cargo fmt --check`、`cargo check -p edit-plus-app`；本次为跨层输入与设置页修改，最终运行 `./scripts/verify.sh`。
