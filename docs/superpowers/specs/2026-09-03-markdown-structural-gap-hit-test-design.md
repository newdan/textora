# Markdown 结构间距命中修复设计

## 问题

源码：

```markdown
国内用增,

---
```

段落与分割线之间存在可见结构间距，但点击靠近分割线的一侧可能返回 `None`，因此鼠标无法移动光标。

当前布局将单个块间空源码行标记为 `HiddenBlockSeparator`。这条空行是 Markdown 块分隔语法，不是独立的可编辑视觉行；该语义应继续保留。

## 根因

`PreviewEngine::hit_test_byte` 在可见间距中按垂直距离选择相邻 `FlatLine`。普通文本行能从视觉位置反查源码字节，但 `HorizontalRule` 没有文字投影。间距点击选择到分割线的空 `FlatLine` 后，源码反查失败并返回 `None`。

命中算法错误地把“视觉上最近的行”当成“最近的可寻址光标位置”，没有跳过不可寻址的原子块。

## 设计

保留以下语义：

- 单个块间空源码行仍为 `HiddenBlockSeparator`。
- 结构间距本身不产生独立光标行。
- 不改变空行高度、段落间距或分割线渲染。

修改间距命中策略：

1. 为间距上下两侧分别解析合法源码锚点。
2. 上侧锚点取最近可寻址文本行的行尾。
3. 下侧锚点取最近可寻址文本行的行首。
4. `HorizontalRule` 等没有文字投影的 `FlatLine` 不作为最终命中目标；搜索沿对应方向继续，直到找到可寻址锚点。
5. 上下锚点都存在时，以间距中点决定落点；只有一侧存在时使用该侧；两侧均不存在时返回 `None`。

因此，在段落与分割线之间点击会落到相邻合法文本边界，不再静默失效。分割线本身的块选择或源码展开不在本次修复范围内。

## 测试

先增加回归测试，使用包含“中文段落、空行、水平分割线、后续文本块”的最小源码：

- 点击段落与分割线之间靠上位置，返回前一段落行尾源码字节。
- 点击间距靠下位置，即使最近 `FlatLine` 是无文字投影的分割线，也返回分割线之后最近文本块的行首字节。
- 现有可编辑空行、行尾空格、普通段间命中测试继续通过。

实现只修改 Markdown 视图命中逻辑及其同文件测试，预计不跨越三个文件。
