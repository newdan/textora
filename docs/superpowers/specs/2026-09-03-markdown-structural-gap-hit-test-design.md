# Markdown 结构间距命中修复设计

## 问题

源码：

```markdown
国内用增,

---
```

段落与分割线之间存在可见结构间距，但点击靠近分割线的一侧、分割线自身及其内间距会返回 `None`，因此鼠标无法移动光标，也无法通过鼠标激活 `---` 源码态。

当前布局将单个块间空源码行标记为 `HiddenBlockSeparator`。这条空行是 Markdown 块分隔语法，不是独立的可编辑视觉行；该语义应继续保留。

## 根因

`LazyLayout` 为 `HorizontalRule` 构造了覆盖完整上下内间距的空 `FlatLine`，却将其标记为无源码投影。`PreviewEngine::hit_test_byte` 默认每个被选中的 `FlatLine` 都能从视觉位置反查源码字节，因此在分割线块内直接返回 `None`；在块外间距按中点选择到分割线时也会以相同方式失败，且没有回退路径。

普通段落拥有 `VisualLineProjection`，不存在该问题。根因是 `FlatLine` 同时承载文本行和原子块，但只保存文本投影，丢失了原子块的源码范围。

视觉间距是独立语义：块间第一个空源码行是隐藏分隔符；后续空行每个保留一份 `line_height + paragraph_spacing`。该规则正确，不在本次修复中压缩。测试必须证明从两个空行缩减为一个空行后不会残留旧的 `y_delta`。

## 设计

保留以下语义：

- 单个块间空源码行仍为 `HiddenBlockSeparator`。
- 结构间距本身不产生独立光标行。
- 不改变空行高度、段落间距或分割线渲染。

为原子视觉块增加显式源码范围，并统一所有命中路径：

1. `FlatLine` 增加 `atomic_source_range: Option<Range<usize>>`；文本行保持 `None`，`HorizontalRule` 从对应 `BlockNode::block_range` 提取不含行尾 CR/LF 的标记范围，避免范围终点落入下一源码行。
2. 扁平化布局时显式传入当前 `BlockNode`，包括嵌套块，确保原子块不会靠视觉索引猜测源码位置。
3. 点击原子块上半部返回范围起点，下半部返回范围终点；两者都位于水平分割线块范围内，下一帧会展开 `---` 源码。
4. 普通文本行继续使用视觉 grapheme 投影，不改变文字点击精度。
5. 块外间距的上侧锚点统一取相邻行尾，下侧锚点统一取相邻行首；文本行和原子块都通过同一边界查询函数解析。
6. 上下锚点都存在时，以间距中点决定落点；只有一侧存在时使用该侧；两侧均不存在时返回 `None`。

因此，在段落与分割线之间点击会落到相邻合法边界；点击分割线及其上下内间距会激活 `---` 源码，不再静默失效。

## 测试

先增加回归测试，使用包含“中文段落、空行、水平分割线、后续文本块”的最小源码：

- 点击段落与分割线之间靠上位置，返回前一段落行尾源码字节。
- 点击间距靠下位置，返回水平分割线源码范围起点。
- 点击水平分割线块的上半部和下半部分别返回源码范围起点、终点，并在重渲染后展开 `---`。
- 一个块间空行保持隐藏分隔间距；两个块间空行只额外增加一份 `line_height + paragraph_spacing`。
- 从两个空行更新为一个空行后，分割线坐标恢复，不保留旧 `y_delta`。
- 以 `dpi_scale = 2.0` 渲染后，使用物理像素坐标仍能命中相同源码边界。
- 现有可编辑空行、行尾空格、普通段间命中测试继续通过。

实现拆为两个子任务：规格与计划文档独立提交；生产代码及测试只修改 `layout/types.rs`、`view.rs`、`selection.rs` 三个文件。
