# Sidebar 类型化新建设计

**日期：** 2026-07-17  
**状态：** 已确认，待实施

## 目标

将 Sidebar 的单一“新建”按钮改为拆分按钮：

- 点击左侧主体，立即新建 Markdown 文档。
- 点击右侧下拉箭头，弹出“新建 TXT / 新建 MMAP / 新建 MD”菜单。
- 三类未命名文档分别显示并建议保存为 `未命名.txt`、`未命名.mmap.md`、`未命名.md`。
- 新建文档在首次保存前不具有真实磁盘路径。

## 交互设计

“新建”保持现有整行高度和视觉风格，内部拆成两个独立命中区域：

- 主区域包含加号图标和“新建”文字；点击后创建 Markdown 文档。
- 右侧窄区域包含向下箭头；点击后打开类型菜单。
- 两个区域分别响应悬停，边界清晰但不引入新的常驻描边。
- 菜单锚定在拆分按钮下方，并沿用 Sidebar 现有弹出菜单的屏幕边界保护、悬停、点击外部关闭和 Escape 关闭行为。

菜单固定按以下顺序显示：

1. 新建 TXT
2. 新建 MMAP
3. 新建 MD

## 类型与分层

在 `ui::sidebar` 中定义纯数据文档类型枚举，包含 Markdown、Text、Mindmap 三种互斥状态。Sidebar 只产生类型化动作，不访问 Workspace、DocumentView 或插件注册表。

动作流如下：

```text
Sidebar 命中/菜单选择
  -> SidebarAction::NewDocument(type)
  -> AppAction::NewDocument(type)
  -> App 创建请求
  -> Workspace 创建类型化未命名文档
```

这保持现有依赖方向：`ui` 提供输入/输出数据，`app` 负责把 UI 意图映射为应用状态变更。

## 未命名文档模型

未命名文档不能通过设置 `DocumentView::file_path` 来模拟名称，否则普通保存可能直接写入工作目录。类型化新建改为在文档条目中保存建议文件名：

| 类型 | 建议文件名 | 初始插件 |
|---|---|---|
| Text | `未命名.txt` | Editor |
| Mindmap | `未命名.mmap.md` | Mindmap |
| Markdown | `未命名.md` | Markdown Editor |

`file_path` 在首次保存前始终为 `None`。标签、Sidebar 文件列表和保存对话框在没有真实路径时使用建议文件名；保存成功后清除未命名建议，统一使用真实文件路径和文件名。

热退出恢复需要保留建议文件名和当前插件，以免重启后丢失文档类型或显示名称。旧工作区数据缺少该字段时按现有普通未命名文档兼容处理。

## 菜单与状态

新建类型菜单复用 Sidebar 已有 `PopupMenu` 基础设施，但使用独立构造函数，避免将新建菜单项目混入设置菜单构造逻辑。Sidebar 同一时间只保留一个打开菜单；打开新建菜单会替换其他 Sidebar 菜单。

菜单选择后立即关闭并产生类型化新建动作。点击菜单外部或按 Escape 只关闭菜单，不创建文档。

## 错误处理

- Workspace 通过枚举穷尽匹配选择建议文件名和插件，不使用字符串分支推断类型。
- 插件注册表无法创建目标插件时沿用现有 Editor 回退机制，避免 panic。
- 新建操作不执行磁盘 IO，因此不新增用户可见错误对话框。
- 保存仍沿用现有错误处理；取消保存不会改变建议文件名或文档类型。

## 测试策略

实施遵循 RED-GREEN-REFACTOR：

1. UI 布局测试：拆分按钮两部分均有有效矩形，且不重叠、共同覆盖原新建按钮范围。
2. UI 命中测试：主体产生 Markdown 新建动作，箭头产生打开菜单动作。
3. 菜单测试：顺序、标签、动作类型、锚点和屏幕溢出保护正确。
4. 菜单交互测试：选择三项分别产生 Text、Mindmap、Markdown 动作，外部点击和 Escape 只关闭菜单。
5. 应用翻译测试：类型从 SidebarAction 无损映射到 AppAction。
6. Workspace 测试：三种类型均保持 `file_path == None`，建议文件名和初始插件正确。
7. 保存测试：另存为默认名读取建议文件名；保存成功后使用真实文件名。
8. 持久化兼容测试：类型化未命名文档往返恢复，旧数据缺字段仍可加载。

最终执行相关 crate 单元测试、编译检查，并按项目规范运行 `./scripts/verify.sh`。

## 实施拆分

由于改动会超过三个文件，按仓库规范拆成三个边界清晰的子任务：

1. UI 交互：类型枚举、拆分按钮布局/绘制/命中、新建类型菜单。
2. 应用动作：SidebarAction 到 AppAction 的类型化翻译与派发。
3. Workspace 模型：建议文件名、插件选择、保存名称与持久化。

三个子任务通过类型化动作接口协作，完成后统一格式化、编译和全面验证。
