# 拖拽文件打开副作用修复设计

## 背景

拖入 Markdown 文件时，`WindowEvent::DroppedFile` 直接调用 `App::open_file`，但丢弃其返回的 `AppEffect`。文件已加载到工作区，但重排、重绘、窗口标题更新和工作区持久化不会立即执行；与文件对话框打开的路径不一致，首帧会表现出卡顿。

## 方案

仅修改 `DroppedFile` 事件分支：当 `open_file` 成功时，立即调用 `apply_effect(effect)`。失败时保留现有错误输出。

`App::open_file` 继续是文件打开的唯一入口；不新增动作类型，也不改变加载、插件选择和文件监听行为。

## 错误处理

文件无法打开时维持当前的 `eprintln!`，且不应用任何副作用。

## 测试

为拖拽事件路径添加回归测试：成功处理事件后，断言重排代次递增并设置重绘请求。测试先在修复前失败，证明它能覆盖此次遗漏。
