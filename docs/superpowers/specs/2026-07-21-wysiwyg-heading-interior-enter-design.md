# WYSIWYG 标题中部 Enter 修复设计

## 问题

Markdown WYSIWYG 模式中，光标位于 ATX 标题正文中部时按 Enter，当前策略会在标题源码行末插入换行，并把光标移到标题之后。标题正文没有在用户指定的位置分开，视觉上却在标题下方出现一条空行。

根因位于 `crates/markdown/src/augmenter.rs` 的标题 Enter 策略：`at_end == false` 时，编辑范围被改写为标题行末的空范围，而不是使用当前光标位置。

## 目标行为

标题中部 Enter 采用 Typora 风格的“标题 + 普通段落”语义：

```text
输入：# 标题前|标题后
输出：# 标题前\n|标题后
```

- 在当前光标位置插入一个逻辑换行。
- 换行前的内容保留原标题级别。
- 换行后的内容成为紧邻的普通段落，不复制标题 marker。
- 光标落在后半段正文开头。
- 不生成空源码行。

标题末尾 Enter 的既有语义不在本次修改范围内。

## 实现边界

只修改 Markdown 编辑增强策略及其测试，不修改布局、渲染、App 分发或 UI 层协议。

`heading_enter_augmentation` 的标题中部分支应使用当前光标的空编辑范围，并插入一个逻辑换行。沿用现有 `EditAugmentation` 协议，确保 `cursor_byte_after` 指向插入换行后的第一个字节位置。

## 测试

先把现有“标题中部 Enter 在行末追加换行”测试改为期望失败的回归测试，再实施修复。测试至少断言：

- 插入文本是单个 `\n`；
- 替换范围位于当前光标位置，而非标题行末；
- 光标移动到原位置加一个字节；
- 将编辑结果应用到 `# hello world` 后得到 `# he\nllo world`。

完成后运行目标测试、Markdown WYSIWYG 相关测试、格式检查和 crate 编译检查。
