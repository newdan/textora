# mmap 渐细连接线转角缺口修复设计

## 背景与根因

mmap 渐细连接线由 `ui::tapered_path` 将中心线分段 tessellate 为主体梯形、转角补片、圆头和羽化带。当前主体梯形在相邻路径段的公共采样点处使用不同法线截面；外弯侧因此留下一个由采样点中心、前一路径段边缘和后一路径段边缘围成的三角区域。

现有 miter/圆角补片只覆盖两条偏移边界之间的外缘区域，没有覆盖这个中心三角区域。mmap 的两个四分之一圆弧各有 8 个采样段，所以每个未覆盖区域都会显示为沿圆弧排列的白色三角缺口。现有测试只验证最外侧 miter 或羽化顶点存在，没有验证转角主体连续覆盖。

## 目标

- 消除 mmap 连接线圆弧采样点处的白色三角缺口。
- 保持现有中心线、8 段圆弧轮廓、渐细宽度、miter/圆角策略和羽化效果。
- 保持现有连接线几何缓存、绘制命令和渲染后端接口。
- 不显著增加 tessellation 或每帧提交成本。

## 非目标

- 不提高圆弧采样密度。
- 不修改 mmap 布局、节点位置、分支颜色或连接线宽度配置。
- 不重写为新的连续三角带算法。
- 不新增 shader、GPU 管线或抗锯齿配置。

## 方案比较

### 方案 A：补齐外弯侧中心扇形

在每个非共线采样点，根据转向符号找到外弯侧，追加一个由采样点中心、前一段外侧边缘点和后一段外侧边缘点组成的实心三角形。既有 miter 或圆角外缘补片继续负责边界轮廓。

优点是直接修复缺失覆盖，几何语义明确；每个转角只增加一个三角形，不改变路径轮廓、羽化和缓存协议。缺点是保留了主体段与转角补片分开生成的现有结构。

### 方案 B：改为共享截面的连续三角带

为每个采样点预先计算受限 miter 截面，并用相邻截面生成连续三角带。

优点是主体拓扑更统一。缺点是会重写渐细、锐角退化、反向折返和羽化连接逻辑，回归风险及验证范围明显更大。

### 方案 C：增加采样或扩大相邻段

通过提高圆弧采样密度，或让相邻主体梯形重叠来遮挡缺口。

优点是实现直观。缺点是没有修复拓扑根因，会增加顶点或过度绘制，并可能改变当前轮廓。

采用方案 A。

## 几何设计

对每个内部采样点计算前后单位方向 `previous_direction`、`next_direction` 及叉积 `turn`：

- `abs(turn)` 小于既有共线阈值时，不生成中心扇形；既有直线和 180 度折返处理保持不变。
- 非共线时，外弯侧为 `-sign(turn)`。
- 使用采样点当前的 `half_width`，分别沿前后方向的法线计算两个外侧边缘点。
- 追加实心三角形 `(sample.center, previous_outer_edge, next_outer_edge)`。
- 随后继续执行既有受限 miter 或圆角外缘补片生成。

中心扇形的三个顶点透明度乘数均为 `1.0`。羽化仍只沿最终外轮廓生成，不在内部拼接边上增加羽化。

该修复位于通用 `ui::tapered_path` 几何层，不让 mmap 或 app 层感知路径转角细节，符合既有跨层依赖约束。

## 异常与兼容性

- 共线路径不增加顶点。
- 近似反向路径继续走既有整圆连接处理，避免方向符号不稳定。
- miter 超限的锐弯仍使用既有内侧 miter 与外侧圆形补片；中心扇形只补主体内部，不改变圆形边界。
- 宽度沿累计弧长插值的算法保持不变。
- `TaperedMesh`、`DrawCmd::TaperedMesh` 和缓存键均不变。

## 测试策略

先在 `crates/ui/src/tapered_path.rs` 新增回归测试，并确认当前实现失败：

- 构造与 mmap 圆弧采样相似的浅正向转弯，验证外弯侧中心区域中的代表点被 `alpha_multiplier == 1.0` 的三角形覆盖。
- 构造镜像的浅反向转弯，验证另一侧同样连续覆盖。
- 保留并运行现有直线、直角 miter、锐角圆角、羽化与反向折返测试。

实现后依次运行：

- `cargo test -p textora-ui --lib -- tapered_path`
- `cargo test -p textora-markdown --lib -- mmf`
- `cargo test -p textora-app --lib -- paint_backend`
- `cargo check -p textora-app`
- `./scripts/verify.sh`

## 性能边界

每个非共线采样点增加一个三角形，即 3 个顶点。mmap 每个正常连接线最多包含两个 8 段圆弧，新增顶点数量仍为常量级，并继续由现有静态 `ConnectorMeshCache` 跨滚动帧复用。中心线采样数量、绘制命令数量和每帧缓存命中路径均不变。
