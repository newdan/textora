# 等宽字体 B2 渲染

## 已确认行为

用户选择 B2：等宽字体的字形绘制位置对齐整数物理像素，关闭 hinting；保留原始 advance、换行、光标与选区度量，不增加轮廓加粗，也不改变 gamma 或对比度。

按每个字形实际使用的 fontdb 字体元数据识别等宽字体，不根据用户输入的字体名称判断。因此混排中的比例回退字体维持原来的 hinting 和四分之一像素定位。字体识别结果按 font ID 缓存。

## 接口与任务拆分

1. **字体策略与栅格化**：在 shaping 中定义 `GlyphRasterization::{IntegerUnhinted, SubpixelHinted}`；`Shaper::glyph_rasterization(font_id)` 获取字体策略，`GlyphRasterization::align_x(x)` 对齐绘制坐标。`rasterize_glyph` 按策略选择 hinting，并将等宽字体的栅格化偏移归零。先添加真实字形与参考无 hinting 位图的回归测试，再实施策略。
2. **绘制与缓存接入**：appkit-shell 的 `text_rasterize::glyph_position` 统一调用策略和 subpixel 拆分，源码、缓存重建、输入法和预览都使用这个入口。预览的 cache key 包含完整横向起点（包括负半像素跨零边界），避免移动后复用错误的栅格位置。预览缓存保存原始 advance，只使用解析器返回的实际绘制坐标生成 glyph instance。
3. **验证与审查**：测试等宽/比例字体、样式变体、混排回退、整数定位的正负边界、零相位缓存、预览原始度量及小数平移及负坐标缓存；运行 `./scripts/verify.sh`，最后进行独立代码审查。

行号现有绘制位置已取整、相位为零，可直接复用 shaping 层的新策略。画布控件的字形覆盖测量会经同一 rasterize_glyph 获得等宽字体的无 hinting 位图。

## 边界

不增加用户设置，不按字母名称加补丁，不修改 shaping 输出与字体尺寸。字形整数吸附带来的相邻绘制间距差异是 B2 的已知取舍。字形缓存无需增加可变模式字段：同一 font ID 的策略由固定字体元数据决定，进程内不切换。
