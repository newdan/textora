# textora Markdown 编辑快捷键规范

## 目标

为 textora 与 notora 的 Markdown 可视化编辑器提供一致的格式化快捷键。快捷键只负责产生类型化的
`SemanticEditCommand`，实际文本变换继续由 `textora-markdown` 规划为原子编辑事务，
以复用现有的选区、撤销、脏状态和插件刷新机制。

“主修饰键”在 macOS 表示 `Command`，在 Windows/Linux 表示 `Ctrl`。

## 快捷键表

| 快捷键 | 命令 | 典型结果 |
|---|---|---|
| 主修饰键 + B | 粗体 | `text` → `**text**` |
| 主修饰键 + I | 斜体 | `text` → `*text*` |
| 主修饰键 + K | 链接 | `text` → `[text](https://)` |
| 主修饰键 + E | 行内代码 | `text` → `` `text` `` |
| 主修饰键 + Shift + X | 删除线 | `text` → `~~text~~` |
| 主修饰键 + Shift + 7 | 编号列表 | 当前行或选中行切换为编号列表 |
| 主修饰键 + Shift + 8 | 项目列表 | 当前行或选中行切换为项目列表 |
| 主修饰键 + Shift + 9 | 引用 | 当前行或选中行切换为引用 |
| 主修饰键 + Alt + 1…6 | 一至六级标题 | 设置当前行或选中行的标题级别 |
| 主修饰键 + Alt + T | 任务列表 | 当前行或选中行切换为任务列表 |
| 主修饰键 + Alt + C | 代码块 | 当前行或选中行切换为 fenced code block |

快捷键按物理键位识别，避免 macOS `Alt` 将逻辑字符转换为特殊符号后导致映射失效。
两端复用 `appkit-shell::window_input` 的同一命令表。窗口事件必须保留物理键位；
没有原生键位的逻辑键调用方可使用兼容入口。控件仍接收原始逻辑字符，普通文本输入不按物理键位改写。

## 输入所有权与冲突规则

1. Modal、搜索框及其他获得键盘焦点的控件优先，Markdown 快捷键不得穿透。
2. IME 组合输入期间遵循现有互斥守卫，不执行格式化事务。
3. 只有活动插件为 `PLUGIN_MARKDOWN_EDITOR`、文档可编辑且编辑器拥有焦点时生效。
4. Markdown 编辑器聚焦时，主修饰键 + B 表示粗体；其他插件仍沿用既有的侧栏钉住行为。
5. 未支持语义编辑的插件不得退化为直接插入 Markdown 标记。
6. 编辑器拥有焦点时，先确定 Markdown 格式化命令，再进行执行权限检查；删除线不能被剪切抢走，代码块不能被复制抢走，布局转换后的字符也不能误触发搜索。
7. 输入法组合期间阻止字符、换行、删除、缩进、剪切、粘贴和撤销/重做修改正文；切离编辑器或 IME Enabled/Disabled 时清理组合态。
8. Shift 产生的大写逻辑字母必须保留既有快捷键含义，包括重做和固定标签页；搜索白名单使用相同大小写规则。

## 选区与撤销语义

- 有非空选区时，行内命令包裹选区；再次选择包含标记的完整文本可移除标记。
- 无选区时，行内命令插入成对标记，并把光标放在标记中间。
- 行级命令作用于光标所在行或选区覆盖的完整行。
- 每次格式化必须作为一个独立原子事务进入撤销历史。
- 事务完成后必须同步源码代次、脏状态、光标可见性和 Markdown 插件视图。
- 空文档和空行也能应用行级命令；跨行选区覆盖的末尾空行参与格式化。
- CRLF 必须作为完整换行处理，不能让替换边界落在 CR 和 LF 之间。
- 单个格式标记选区、空代码围栏不能触发切片越界；设置标题不能吞掉普通正文的 `#`。
