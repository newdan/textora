# WYSIWYG 可编辑段落统一编辑语义

本规范落实 2026-09-06 空行边界审查。用户已要求按报告系统修复；在既有空段落布局模型上统一编辑语义，保留已完成的列表分隔和 CRLF 空项投影修复。

## 事实源与不变量

源码是持久化事实源。`EditableParagraphMap` 是空行归属、可编辑段数与隐藏分隔的唯一语义查询；`FlatLine` 是几何事实源。禁止各输入入口重新用相邻文字矩形反推空段落，也不添加元素专属光标偏移。

- 普通 Enter 创建一个可编辑段落；文首不增加两段，已有 EOF 空段不能被吞掉，带空格或 Tab 的分隔与裸空行等价。
- 块间一个隐藏分隔不占独立行；超出的空段按既有容器正文样式排版。
- 删除方向不改变“内容变空”的结果：无选区 Backspace、Delete、清空相同段落内容的选区应保留同一个空段与容器，不额外制造一段。
- 段首 Backspace/段尾 Delete 先处理最近的可编辑空段，每次只减少一段。只剩隐藏分隔时才执行既有合并、样式移除或原子块保护。不能跨过空段将文字直接并入标题/引用/列表。
- HeadingStart、HeadingInterior、HeadingEnd 互斥。内容起点按可见投影定义，包含加粗、强调、链接等开头样式。标题内容起点 Enter 在前方建立普通空段并保留原标题，光标留在下移后的原标题内容起点；随后 Backspace 先移除前方空段，恢复标题位置。中部拆分与末尾退出分别处理。
- 标题位于列表项首内容时，前插点提升到保持列表合法的外侧边界；空段放在列表前，原标题、有序编号、任务状态和嵌套结构原样保留，避免连续裸空首行使 CommonMark 结束列表。已有合法空首行仍由空段映射展示和编辑。
- Setext 标题内容起点同样支持前插空段；其他位置继续在下划线后退出，保留下划线源码。
- 容器内段落维持归属；空列表项和单个空引用的逐层退出规则保留。已完成的列表 Enter 最低分隔保护及额外空行复用是列表续项规则，不套用普通正文段落创建公式。
- LF/CRLF 按完整逻辑换行处理；Unicode 按 grapheme 处理。

2026-09-07 边界补充（依据与复现见 [块边界不变量](2026-09-07-wysiwyg-block-boundary-invariants.md)）：标题终点按可见投影识别，插入点在完整标题源码之后，保留行内样式和可选闭合 `#`；有效可见 span 的端点不能被零宽 span 遮蔽。普通段落的不可见尾空格/Tab 不得使单字删除绕过统一清空操作。最后隐藏分隔之后的标题合并只移除可选 ATX 闭合尾缀，保留行内闭合语法；双向结果一致。

## 编辑计划

`EditAugmentation`/`EditTransaction` 保持一次原子替换（必要时有多个不相交替换），光标是结果源码的合法字节边界。选区处理验证范围及 UTF-8 边界后，再判定是否清空完整段落；部分内容、跨原子块、代码文本等保留对应安全默认行为。

共用“删除范围导致段落变空”处理，不分别给 Backspace、Delete、选中删除维护三个空行修剪算法。空段创建与邻接空段删除共用布局同一份 `EditableParagraphMap`。

同一视觉空段可能有不唯一的空白字节表示，例如 `a\n` 与 `a\n\n`。无历史编辑按语义保持段数、归属与光标；Undo/Redo 通过事务历史恢复精确字节。对于没有空白规范化的普通场景，Enter/Backspace 仍应按字节往返。

## 验证与兼容

保留正常文字输入的快速路径；普通词中退格不解析全文。测试覆盖文首/文中/文末，0/1/N 空段，正文/标题/分割线/列表/引用/代码/表格，LF/CRLF，三种删除入口，空态→输入→删空的真实行几何、命中、IME，及应用层 Undo/Redo。

旧测试只有在明确断言被本规范替代的语义时才更新，并给出对应新不变量断言。完整验证执行 `./scripts/verify.sh`；mock 本机端口受沙箱限制时在获准环境完整重跑。ui 不得依赖 app 状态。
