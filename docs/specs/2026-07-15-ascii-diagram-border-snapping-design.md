# Markdown ASCII 框线图右边界吸附设计

**日期：** 2026-07-15  
**状态：** 已确认，待实施计划

## 背景与根因

现有固定网格渲染已经消除了字体 fallback 和中英文自然字宽造成的像素漂移，但仍忠实使用每个框线字符在源文本中的逻辑列。

问题示例的同一矩形右边界并不处于同一源文本列：顶部和部分内容行的右边界位于第 32 列，其余内容行及底部位于第 31 列；另一个矩形的内容行还分散在更靠左的列。固定网格因此把源文本中的一列差异稳定地渲染为一个单元格宽度的视觉错位。

本轮需要在不修改 Markdown 源文的前提下，识别完整矩形框并为其右边界生成仅供渲染使用的统一列。

## 目标

- 在已识别的 fenced ASCII 框线图中，自动识别完整的轻线矩形框。
- 同一矩形的右上角、右侧竖线和右下角渲染在同一 x 坐标。
- 支持同一图中的嵌套矩形、上下排列矩形和左右并排矩形。
- 只改变框线几何，不改变文字、箭头、空格、源码字节位置或选择映射。
- 输入结构不完整或关联存在歧义时，保持当前固定网格结果并安全降级。

## 非目标

- 不修改或格式化 Markdown 源文本。
- 不对普通代码块、缩进代码块或编辑中的活动代码块启用吸附。
- 不把任意相邻竖线按距离聚类；内外框距离很近时不得合并成同一边界。
- 不缩放整行，也不移动普通文字、箭头或非目标框线。
- 不扩展公开的 `LaidOutBlock`、`LaidOutDoc` 或既有渲染 API 字段形状。

## 结构识别

吸附分析在 `crates/markdown` 的 ASCII 图私有模型中完成。

1. 在每行中查找由 `┌` 开始、同一行后续 `┐` 结束的顶部框边候选。标题文字可以位于两角之间。
2. 向后匹配左下角位于同一逻辑列的 `└ … ┘`。多个候选按行序和嵌套关系分别配对，不跨越已确定的平行框区域。
3. 顶部或底部缺少成对角点、左右次序无效，或存在多个同等合理匹配时，不为该候选生成吸附数据。
4. 矩形的规范右边界取顶部右角与底部右角中更靠右的逻辑列。规范列只向右扩展，避免覆盖框内文字。
5. 对顶部与底部之间的每一行，在该矩形的水平范围内查找右侧竖向连接字符。候选必须位于规范右边界左侧或正好位于该列，并且候选与规范列之间只能有空白；取该矩形范围内最靠右的有效候选。
6. 外框与内框分别使用自己的左右角点和行范围进行匹配。禁止仅凭列距离把两个矩形的边界合并。

首版仅处理当前已支持的轻线框字符及其竖向连接。未映射字符继续走既有固定网格或文字 fallback。

## 渲染数据与绘制

每个被吸附的右边界单元保留源列，同时附加 crate-private 的规范渲染列；源码字节范围和高亮查找仍使用原单元信息。

- 中间行的右侧竖线在规范列绘制，原列不再绘制该竖线几何。
- 右上角与右下角移动到规范列。
- 当角点向右移动时，补绘从原角点位置到规范角点的水平连接段，确保顶边或底边连续。
- 其他框线单元和全部文字仍使用原逻辑列。
- 若吸附元数据缺失、行数不匹配或 shaper 不可用，继续使用现有安全回退。

吸附信息跟随现有 `AsciiDiagramRegistry` 生命周期，在重新布局、source invalidation 和 viewport eviction 时一并释放，不增加公开状态。

## 编辑与选择行为

现有行为保持不变：光标进入代码块时使用普通文本路径；非空选择与图表相交时暂停网格渲染。清除选择后复用同一图表模型并恢复吸附几何，不修改 Markdown 文档或重建公共布局类型。

## TDD 与验证

实施必须先加入失败测试并确认 RED：

1. 使用问题截图中的代表性不等宽矩形，证明其原始右边界列不同，而吸附后的右边界列相同。
2. 渲染测试收集顶部角点、中间多行竖线和底部角点的细竖线 x 坐标；修复前应出现多个 x，修复后必须只有一个 x。
3. 嵌套矩形测试验证内框和外框各自对齐，但不会互相合并。
4. 左右并排矩形测试验证两个框各自形成独立右边界。
5. 缺少底边、角点歧义或间隙中含非空白字符时不生成吸附数据。
6. 普通代码块、活动代码块、选择态、语法高亮、未知框线 fallback 和公开 API 兼容测试继续通过。

定向测试通过后运行：

```text
cargo fmt --check
cargo test -p textora-markdown
cargo check -p textora-markdown
git diff --check
```

最终运行项目级 `./scripts/verify.sh`。

## 验收标准

对问题截图对应的 fenced 代码块进行预览时，每个完整矩形的右上角、全部右侧竖线和右下角位于同一 x 坐标；内外框与左右并排框保持独立。Markdown 源文本、普通文字位置、编辑行为和公共 API 均不发生变化。
