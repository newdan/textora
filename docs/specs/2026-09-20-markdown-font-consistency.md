# Markdown 正文字体一致性

## 行为

Markdown 源码、预览和所见即所得正文统一使用编辑器的 `font_family`。
保留已有字号、标题层级和行高规则；代码块继续使用独立的等宽字体。
不自动替换用户已选字体，也不更改全局默认字体。

运行中修改字体后，前台字形、后台换行、光标测量和 IME 预编辑均须更新。
字体切换不修改文档内容。

## 数据传递与缓存

- `ui::PluginMessage::SetRenderSettings` 携带纯数据字体名称，由应用层提供配置。
- `MarkdownRenderSettings` 和 `PreviewEngine` 将该名称传给 Markdown 正文样式。
- 替换选区的 IME 预览复制正文字体；独立预编辑的测量与绘制也使用该字体。
- 两个应用入口在源码绘制前同步实际 shaper 的字体与物理字号。
- `ReshapeRequest` 保存每次请求的字体快照，worker 不依赖启动时的字体。
- 前后台共用布局哈希包含字体名称，防止旧字体的字形及折行结果命中缓存。
- Markdown 的样式哈希已有字体名称；配置变更同时使预览绘制缓存失效。

## Menlo 诊断

以本机实际字体和项目 shaping 实测，32px 的 Menlo 英文 advance 为
19.265625px；`agent Skill loop` 的快速与完整整形结果相同。
中文混排行中的英文仍使用 Menlo，汉字回退到 PingFang SC。
窄字母 `i/l` 仍占完整等宽格，因此与中文混排时显得疏松，这与字体设计有关。
该结果不表明所有字体或组合文字的渲染均不存在问题。

## 回归验证

- 自定义字体及 1x/2x DPI 正确传入 Markdown 样式，代码字体保持独立。
- 预览和所见即所得多次切换字体后，实际 glyph、font ID、advance 与源码整形一致。
- 字体变更使样式哈希及前后台布局哈希变化。
- 后台 worker 使用请求的新字体计算宽度。
- 字体设置同步到编辑器 runtime。
- 替换选区和独立 IME 预编辑保持字体一致，独立预编辑光标宽度与绘制一致。
- 运行 `./scripts/verify.sh` 完成架构、格式、Clippy 和工作区测试。
