# TXT 与 Markdown 中文混排间距方案

日期：2026-09-20。状态：已实现，仓库自动化验收通过。

用户确认：Markdown 源码模式也需要优化。覆盖 TXT 正文、Markdown 源码正文、所见即所得正文和预览正文。

## 目标与选择

解决半角标点紧贴中文的问题。仅改变排版几何，原始字节、复制结果、保存、搜索、撤销和 Markdown 语义保持不变。各模式使用同一规则；源码模式因为显示语法标记，换行位置不要求与预览相同。

比较三种方案：

| 方案 | 收益 | 代价 | 选择 |
| --- | --- | --- | --- |
| 所有标点补齐最小宽度 | 改动较小 | 不区分中文、英文、技术文本，也不区分标点方向 | 不采用 |
| 按字符类别、相邻内容和语义区间增加留白 | 有针对性，保留字体自身宽度，编辑可一致 | 需要统一测量、换行和命中 | 推荐 |
| 中文环境下把半角标点替换成全角字形 | 中文视觉更规整 | 所见字符与源字符不一致，代码及符号语义容易混淆 | 不采用 |

第一版只做自然左对齐混排。全角标点压缩、两端对齐、标点悬挂和自动替换字符不在范围内。

## 实施前的现状

- `crates/ui/src/layout.rs::apply_punctuation_padding` 对标点补齐最小 advance，并居中字形；除有序列表句点外，未按中文邻接关系区分。
- `crates/ui/src/settings.rs` 的 `min_punctuation_width_ratio` 默认值为 0.5。
- `crates/appkit-shell/src/render_pipeline.rs` 在确定 visual lines 后调用补齐；`reshape_worker.rs` 用未补齐的宽度计算换行。扩大宽度没有完整计入换行结果，是需要一并解决的几何风险。
- Markdown 经 `layout/context.rs`、`layout/block.rs`、`layout/shaping.rs` 完成测量、换行、样式重塑和布局，没有复用上述补齐入口。
- Markdown 样式段宽度存在独立测量；新增间距必须同步进入样式背景、链接、光标与选区几何，不能只移动绘制字形。

以上为实施前代码检查结论。现已替换旧补齐规则，并使用真实字体完成自然/原样对照。

## 视觉规则

以下数值是 textora 的设计初值，不是 Word 的精确参数。1em 使用所在正文 run 的字号；跨不同字号边界取两侧较小字号。每个逻辑边界最多增加一次留白，规则冲突取最大值，不累加。

| 场景 | 自然模式的初始规则 | 例子 |
| --- | --- | --- |
| 汉字与拉丁字母、阿拉伯数字相邻 | 边界增加 0.125em | `使用Word编辑`、`共100页` |
| 半角句读 `, . : ; ! ?`，任一侧紧邻汉字 | 左侧紧邻汉字时增加 0.0625em；右侧有相邻正文时增加 0.125em | `你好,世界`、`注意:保存`、`版本:beta` |
| 半角开括号 `(`、`[` | 左侧为汉字时外侧增加 0.125em；右侧为汉字时内侧增加 0.0625em | `正文(说明)` |
| 半角闭括号 `)`、`]` | 左侧为汉字时内侧增加 0.0625em；右侧为汉字时外侧增加 0.125em | `正文(说明)继续` |
| 中文语境的连续句读 | 作为一组，仅组外按句读规则增加留白 | `真的吗?!继续`、`等等...再说` |
| 纯英文、纯数字、全角标点 | 沿用字体和已有排版，不增加本方案的留白 | `Hello,world!`、`你好，世界` |
| 已有空白 | 有空格、Tab、NBSP、全角空格的边界不额外增加留白 | `你好, 世界` |

16px 字号下，0.125em 为 2px，0.0625em 为 1px。保留浮点精度，在最终栅格化前不对每个间距取整。

补充约束：

- “汉字”采用专门的 Unicode 表意文字分类；不能直接复用现有也包含全角标点的 `is_cjk_char`。第一版不把假名、韩文、emoji 自动视作汉字。
- 配对半角双引号在同一正文段内可明确配对时按括号处理；转义引号不参与配对。无法判定的双引号、单引号、撇号保持原样。
- `/ \\ + - = @ # $ % & * _ < > { } | ~` 不因属于 ASCII punctuation 就统一加宽。第一版仅对表中列举类别应用规则。
- 连续标点内部不插入留白；纯英文标点组不处理。列表编号的点、数字内部的点/逗号/冒号/连字符不按句读处理。
- 候选 gap 只对同一视觉行中仍相邻的两个单元生效；断行后取消两行之间的 gap，不留下行首或行尾虚拟空白。
- 同一 grapheme/整形 cluster 内不插入 gap，不拆开连字、组合符和 emoji 序列。多字形 cluster 的同一边界只处理一次。

## 范围与受保护区间

推荐用互斥枚举表达 `Natural`（自然混排）与 `Verbatim`（原样排版）。TXT 和 Markdown 正文默认 Natural；代码内容自动 Verbatim。在应用设置中提供 Natural/Verbatim 切换入口，以支持日志、等宽表格等用途。

### TXT

- 常规段落按自然模式排版，纯英文段落不增加混排间距。
- 有 Tab 的行在第一版整体保持原样，避免破坏列对齐；空格手工对齐的文本可以切换整篇原样模式，不凭几个空格猜测语义。
- 保守识别明确的 URL、邮箱、路径以及数字形式，保护其内部边界。例如 `https://a.com/x?a=1`、`a@b.com`、`/usr/local`、`C:\\work`、`3.14`、`1,000`、`12:30`、`2026-09-20`、`50%`。
- 技术 token 的边界分隔符不吞入相邻中文正文；若无法可靠判定，优先不加该处间距。不能因为整行包含一个 URL 就关闭整行正文优化。

### Markdown 源码

- 使用 Markdown 解析得到的源范围，提取正文区间和语法区间；不靠 `is_ascii_punctuation` 区分语法与正文。
- 标题、列表、引用、表格单元格的正文、强调内部正文、链接的可见标签均可优化。
- 代码块、行内代码、ASCII 图、链接目标、自动链接、HTML、metadata、数学内容（如当前解析器支持）保持原样。
- `#`、列表前缀、有序列表编号、强调分隔符、反引号、表格竖线和分隔行等语法标记保持原样。语法区间两端不跨越插入间距。
- 例：`**你好,世界**` 优化正文逗号；`[你好,世界](https://a.com)` 只优化标签中的逗号；反引号中的 `foo(中文)` 不优化。
- 源码中被解析为普通文本的圆括号或方括号可按正文规则处理；链接语法中的同形字符受保护。
- 语法未闭合或尚未完成增量解析时，可疑区间暂用原样模式；不要为实时排版新增第二套 Markdown 解析器。

### Markdown 所见即所得与预览

对投影后的正文应用相同规则，保留原有源范围映射。隐藏标记不成为间距单元。加粗、斜体、普通链接文字之间如果仅存在样式变化，应跨样式边界判断相邻文字，避免遗漏或重复。

代码节点及其两侧边界第一版不新增 gap，沿用现有代码背景 padding。显示为网址的自动链接整体保持原样，普通链接标签可以作为正文。

## 布局协议与接入

在 `ui::typography` 定义纯数据输入及无应用状态依赖的边界规则。建议输入包含 `TextSpacingMode`、可排版文本、带字号的正文/受保护范围、原始 shaped clusters；输出包含按 UTF-8 边界索引的 gap 候选和最终行几何。

职责分配：

- `app/appkit-shell` 根据文档种类、用户设置和语义范围构造输入，不向 ui 传入 DocumentView、Workspace 或命令对象。
- `textora-markdown` 根据 AST 与投影提取区间，调用 ui 的共同规则。
- `shaping` 保留字体整形职责；全局 `Shaper::shape` 不隐式加入正文规则，防止按钮、搜索框和侧栏一起变宽。
- 原始整形缓存与间距处理后的布局分开，避免对缓存结果重复加宽。替换当前正文的最小标点宽度补齐，不与旧补齐叠加。

统一处理顺序：

```text
源文本 / Markdown 投影 + 语义范围 + 字体样式
  → 字体整形
  → 分类相邻 cluster，生成候选 gap
  → 用实际字宽 + 行内 gap 选择换行点（同时应用禁则）
  → 去除跨行 gap，形成最终布局几何
  → 绘制、光标、选区、命中、搜索高亮、链接、IME 共用
```

gap 存在于布局中，不产生可编辑字符或额外光标停靠点。边界 gap 的左右半区分别属于相邻单元的命中区，二者在共同的逻辑插入边界汇合；光标画在 gap 中点。选区起止使用这些相同的插入边界。精确命中仍依照 grapheme 与 source projection 映射。

TXT 的前台、后台 worker、长行子区间 shaping 和 fallback 都必须携带同一策略与范围。对子区间计算需要提供紧邻上下文和保护区间状态，不能把截断边界当成段落边界。

Markdown 的换行、样式段宽度、表格宽度需求测量和最终绘制共用最终几何；禁止先用原始宽度换行，随后按样式重新 shaping 时丢掉或重加间距。离屏估算可以近似，可交互行须先精排，再接受点击或定位光标。

缓存键包含文本版本、语义区间版本、字体/字号/样式、可用宽度、DPI 与间距策略版本；切换模式时同时失效行布局、DisplayMap、命中缓存与渲染缓存。内容 hash 相同不足以复用布局。

旧 `min_punctuation_width_ratio` 的正文调用迁移后退出该路径；实现前核对其是否存在持久化映射，有则在配置边界迁移，不让新旧策略同时生效。

## 换行与编辑约束

- 开括号不单独停留在行尾，闭括号和句读不作为普通行首；按类别实现，不能把所有 ASCII 符号都视为禁则标点。
- 常规英文单词、数字组合沿用词边界处理。极窄视口或超长 token 允许在安全 grapheme 边界强制断行，确保前进、不死循环；第一版不允许标点悬挂导致越界。
- 输入或删除标点会引起合理的局部重排。重排保留源码光标位置和滚动锚点。
- 点击、左右移动、Shift 选区、Home/End、跨行选择、IME 下划线与候选框都使用最终布局。
- 跨样式、跨投影边界只出现一个源插入位置；软换行处沿用现有行亲和性，不新增文本位置。

## 分阶段实施与验收

每阶段再拆为每个子任务最多修改 3 个文件的变更；先失败测试，再实现。不是按“先改绘制、以后修光标”的方式发布。

1. **基线与共同规则**：建立中文半角句读、括号、纯英文、数字与技术 token 的复现样例；完成纯数据分类、gap 计算、保护范围和幂等性测试。
2. **TXT 完整接入**：统一前台、worker、fallback、长行子区间和缓存；同步换行、命中与绘制；移除本路径旧 padding。
3. **Markdown 全模式接入**：接入源码 AST 范围、所见即所得及预览投影，覆盖样式切分、代码、列表、链接与表格。
4. **视觉校准与发布验证**：比较自然/原样，调校默认 gap；验证配置切换、滚动锚点、增量编辑和大文件性能。

必须覆盖：

- `你好,世界.接着说:可以;没问题!真的吗?`、`正文(说明)继续`、`正文[补充]继续`。
- `中文Word中文2026年`、`版本:beta`、`Hello,world!`、`你好，世界。`。
- `3.14`、`1,000`、`12:30`、日期、网址、邮箱、路径、百分数不被拆散或逐符号加宽。
- `真的吗?!继续`、`等等...再说`、成对/未闭合/转义引号，空格与 Tab。
- Markdown 标记仍可准确点击和选择；代码块、行内代码、ASCII 图保持原样。
- 同字体、字号和可见正文条件下，各模式共享相同间距；源码额外标记带来的宽度差异属于预期。
- 用可控字体宽度测试验证 0.125em/0.0625em 规则；用真实字体截图校准观感，避免仅靠固定像素快照判断逻辑。
- 换行边界的 gap 去除、字符禁则、极窄视口、连续标点、大文件及长行截断。
- 1×/2× DPI、多字号、不同中西文字体、加粗斜体跨界、组合符与 emoji。
- 暖缓存/冷缓存、前台/后台、增量重排/完整重排一致；精确路径以相同最终几何为准，估算路径只允许离屏使用。
- 文档未编辑时切换模式不修改源字节；编辑、复制、保存、搜索及撤销不产生虚拟空格。

性能要求：新增分类与 gap 计算为所处理文本长度的线性复杂度；随现有增量范围重排，不在每帧扫描全篇，不为每个边界单独 shaping。用同一设备与样例对比实施前后的现有编辑基准并记录差异。

每次代码提交前编译通过，完成后运行相关 crate 测试与 `./scripts/verify.sh`。用户随后授权开发并指定 Luna 子智能体，实现已落入隔离分支 `codex/cjk-ascii-spacing`。


## 实施记录与验证边界

- TXT 普通编辑、TXT 阅读视图、Markdown 源码、所见即所得与预览均接入。设置入口为“中西文间距：自然 / 原样”，默认自然；该设置为应用级并持久化。
- UI 规则仅输出间距候选，共享 layout 在换行前计入宽度并取消跨行间距。相邻字素各分配一半间距，使命中和光标边界保持一致；原始 shaped 缓存不被重复加宽。
- Markdown 解析保留 HTML block 源范围；投影以 `ProjectionSpanKind::Verbatim` 传递 HTML、自动链接的保护信息，布局阶段不重复解析每个 span。表格列宽、样式段与最终绘制采用同一保护信息。
- 源码保护范围在内容修订或文档类型变化时刷新，前台与 worker 共用包含策略、行内保护范围及语义规则版本的缓存键。每次刷新当前会解析完整 Markdown 文档，尚未实现解析器的局部增量更新。
- 长行子区间仍使用完整源行计算引号角色；回退估算沿用核心 UAX#29 字素边界，保护组合符、ZWJ emoji 与旗帜。回退字宽属于估算，不等同于真实字体精排。
- TXT 含 Tab 的整行在编辑及阅读视图中保持原样。代码语言编辑路径、Markdown code、语法标记、HTML 和自动链接不增加本方案间距。
- 已执行可控几何测试、真实字体 Markdown/TXT 阅读布局测试、设置与源码模式集成测试；另对共享布局运行 4125 组几何探针，验证行宽、cluster 边界与 glyph 内部相对位置。
- 视觉对照使用 PingFang SC 22px 和实际共享排版代码生成，属于排版层样例，不是应用窗口截图。系统输入法候选框、真实窗口的滚动观感及不同显示器 DPI 尚未人工验收。

### 局部耗时抽样

| UTF-8 字节数 | 原样布局 | 自然布局 | 比值 |

该抽样仅说明当前设备上的局部额外成本；发布构建、大文件交互和完整编辑基准仍需另行测量。
