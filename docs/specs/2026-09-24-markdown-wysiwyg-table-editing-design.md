# Markdown WYSIWYG 表格创建与编辑方案

## 目标与现状

Textora 以 Markdown 源码为持久化事实源，在编辑视图中直接显示和编辑 GFM 表格。用户既能通过类似 Word 的选格面板创建空表，也能输入管道表头后按 Enter 创建表格。表头、表体均可原位编辑；行列和对齐由结构命令修改。一次用户操作对应一次可撤销的源码事务。

现有 `textora-markdown` 已构建 `TableWrapper`、表头/表体单元格和单元格级 `ProjectionOwnerId::TableCell`；已有表格命中、折行、IME 和 Enter 导航的回归。Enter 当前在非末行移动到下一行同列，在有内容的末行新增一行，在空表体末行退出表格。本方案沿用该行为。`SemanticEditCommand`、`SemanticEditPlan` 和编辑事务已有完整执行链。尚无创建表格的语义命令及选格面板。

## 用户交互

### 菜单创建

“插入 → 表格”打开选格面板。面板打开时不预选固定的行列数。鼠标移动高亮从左上角到指针格的矩形，显示“列数 × 行数”；点击该格或按下后拖动、松开时创建。行数包含一行表头，至少选择一列、两行。拖出当前可见网格时自动扩展可选范围；同时提供行数和列数输入框，便于创建大表。Escape 关闭，不修改文档。键盘可以通过方向键调整尺寸并按 Enter 创建。

创建成功后，光标落到表头第一格。弹窗仅保存待选尺寸；打开、悬停和拖动都不修改源码。文档只在确认尺寸时产生一次事务。面板属于 `ui::widgets`，只接收纯数据状态并返回尺寸选择；`app` 从活动文档和插件状态决定是否展示与执行命令，`ui` 不读取 `DocumentView`。

### 输入管道表头创建

用户在独立源码行输入 `| 名称 | 说明 |` 后按 Enter，将该行视为表头，补充分隔行及一行空表体，光标落在表体第一格。识别显式的管道边界与未转义的列分隔符；转义管道 `\|` 和行内代码中的管道不计为分列。普通句子 `甲 | 乙`、代码块内部、已有表格单元格、表格分隔行以及非可编辑区域不触发。光标须位于表头可见内容的行尾，不能在中间输入时抢走普通 Enter。

识别与源码生成集中于 Markdown 层，并通过重新解析生成结果验证它确实是期望列数的 GFM 表格。识别失败则维持现有 Enter 语义，不生成半成品。已有表格内的 Enter 分派优先于“创建表格”识别。表头中的行内 Markdown 尽量保留原源码；当前 GFM 解析器要求行内代码里的字面 `|` 在表格源码中写成 `\|`，创建时仅对这类管道增加转义，保证代码显示文本不变。

### 表格内编辑

点击或键盘移动到单元格后，直接使用现有编辑器光标、选区与 IME 输入文字；不叠加独立输入框。表头与表体使用同一文字编辑链，单元格内的加粗、链接和行内代码按现有格式命令处理。普通文字输入优先修改当前单元格的局部源码范围，保留其余单元格的空格、分隔行、对齐、容器前缀和换行格式。输入字面 `|` 时必须转义，粘贴含换行的文本不能意外生成新表格行；首版将格内换行归一为空格，矩阵粘贴另列阶段实现。

Tab 移到下一格，Shift+Tab 移到上一格，按视觉行优先顺序穿过表头和表体。最后一个表体格按 Tab 新增一行并进入新行第一格。已有 Enter 保持向下同列；非末行仅移动光标，末行有内容时新增行，空末行按现有规则退出表格。表格外 Tab 保留原有缩进行为。IME 组合期间不触发导航或结构命令。

表头可清空，但仍作为表头单元格存在。修改列名不改分隔行。列对齐是结构属性，由表格工具条或右键菜单选择默认、左、中、右；只修改分隔行相应列的对齐标记。工具条可新增/删除当前行或列，删除表头行不可用，只有一列时删除列不可用。至少保留一行表体；删除唯一表体行时清空该行而不是删除表格。删除整个表格使用独立命令。已有外部文件若只有表头和分隔行，仍照常显示，Tab/Enter 可创建首行表体。

## 源码与事务规则

创建表格使用无标题占位文字的 GFM 源码：空表头、`---` 分隔行、空表体。所有列在同一行都有对应单元格；表格至少一列。菜单创建时在当前可编辑段落位置插入：空段替换为表格，段落尾插到段落后，段落中间先拆分前后文本并将表格放在中间。边界由已有块结构与 `EditableParagraphMap` 判定，不按相邻换行数量猜测；不得吞掉邻接标题、列表或引用。首版非空选区不触发菜单创建，避免隐式丢弃或猜测转换选中文字；后续可增加显式“文本转表格”。

管道表头创建保留用户输入的表头源码，除行内代码管道所需的最小转义外，仅补上分隔行和首行表体。两条创建路径共用表格源码生成和结果验证。LF/CRLF 跟随当前位置的文档换行风格，容器内表格保留引用或列表前缀。首阶段只支持顶层普通段落创建；容器内创建在通过前缀与解析回归后启用，菜单在尚不支持的容器位置禁用，而不生成位置错误的顶层表格。

所有创建、行列增删、对齐修改均产出一个 `EditTransaction`，携带结果光标字节位置。修改单元格文字尽量局部替换；增删列需要触及每一行，但仍作为一次原子事务提交。事务执行后使用重新解析所得投影定位光标，不依赖旧布局字节偏移。Undo/Redo 恢复源码、光标与视图状态。对齐与结构操作保留无关源码；只有受影响行允许按规范重写。

## 分层接口

`ui::widgets` 提供纯数据的表格选格面板及其命中、拖动和键盘结果。`ui::plugin::SemanticEditCommand` 扩展 `InsertTable { columns, rows }` 及必要的表格结构命令；行列数在边界处检查非零和资源上限，不在布局或序列化中散落魔法值。`app`/`appkit-shell` 负责菜单、焦点、IME 守卫及将面板结果送入活动 Markdown 插件。`textora-markdown` 负责识别表格上下文、生成源码替换、行列与对齐操作、结果光标和解析验证。两个产品入口复用同一命令执行协议。

表格源码模型至少包含表格完整范围、表头/表体行范围、每格正文范围、分隔行各列范围、对齐方式和容器前缀。源码模型只用于编辑规划，不代替现有 `BlockNode`/`LaidOutBlock` 渲染树。行列操作必须从解析器提供的源码区间建立模型；不使用简单的 `split('|')` 处理转义管道或行内代码。

## 分阶段实施与验收

每个阶段再按不超过三个文件的子任务提交；先固定接口和测试，再分别接 Markdown 核心、UI 控件和应用路由。每次提交前保证编译通过，完成重大阶段后运行 `./scripts/verify.sh`。

1. **核心创建协议**：先写复现测试覆盖空表解析、1/多列、段首/段中/段尾、空段、相邻块、LF/CRLF、Undo/Redo。实现表格源码生成、语义命令和光标落点。若当前解析器不能稳定识别全空表，先修复编辑态投影或调整生成策略，再开放菜单入口。
2. **管道表头 Enter**：建立严格识别与优先级，覆盖转义管道、行内代码、代码块、已有表格、非行尾光标以及正常正文 Enter 不回归。生成结果需重新解析为正确列数；一次 Enter 一次 Undo。
3. **选格面板与路由**：完成悬停预览、点击/拖动确认、越界扩展、数字输入、键盘操作、Escape、缩放/DPI 和焦点回归。确认前源码不变；确认后只执行一次创建命令。
4. **表格内导航与表头编辑**：补齐 Tab/Shift+Tab、最后一格增行、空格命中、文字与 IME 投影、表头行内格式、字面管道和粘贴换行。验证进入/离开表格时 Tab 与现有缩进不会互相抢占。
5. **结构工具**：加入行列增删、列对齐与删除表格；验证源码局部保真、不同容器、宽窄视口、包裹行、Undo/Redo 和大表性能。

验收必须使用真实解析、布局与应用事务链，不能只比较拼接字符串。关键场景包括：菜单建立空表后立即可见且每格可点击；管道表头 Enter 后焦点进入第一行表体；表头改名不改变列对齐；最后一格 Tab 正确增行；输入 `|` 不增加列；CRLF 不产生孤立 `\r`；一次结构操作一次 Undo；保存再打开的表格与编辑前视觉结构一致。

## 暂缓范围

跨单元格矩阵粘贴、拖动重排行列、拖动列宽、合并单元格和自动“选中文字转表格”不进入首轮。GFM 不直接表示合并单元格或固定像素列宽，若未来提供这些能力，需要另行定义持久化格式，不能只在 UI 中保存临时状态。
