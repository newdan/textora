# WYSIWYG 段落空格与首行缩进

用户已确认：保留已有 Markdown 缩进代码块；WYSIWYG 创建代码块使用围栏或显式命令；中文首行缩进由排版处理。

## 行为与边界

- 保持 CommonMark 解析器及源码模式语义，已有四空格代码块继续可读、可编辑。
- WYSIWYG 普通段落行首键入空格时，用普通文本空白表示，防止保存重开后成为代码块。采用 U+00A0 不换行空格保护段首空白，不添加隐藏标记，不全局关闭缩进代码块解析。
- 只干预普通段落/可编辑空段中的单行输入；代码块、列表结构缩进、多行 Markdown 粘贴维持原有语义。三个反引号和代码块命令仍可创建代码块。
- 添加“Markdown 首行缩进”设置，默认关闭。开启后普通顶层段落首个视觉行缩进两个正文字符宽度；后续换行回到左边界。标题、列表、引用、代码块不应用。此设置不写入 Markdown 正文。
- 首行缩进参与换行宽度、光标命中与布局缓存失效，随字号及 DPI 缩放。

## 实施子任务

1. 输入保护：新增独立输入处理模块与行为测试，在 augmenter 中接入；覆盖逐空格输入、段首已有正文、空段后输入正文、已有代码块、围栏、CRLF 和保存后重新解析。
2. 设置：UI 纯数据字段 `markdown_first_line_indent: bool`，设置页开关、app 持久化与动作桥接；新增默认值兼容与往返测试。按数据定义、持久化、UI 三个小阶段实施。
3. 排版：`MarkdownStyle.paragraph_first_line_indent: f32`，由渲染设置产生 0 或两个字号的偏移；仅首视觉行缩短可用宽度与平移行矩形。覆盖窄视口、精确和估计布局、源码投影与缓存切换。
4. 验证：针对性测试先失败再实现；运行格式检查和 `./scripts/verify.sh`；完成代码审查。

## 取舍

仅在内存禁用新代码块会造成保存重开语义变化；全局禁用解析会破坏已有文档。段首文本空格采用标准 Unicode 空白，使文本意图可持久化。真正的中文首行缩进使用独立排版设置，避免用正文空格模拟格式。
