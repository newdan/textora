# 段落、分割线、代码块的自动化编辑验收

## 目标与判定

测试持续覆盖源码编辑、块类型、可编辑空段、光标几何、应用事务历史及真实窗口截图。生成的文档全部位于 `target/editing-audit/fixtures/`，不得将 Computer Use 重放器指向用户文档。

判断依据是产品编辑语义，不能将“源码中几个换行”直接当作“显示几段”。允许规范已有的空白归一化；Undo/Redo 必须恢复精确源码和光标。新发现的失败保留为回归断言，不用截图基线把错误固化。

## 测试分层

| 层 | 入口 | 断言与覆盖 |
|---|---|---|
| 编辑语义 | `MarkdownEditorView::plan_edit` | 段落/分割线/围栏代码两两相邻，文首/文末，0/1/N 空段，LF/CRLF，空格/Tab，连续 Enter/Backspace，Delete 双向对照，行内样式及已有软/硬换行 |
| 空段与排版 | `MarkdownDoc::build_for_editing` 和真实 `ViewPlugin::render` | 增删一个可编辑单位、原子块类型保持；输入→删空时光标基线及高度保持，1×/2× DPI |
| 文件往返 | `DocumentView::from_file/save` | 加载及无编辑保存不得改变 LF/CRLF 字节；前置失败时跳过按键，避免误报 |
| 应用历史 | 应用事务分派和真实文档历史 | 216 个块组合/位置/命令场景，以及 432 个正反选区与历史分支；Undo/Redo 恢复源码、光标和选区，不模拟历史栈 |
| 原生窗口 | `scripts/editing-cua.mjs`，在 `cua_repl` 中执行 | 110 个独立 Markdown 文件；LF/CRLF、已有软硬换行、Shift+Enter、Unicode、选区粘贴、连续删除、容器代码、快速按键和导航；保存、撤销、重做、关闭重开及截图 |
| 整体检查 | `scripts/verify.sh` | 架构、格式、Clippy、工作区测试及 doctests |

代码位置：`crates/markdown/tests/system_boundary_audit.rs`、`crates/markdown/tests/support/editing_audit.rs`、`crates/app/src/dispatch/editor.rs` 中的 `editing_boundary_audit_undo_redo_restores_exact_source_and_cursor`。

## 可重复执行的流程

1. 运行 `./scripts/verify-editing.sh [输出目录]`。脚本构建当前 textora、建立独立测试 bundle、生成夹具及 manifest，然后执行格式检查、完整语义/排版矩阵、应用历史、测试流程自检及 `./scripts/verify.sh`。即使某个阶段失败，其他阶段仍执行并保留日志。
2. 在本机 Codex Computer Use 中按 manifest 中唯一的 `bundle.display_name` 绑定测试应用。macOS 必须解锁；工具权限由现有 Computer Use 授权管理。不要用 Shell、AppleScript 或系统事件注入替代真实 UI 输入。
3. 用 `cua_repl` 导入 `scripts/editing-cua.mjs`，读取 manifest，逐个调用 `beginEditingCase(app, manifestPath, caseId)` 和 `completeEditingCase(app, prepared)`，分开准备与重放，避免一次调用过长。仅通过观察到的 AX 元素定位文件对话框；必须观察到弹窗消失、目标文件成为窗口标题，不能把路径输入框中的文件名当作打开成功。切到源码视图后，使用本轮截图校准的 `sourceFocusPoint` 取得正文焦点，再按 grapheme 定位；保留 `position-source.png` 和 `position-markdown.png`，然后执行按键。不能仅以最终源码往返证明定位正确。
4. 查看截图：`before.png`、`step-01.png` 等中间帧、`after.png`、`undo.png`、`redo.png`。核对块类型、行数、间距、光标可见性、文本重叠/截断，和撤销后的布局恢复。每帧使用完整 AX 状态，避免 AX 树未变化时把尚未完成的编辑画面当作稳定结果。像素变化不能替代语义断言。
5. 用带 Pillow 和 NumPy 的 Python 执行 `scripts/editing-audit.py images <输出目录>`，检查逐按键的编辑区行特征是否改变、最终是否恢复。无布局变化必须复核焦点、按键和应用行为，不能仅凭源码往返就算通过。此检查按本轮 macOS 2× 编辑画布裁剪校准，窗口或主题变化时需重新校准并复核，不能代替语义断言。可选用带 Pillow 的 Python 执行 `scripts/editing-audit.py contacts <输出目录>`，生成对照图。当前对照图裁剪适用于本轮截图的 macOS 2× sidebar 布局；窗口尺寸/布局变化时必须调整裁剪，原始 PNG 始终保留。
6. 将模型/人工复核结论写入输出目录的 `visual-review.md` 与 `visual-review.json`，后者包括当前 manifest 的 `run_id`、`completed` 和全部用例的 `id`、`evidence_fingerprint`、`layout_passed`、`conclusion`。用 `python3 scripts/editing-audit.py fingerprints <输出目录>` 获取当前截图、源码和结果文件的 SHA-256 指纹，复核结论必须绑定此指纹，避免重试后沿用旧截图结论。执行 `python3 scripts/editing-audit.py summarize <输出目录>` 更新报告。完成复核与通过验收分别记录，已检查的失败不能标为通过。
7. 再次执行 `python3 scripts/editing-audit.py summarize <输出目录>` 取得最终验收退出码。专项语义验收与普通项目验证分开报告；汇总失败退出 1，缺少窗口/复核/阶段证据退出 2，全通过退出 0。

Computer Use 调用示意（在工具运行时中执行，不是普通 Node CLI）：

```javascript
let manifest = JSON.parse(await (await import("node:fs/promises")).readFile("<输出目录>/manifest.json", "utf8"));
let app = await cua.getApp(manifest.bundle.display_name);
let runner = await import("/绝对路径/textora/scripts/editing-cua.mjs");
// sourceFocusPoint 从当前源码画布截图确定，不复用其他窗口的坐标。
let prepared = await runner.beginEditingCase(app, "<输出目录>/manifest.json", "paragraph-rule-enter-1", { sourceFocusPoint });
// 下一次工具调用完成重放，便于提供进度及检查窗口。
let result = await runner.completeEditingCase(app, prepared);
nodeRepl.write(result);
```

重跑准备阶段先把旧日志、状态、截图和报告归档到 `archive/`，避免旧阶段状态污染新验收。每轮 manifest 使用新的 `run_id`，夹具放在 `fixtures/<run_id>/`；同一用例重试前，旧截图和结果移动到 `attempts/` 保留。每次重放再复制到独立的 `replays/<run_id>/<attempt_id>/`，避免应用复用旧文档内存；汇总器忽略旧轮 UI 结果，防止旧截图误算新版本通过。如遇焦点异常，可依据当前截图传入 `editorFocusPoint`（编辑画布中的已观察坐标）进行独立复核，不能使用未校准的固定坐标。文件弹窗创建、路径提交为异步步骤，必须确认 AX 状态后才能继续。Node 模块已加载后修改 runner，需要新文件路径或重置 REPL 才会加载新代码。

异常诊断可传入 `saveEachStep: true`，保留每次按键后保存的 `step-*.md` 与 `stepSources`。此选项会增加 Save 按键，必须标为诊断过程；汇总器将其计入独立的 diagnostic 类别并阻止替代默认序列验收。随后用默认序列独立复核，不能将诊断通过替代原场景通过。重试通过也不删除此前失败记录，时序原因未定位时应在复核报告中明确说明。

每次构建使用不同的 `.app` 路径、`CFBundleIdentifier`、`CFBundleName` 和 `CFBundleDisplayName`，并在 manifest 的 `bundle` 中记录可执行文件 SHA-256。按唯一显示名绑定后核对窗口菜单名称，避免工具按旧显示名路由到其他进程。重放文件名也包含尝试 UUID；窗口必须精确匹配该唯一文件名，不能只靠相同 case 名称判断打开成功。本轮真实窗口运行的应用路径与实际可执行文件指纹另记在截图复核报告中；不能将后续构建产物的指纹追认到既有截图。

## 输出与退出码

- `manifest.json`：用例源码、光标前缀、按键、预期结果、运行 ID。
- `build.log`、`formatting.log`、`semantic.log`、`file_roundtrip.log`、`history.log`、`harness.log` 与相应 `.status`：各阶段独立证据。整体验证结果另存为 `full_verify.log`、`full_verify.status`。
- `screenshots/<case-id>/`：原始 PNG、每帧 AX 状态、五阶段 Markdown、`result.json`（实际源码和匹配结果）。
- `summary.json`、`report.md`：机器可读及可阅读汇总；源码/截图复核未完成时不得给整个流程标记通过。
- 退出码 0：全部规定阶段通过；1：已有检查失败；2：原生窗口/截图复核尚未完成。

汇总器必须收到构建、格式、语义、文件往返、历史、测试流程自检、整体验证和截图比对八个阶段状态，并找到所有用例对应的阶段截图和逐项视觉结论，以及下述七项必需原生专项；任何缺失都不能通过。`scripts/tests/test_editing_audit.py` 复现并防止缺失阶段、缺失中间帧、错用用例结果、无效重放和未逐项复核导致的假通过；`scripts/tests/editing-cua.test.mjs` 验证文件弹窗的异步关闭不会误判为文件打开。归档结果和当前轮结果按 `run_id` 隔离。

首轮分阶段复现时曾使用具名 `ignore` 隔离未修复用例，专项脚本始终传 `--include-ignored` 以暴露失败。当前专项回归已全部移除 `ignore`，普通 `cargo test` 同样执行。发现缺陷必须先复现再修复，不得跳过断言或修改预期使错误通过。

## 首轮发现的缺口

1. 原子块起点未进入统一空段删除，退格可能将分割线变成 Setext 标题，或破坏代码开围栏。
2. 分割线末尾 Delete 未保护最后一个结构换行，可将后段拼成 `---after`。
3. 原子块旁带 Tab 的空段被按物理换行删除，Tab 并入后一行后，分割线变成缩进代码。
4. 原子块旁存在可编辑空段时，部分 Delete 提前消费按键，无法逐段删掉空段。
5. 已有软/硬换行处 Enter/Backspace 不能恢复原分隔，可能连接成 `helloworld`。
6. 引用容器中的闭围栏被分类成普通代码体，Enter 退出行为不统一。
7. CRLF 文档在编辑前的保存检查中变为 `\r\r\n`，新增独立文件往返回归；前置失败的用例不继续发送编辑按键。
8. 代码正文误用标题/列表标记、硬换行规则；代码开闭围栏的结构换行缺少 Backspace 保护。

首轮建立验收过程并记录缺陷，当时没有改变产品编辑行为；后续修复和扩展验收见修复计划及当前运行报告。实际结果以输出目录中的日志、源码和截图为准。

### 断言本身仍需增强

1. 块尾往返已检查正文内容，但空段输入删空、相邻删除等部分矩阵主要检查空段数量和原子块签名，仍需补正文、行内样式、精确光标、选区和合法 grapheme 边界断言。某些普通代码行合并仅检查“发生变化”，还应核对具体结果。
2. 截图行特征只验证布局发生变化及恢复，排除了闪烁光标；不能据此证明横向位置、每个间距数值、换行位置和全部文本绘制正确。需要组件几何/受控截图预期，并继续复核原始 PNG。
3. 已失败、被前置条件阻断、生成时没有命中可编辑空段而跳过的场景，应分别计数。整体脚本失败会提前停止其后测试；既有单测存在，也不代表此次完整运行到了它们。

### 下一阶段的补齐与判定

先补 P0 的选区、光标路径、Shift+Enter、真实输入法和持续编辑状态；保存问题修复后补跑 CRLF 原生编辑。随后扩展历史交错、语法变体、粘贴、多块排版和保存重载。各阶段保持代码语义、应用事务和原生窗口三层可对应的场景 ID。

核心三种块、光标/选区位置与编辑动作的关键组合应完整枚举；宽度、字体和其他环境可使用两两组合，重点交互增加三维组合。再增加固定随机种子的持续操作序列，并把失败序列缩减为最小复现。每步核对内容、块结构、空段、光标/选区和历史，不只核对最终源码。

只有声明的支持范围中，必需组合没有缺失或被阻断、断言覆盖完整状态、真实窗口与代码结果一致、重复运行稳定，才能称为该范围内覆盖完整。当前尚未达到此条件。


## 扩展验收与修复

修复设计见 `docs/plans/2026-10-14-editing-boundary-repair.md`。原子块的可编辑空段和隐藏结构分隔由同一导航层判断；代码正文不使用 Markdown 标记删除规则，闭围栏识别使用容器路径。保存序列化不重复 CR，混合换行保持原字节，Undo/Redo 直接还原历史字节。共享运行时、应用单次和多次替换均在历史记录之前同步选区，并从历史中回读选区。

段落拆分的计划仅在源码更新与替换精确匹配后确认。记录局部逆替换和光标，不缓存每个拆分的整篇文档；来源支持 Undo/Redo 的源码同步，无关编辑变换偏移，修改边界使来源失效。持续实例用例不能用每步重建 view 的测试替代。

新增矩阵包括 432 个选区替换、432 个选区历史分支、162 个三块连续删除序列、固定种子 100 个块组的持续 Unicode 编辑，以及 48 组宽度、字号、主题、DPI、鼠标命中与 IME 取消几何。几何断言涵盖 X/Y/宽/高；原生重开截图是必需证据。快速按键以一次动作发送多键，中途不进行观察；Undo/Redo 使用动作的按键数作为历史条目上限，不能把每个按键视作必有一条历史。

本轮汇总统计所有保留尝试，互斥地记录默认序列通过、编辑失败、保存前置阻断、重放无效、待准备、待重放、诊断过程和缺少元数据的旧尝试。重放器在首次 UI 调用前写入 preparing 记录，准备成功后写 prepared，完成或失败再覆盖；调用方中断也能保留尝试身份和构建归属。代码层 IME 预编辑、取消及提交模拟不能代替系统输入法候选框的真实验证；其他平台和显示器也不得从 Mac 测试推定通过。最终覆盖完成状态、实际构建指纹、环境限制及失败原因以当前验收报告为准。

## 容器内代码专项

引用、列表及引用内列表的代码正文续行只复制 AST 所需容器前缀，字面 `>`、列表标记和 Tab 余量不作为容器结构。专项检查正反向合并、开围栏续行、Enter/Shift+Enter、闭合和未闭合末行，以及 LF/CRLF。原生样例在每轮构建冻结后执行；逻辑测试通过不能替代窗口证据。

## 本轮补充断言与环境记录

专项共 28 组。空段输入删空及相邻删除增加正文签名检查；空格转换成不换行空格时，光标应仍处于空白行，不要求等于唯一锚点偏移。代码末行补充 LF/CRLF、顶层与三类容器、闭合与未闭合围栏的 16 个真实渲染循环，检查 Enter 增加可见行，Backspace 恢复源码及光标 X/Y/宽/高。测试流程自检为 Python 23 条和 Node 20 条。

截图指标遇到缺帧、无效重放、旧构建或诊断序列时记录证据缺失，退出 2；已有图像断言失败退出 1，全部指标通过退出 0。完整验收仍需所有原生用例和逐帧复核。

全项目验证使用本地 HTTP 模拟服务，执行环境需允许 127.0.0.1 套接字。沙箱套接字限制导致的旧失败单独归档。提升权限环境曾暴露三项恢复超时，采样定位到工作区启动同步等待 FSEvents 注册。异步启动和独立关闭协议修复后，三项在原失败环境分别于 0.03、0.21、0.03 秒通过，原两秒断言未改；随后 notora-app 438 项库测试全部通过。文件监听阻塞修复后的 `editing-monitor-audit` 轮 `./scripts/verify.sh` 已完整运行并退出 0，包含架构、格式、工作区 Clippy、全部单元/集成与文档测试。此后连续保存误报的修复使用 `editing-complete-audit` 验证；长代码光标问题又触发产品修复，该轮完整验证以 143 主动终止，不能沿用为当前源码的通过结论；分环境补测记录仍保留。原生键鼠/截图的锁屏阻断另行记录，不能据代码回归推定窗口验收完成。

原生长用例可依次调用 `beginEditingCase`、`replayEditingActions` 和 `verifyEditingHistory`，在编辑及历史重开之间让出控制。中间记录保持 `passed:false`、`replayStage:prepared`，并标记 `nextPhase:history`；中断不得被汇总为通过。原 `completeEditingCase` 接口保留，仍执行同一套按键与检查点。

需要进一步限制单次调用时长时，把 `verifyEditingHistory` 拆为 `replayEditingHistory` 和 `finishEditingCase`：前者只撤销与重做，后者关闭重开并给出最终结果。历史完成后仍记录 `passed:false`、`nextPhase:reopen`。

原生历史重放在每个 Undo/Redo 按键后读取完整无障碍树，使下一键与当前窗口同步；源码定位、每次编辑和最终检查点仍单独截图。发生服务超时时，保留失败尝试，以新夹具重跑。普通弹窗状态读取不重复截取像素，不能由此省略任何验收 PNG。

夹具源码定位从文首/文末较近一侧按完整字素簇移动，校验 cursor_prefix 位于全文字素边界；CRLF 和组合 emoji 各算一个字素。定位截图及中间帧仍需复核。发现中间行为与目标落点不一致，即使最终源码往返相同，也必须排除该尝试并独立重跑，不得仅凭最终源码通过。

可通过 `sourceTogglePoint` 指定已观察的界面模式按钮坐标；重放器先取新截图再点击，并记录坐标。输入源对照中曾出现 Cmd+Shift+M 不切换、界面按钮正常的现象，原因尚未确认，不可据此改业务逻辑。只有 Source 定位截图确有行号、Markdown 定位截图确实回到渲染视图且中间编辑落点正确，才接受该尝试。真实 IME 诊断中一次 nihao 为字面输入，尚不能认定候选、确认或取消通过。

原生慢环境使用有界阶段：`openEditingCase` 打开独立夹具，`startEditingPosition` 初始化 Source 起点，重复调用 `advanceEditingPosition`（每批最多四个字素导航键），待 remaining 为零后调用 `finishEditingPosition`。再执行编辑、历史及重开。未完成定位禁止开始编辑，同一尝试禁止重复发送编辑序列；这些协议都有流程自检。高层 begin/position/complete 接口保留用于调用时长不受限的环境。

历史阶段同样使用 `startEditingHistory` 初始化，再重复调用 `advanceEditingHistory`：每批最多四个历史键，每键后重新观察窗口；Undo 完整后才保存 undo 检查点，Redo 完整后才允许重开。所有中间结果保持未通过，并记录 historyProgress。高层 replayEditingHistory 仍按同一协议执行。当前测试流程自检合计 46 项。

## 长时间验收的文件监听与夹具回收

2026-10-15 的原生批量保存关闭复现了主线程同步等待 FSEvents 注册。监听后端现在在工作线程初始化，UI 只发布最新目录集合；工作线程按差集更新订阅，保留不变目录。连续未处理请求读取最新集合，不重放过期目录。每个成功的订阅变更、路径批次和失败都发布类型化结果并唤醒事件循环；订阅完成或失败会请求一次文件安全检查，以覆盖注册空隙。退出发送停止状态，不在窗口线程等待系统注册或后端析构。

回归通过可控后端检验系统调用阻塞时请求和关闭仍可完成，并覆盖差量更新、部分失败状态、连续请求合并、后台初始化失败和完成唤醒。原生重放在保存重开、截图和源文核对完成后关闭当前唯一夹具页签；若关闭未生效则保留为重放失败，不生成通过证据。

此修改改变了生产构建。旧轮 `editing-final-audit` 的 41 个通过只适用于旧二进制；新的 `editing-monitor-audit` 必须独立完成全部原生检查，不继承旧轮通过状态。

工作区恢复复测进一步确认，环境差异会暴露另一条生产同步等待：`notora-core::WorkspaceFileMonitor::start` 等待 FSEvents 就绪后，工作区后台准备才能返回。新增可控注册门闩复现启动等待，以及索引线程依赖监听通道断开才能关闭的问题。监听器结果采用 `Ready / Changes / Failed`；工作区激活不等待平台注册，Ready 后补扫注册期间的变化；失败或断连向产品报告，索引线程仍处理用户命令，命令所有权结束后退出。此修复属于独立工作区模块，当前冻结 textora 构建的截图归属保持不变；旧环境失败记录保留，最终以修复后的复测结果为准。


## 必需原生专项的完成门槛

110 个固定按键用例与以下七项专项共同构成原生验收：真实系统输入法、画布鼠标边界与拖选、视觉行导航、真实窗口缩放、长文档滚动与光标、批量保存关闭、页签及应用重启后的焦点。具体场景与必需帧在 manifest 的 `required_native_checks` 中列出；汇总器使用内置完整列表校验，删掉 manifest 条目也不能规避要求。

专项证据存放在 `native-checks/<专项 ID>/`。每个规定阶段保存 `<stage>.png` 和 `<stage>.ax.txt`，`result.json` 记录当前 `run_id`、`id`、`build`、`replayValid:true`、`passed`、按执行顺序排列的 `observations:[{stage,...}]`，以及具名 `assertions:[{name,actual,expected}]`。实际行为断言必须来自当前窗口操作、保存内容或观察；`actual` 与 `expected` 不一致时，即使写入 `passed:true` 也判失败。输入法阶段必须真正显示组合/候选，字面输入或粘贴中文不替代 IME。

逐帧复核另存为根目录 `native-review.json`，包含当前 `run_id`、`build`、`completed` 和 `reviewed_checks:[{id,evidence_fingerprint,layout_passed,conclusion}]`。指纹按同一 `case_fingerprint` 规则绑定各专项目录的原始截图、AX、源码和结果，不包含根目录复核文件。缺少候选截图、旧构建、旧观察指纹、漏项或断言不符均阻止完成；这些门槛由 Python 回归验证。

当前七项专项尚未取得本轮全部证据。它们和固定矩阵分别报告，不由代码层模拟、已有其他构建截图或固定矩阵通过数推定完成。Computer Use 按当前截图选择点击坐标和输入源，保留每一步实际操作及源文断言；不得用 Shell 键盘注入替代。


### 专项夹具与重放顺序

`prepare` 为七项专项创建 `native-fixtures/<run_id>/` 模板，并在 manifest 中记录 `path/source`。长文档包含 80 组中英混排、分割线和长代码行；批量关闭提供三个独立模板；重启夹具使用 UTF-8 BOM 和 CRLF。每次实际重放仍须复制到新的 UUID 路径，不能反复使用已被应用缓存的模板路径。

Computer Use 可使用 `editing-cua.mjs` 导出的 `openFixture(app, replayPath)` 打开这份独立副本，并以 `capture(app, capturesDirectory, stage)` 保存规定阶段的 PNG/完整 AX。在第一次 UI 操作前初始化 `result.json` 为 `passed:false/replayValid:false`，按真实执行顺序追加 observations 和具名断言；只有完成全部步骤后才能记录有效重放。失败和重试均保留，人工/模型复核最后绑定指纹。

| system-ime | 在段落中显示真实组合和候选，组合内退格，Escape 取消；再次提交后 Enter 只确认候选。检查撤销/重做。再在代码正文中完成组合、提交、历史，保存重开。 |
| pointer-boundaries | 分别点击正文、可编辑空段、分割线边缘和代码行，插入/删除后核对准确位置；鼠标拖选跨块替换，检查源码、选区、历史与重开。 |
| visual-navigation | 在长段的自动换行中使用上下及当前平台的行首/行尾键，截图确认视觉位置，再编辑、撤销、重做、重开。 |
| resized-wrapped-layout | 用真实窗口边缘拖拽缩窄，检查中英换行、代码框和光标。另定位长代码行末，确认末尾文字及光标进入代码框视口，插入标记核对准确字节位置，检查跨行选区高亮的裁剪；撤销后源码恢复。缩窗后编辑，再恢复尺寸并重开。不得用代码层模拟窗口尺寸替代。 |

### 专项取证接口

`scripts/editing-native-cua.mjs` 提供 `beginNativeCheck`、`observeNativeStage`、`recordNativeAction`、`assertNativeValue`、`finishNativeCheck`。调用方仍通过 Computer Use 执行真实键鼠操作。每次 begin 归档旧尝试、创建 UUID 夹具并在打开前写入未通过状态；observe 必须按规范顺序取证，拒绝跳项和重复阶段；finish 检查全部原始截图、AX 和显式行为断言。有效重放中的断言不符保留为失败，不能以 finish 调用成功充当行为通过。

截图接口可能返回 JPEG 字节，即使证据文件采用统一 `.png` 名称。使用 Pillow 等能识别实际格式的解码器获取尺寸，不能按扩展名直接读 PNG 头。缩窗诊断曾因此产生取证断言失败，原始帧实际从 2022×1648 缩至 1302×1648；保留该尝试，在新构建重跑，不修改失败断言为通过。

完整代码回归包含会创建原生窗口的测试，须先完成这些窗口阶段，再启动 Computer Use。只有确认后续检查不创建或激活窗口时，剩余纯代码回归才可与 Computer Use 并行；无法确认时保持串行。窗口阶段并行运行可能触发焦点变化保护，使文件对话框和重放失效。输入法候选在切到其他应用回复时可能自动提交；需要候选阶段的原始截图，不能用回复后已经提交的中文推定候选通过。实体输入次数或确认操作不确定时保留诊断，不能误报重复提交缺陷。

完整流程自检合计 Python 24 + Node 22 = 46 项。`verify-editing.sh` 同时执行两份 Node 测试。

### 最终快照一致性回归

连续保存触发过同内容冲突副本：监听器遇到磁盘 revision 改变后，先确认磁盘与本地快照内容是否相同；相同则更新基线，不生成冲突文件。runtime 使用保存路径的 `document_save_snapshot`，保证 BOM 与 CRLF 字节表示一致。三个新增失败回归（监听器两项、真实文档/worker 一项）均已转绿。修复改变生产构建，`editing-monitor-audit` 的 33 个矩阵和专项探索、`editing-self-save-audit` 的中间构建均保留；最终验收目录为 `target/editing-complete-audit`，不得沿用前两轮通过数。

### 长代码横向视口与组合输入回归

代码长行保持原始逻辑行及源码换行。横向视口保存编辑实例的偏移：光标仍在可视区时保持画面稳定，越过边界或尺寸／正文收缩时才调整；估算布局不得覆盖按实际字形测得的偏移。源码更新的查询布局与实际绘制布局通过同一入口继承视图状态。绘制、命中测试、选区与搜索使用同一组行坐标，高亮和组合下划线裁剪在代码框内。

代码块的无选区组合与已有选区替换组合共用预览布局，临时文字不写入源码。回归检查绘制光标与候选锚点一致、长组合可见、取消后恢复几何及原字节；覆盖普通／引用／列表代码块、LF／CRLF、中文、长组合、组合字符和 emoji。连续 Left、行内插入、重新点击和窗口宽度往返另有回归。加入延迟光标显示与手动滚动取消回归后，边界回归共 33 组。

`editing-viewport-audit` 和 `editing-code-viewport-audit` 保留被替换方案、失败尝试与修复前的原生证据；最新生产实现使用 `editing-scroll-save-audit` 重新冻结，完整代码验证已通过。专项临时目录运行会记录原始和复制后二进制的 SHA-256，仅用于避免 macOS CFBundle 扫描巨大 deps 目录造成的定位延迟；最终完整检查仍执行原始 `./scripts/verify.sh`。原生矩阵与七项专项只接受最新冻结构建的独立证据，目前因窗口工具报告锁屏而尚未完成，不得将代码验证通过表述为整体通过。

快速连续编辑的批次仅保存整组按键后的截图，图像度量检查最终布局恢复；逐个按键的用例还必须逐步产生布局变化。批次记录标注 `capture_scope: batch-final`，不能据此声称看到了批次内的中间画面。两类用例均保留源码、历史、全部规定截图和逐帧复核门槛；缺失批次的最终截图仍判证据未完成。该规则有先失败后通过的回归。

原生断言在记录时转换为可忠实归档的 JSON 值并保存快照，再比较归档结构；不同 JavaScript 上下文的数组／对象原型不参与行为判定。非有限数值、嵌套 undefined 等不能忠实归档的输入会被拒绝。跨上下文与观察后原对象变更均有回归；已完成的失败尝试保留，用新夹具重放，不将历史结果改为通过。
