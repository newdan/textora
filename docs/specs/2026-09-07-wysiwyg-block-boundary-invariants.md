# WYSIWYG 空行占位的根因与块边界不变量

## 结论与范围

空行问题的共同根因是编辑入口使用了互不一致的边界定义：Markdown 原始换行、可见内容边界、块的完整源码范围和排版间距不能互相替代。排版已经识别为空段的位置，如果输入、删除或合并仍按原始字节猜测，下一次解析就会多出空段、吞掉空段，或生成真的空标题。

本轮在既有 `EditableParagraphMap` 和段落编辑修复上继续审查，保留原有用户修改。开始时 Markdown 库 1256 项测试通过；补充测试又复现了闭合 ATX 标题和隐藏尾空白的剩余缺口。期间工作区基线由 `23f4bba` 更新为其他任务创建的 `41efaf4`；本轮未执行提交命令，验证以最终工作区文件为准。

现行基础语义见 [段落编辑规范](2026-09-06-wysiwyg-paragraph-edit-semantics.md)，既有复现矩阵见 [空段边界审查](../plans/2026-09-06-wysiwyg-empty-paragraph-boundary-audit.md)。本文件补充边界定义、参考依据与新回归，不将历史审查的失败数量当作当前状态。

## 四类空白必须分开

| 类型 | 含义 | 编辑行为 |
|---|---|---|
| 语法分隔 | 维持 Markdown 块独立所需的空行 | 不独立占一条编辑行 |
| 可编辑空段 | 用户建立的空白正文段落 | 有真实布局行、源码锚点和光标位置，可逐个增删 |
| 元素间距 | 标题 margin、分割线上下间距、段间距 | 纯排版属性，不参与删除计数 |
| 语法内空内容 | 空标题、空列表项、空引用或代码中的空行 | 按所属块的编辑协议处理 |

例如 `a\n\nb` 没有独立空段，`a\n\n\nb` 有一个；文首和文末采用各自的边界规则。不能把“Enter 固定插两个 LF”或“Backspace 删除整个换行串”当作所有场景的通用算法。

## 参考实现与适配取舍

[Typora 官方空白与换行说明](https://support.typora.io/Line-Break/)明确区分新段落和单个换行：Enter 建立段落，Shift+Enter 插入段内换行；编辑视图与导出对空白的保留也不同。这支持以编辑语义解释输入，不能仅凭源文件有几个换行判断视觉空段数量。公开材料没有提供 Typora 内部编辑器源码，本方案不声称复刻它的内部实现或所有按键细节。

[ProseMirror 的公开命令源码](https://github.com/ProseMirror/prosemirror-commands/blob/master/src/commands.ts)将 Enter 分派到代码换行、块附近建段、空块提升和块拆分，将双向删除分派到选区删除与方向对应的块合并；标题起点/终点通过节点位置判断。这说明可复用的工程原则是“先识别语义操作，再生成事务”。Textora 使用源码作为持久化事实源，不照搬其文档树作为主模型。

三种路线的取舍：

1. 对不同元素调整占位高度或光标偏移：无法修正源码增删不对称，排除。
2. 改为可变富文本文档树并重写 Markdown 序列化：能表达块命令，但会显著扩大源码保真、历史、容器及增量更新的迁移范围，本轮不采用。
3. 源码持久化不变，统一空段映射和解析投影边界，生成原子源码事务：采用。已有编辑布局与历史可继续复用。

## 单一事实源及执行顺序

```text
源码 + 光标/选区
  → 解析块结构 / 可见内容投影
  → EditableParagraphMap（空段数量、容器归属、隐藏分隔）
  → 段落创建 / 内容清空 / 最近空段删除 / 块合并
  → EditTransaction（源码替换 + 结果光标）
  → 重新解析并注入空段
  → FlatLine（布局几何）
  → 命中、导航、光标、IME
```

- 创建一个普通空段时，按映射计算必要分隔；列表续项、空项退出、代码换行继续采用各自协议。
- 删除内容导致段落变空时，Backspace、Delete 和选区删除共用 `erase_range`，一起移除不再需要的分隔。
- 块边界删除先查询最近可编辑空段。存在时只移除一个；不存在时才进入合并或原子块保护。
- 最终合并也通过映射取得唯一隐藏分隔的完整源码范围，带空格/Tab 的分隔与裸空行等价。标题尾空白不属于段落硬换行，须在块类型已知后解释。
- 标题位置是互斥的起点、中部、终点。起点前插普通空段并保留标题；中部采用既有拆分语义；终点在完整标题源码之后建段。
- 可见末尾可以位于行内闭合标记之前，也可以对应投影的源码末端。零宽投影 span 不应使真实可见端点失效。语义判断使用有效可见 span 与投影范围，源码替换使用完整语法边界。
- 快速筛选只排除明确位于文字内部的输入，不用 Markdown 标记字符白名单充当语义判断；普通词中/词尾退格继续避免全文解析。
- `ui` 保持纯数据输入，不依赖 app 状态；本轮未增加几何偏移补丁。

## 本轮新增复现与修复

表中的 `|` 表示光标，`\n` 表示逻辑换行。

| 场景 | 修复前实际结果 | 修复后的语义 |
|---|---|---|
| `# Title| ##`，Enter | `# Title \n##`，闭合标记生成新的空标题 | 保留 `# Title ##`，在后方建立普通空段 |
| `# Title| ##\n\n\ntail`，Delete | 删除闭合标记前空格，空段仍在 | 删除后方一个空段，原标题源码完整 |
| `# **Title** ##` 的可见末尾，Enter/Delete | 零宽 span 导致有效内容末端未被认作块尾 | 可见 span 端点与完整投影端点均可识别 |
| `a\n\nx| \n\ntail`，Backspace | 留下 `a\n\n \n\ntail`，出现两个空段 | 与 Delete、选区清空一致，只保留一个空段 |
| `# **Title** ##\n\n|tail`，Backspace | 仅删换行后 `##` 暴露为正文 | 合并为 `# **Title**tail`，去掉块级闭合标记并保留加粗语法 |
| `# Title ##\n \ntail`，双向合并 | 只扫描连续换行，遗漏带空格的隐藏分隔 | 从同一空段映射取完整分隔范围，一次完成合并 |
| `# Title ##  \n\ntail`，Delete | 标题尾两个空格被误判硬换行，绕过语义合并 | 根据 Heading 类型解释尾空白，再按完整块边界合并 |

最终合并不是简单删除“可见标题末尾到下一段开头”的全部字节，否则会同时删掉行内 `**` 或链接目标。双向合并共用 ATX 闭合尾缀边界，只移除可选块级尾缀。转义的 `\##`、不属于闭合序列的 `Title#` 保留；空标题合并保留开头 `# ` 所需的空格。

## 验收覆盖

- 既有矩阵：文首/文中/文末，0/1/N 空段，正文、标题、分割线、列表、引用、代码、表格，LF/CRLF，Unicode grapheme。
- 新增矩阵：普通/加粗/链接/闭合标题，可见末尾与完整源码末尾，Enter、Delete、Backspace、隐藏尾空格/Tab、最终边界合并、EOF 与原子后继保护。
- 真实布局验证：新段前后行数、空态→输入→删空几何、1×/2× DPI、命中及 IME 的既有回归。
- 应用事务验证：新增闭合标题 Enter/双向合并与尾空白删空，Undo/Redo 精确恢复源码和光标，包含 CRLF。
- 整体验证：`./scripts/verify.sh`，包含架构边界、格式、Clippy、工作区测试与 doctests。

自动测试使用真实 Markdown 解析、编辑策略、布局引擎及应用事务；本轮没有进行原生窗口鼠标/键盘的手工交互验证。
