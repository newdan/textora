# Markdown 代码块 ASCII 框线图固定网格渲染设计

**日期：** 2026-07-15  
**状态：** 已确认，待实施计划

## 目标

Markdown 预览自动识别由 Unicode 框线字符组成的 ASCII 图，并使用固定列网格渲染。中英文混排时，所有边框端点、竖线与交叉点必须落在同一逻辑列，避免依赖字体 fallback 的自然字形宽度而造成右边框错位。

处理仅影响 Markdown fenced code block 的预览渲染，不修改源 Markdown 文本。

## 非目标

- 不把 ASCII 图转换为流程图、SVG 或可交互节点。
- 不更改普通代码块、语法高亮、复制结果或源文本。
- 首版不在焦点位于代码块时提供网格化光标命中、选择映射或输入法坐标。
- 首版只为常用轻线框字符提供几何绘制；罕见框线字符可以安全降级为字体字形。

## 识别规则

在代码块布局阶段，对原始行执行纯函数检测。仅当同时满足以下条件时标记为 ASCII 图：

1. 代码块至少包含两行非空文本。
2. 至少包含一个角点字符：`┌`、`┐`、`└`、`┘`。
3. 框线字符总数达到最小阈值，且分布在至少两行。

框线字符集合至少包含：`─`、`│`、`┌`、`┐`、`└`、`┘`、`├`、`┤`、`┬`、`┴`、`┼`。

未满足规则的代码块沿用当前渲染路径。识别不会因行宽不一致而失败；恰恰应由固定网格消除这种视觉差异。

## 布局模型

为已识别的代码块构造独立的纯数据网格布局：

- 一个 grapheme cluster 对应一个或多个逻辑单元格。
- ASCII 字符和框线字符宽度为 1 列。
- CJK 与全角字符宽度为 2 列。
- 组合标记不额外占列，并附着在其所属 grapheme cluster。
- 其他字符首版按 1 列处理。

每一行记录其单元格序列和总列数。代码块以所有行的最大列数作为内容宽度。实际 `cell_width` 在渲染时从当前代码字体的等宽列宽取得，所有元素的 x 坐标均由 `column_index × cell_width` 计算，而不是累计字体 shape advance。

网格模型属于 `crates/markdown`，只描述 Markdown 代码块的渲染输入；`ui` 不依赖 Markdown 或 app 层状态。

## 渲染模型

`LaidOutBlockKind::CodeBlock` 扩展可选的网格化展示数据。渲染时：

1. 普通代码块继续调用既有整行文本渲染。
2. 已识别图表逐 grapheme cluster 按网格列位置放置文本。
3. 常用框线字符改由几何线段在单元格内绘制。横线、竖线、角点、T 型连接和十字连接共享一套字符到连接方向的映射。
4. 普通文字继续复用现有字体 shaping，并在其 1 列或 2 列分配区域中对齐。

几何框线不受字体 fallback 影响，因此右边框的逻辑列和视觉端点均可严格一致。罕见或未映射的框线字符仍按网格 x 坐标用当前字体绘制，不得导致 panic。

## 编辑态与降级

首版仅在非活动代码块启用网格化预览。若光标或选区进入代码块，使用现有文本渲染与现有 source projection，保证编辑、光标、选择和 IME 行为不回归。代码块重新失焦后恢复网格预览。

代码块内容超出视口时，继续使用现有 code block 裁剪策略。检测或网格构造失败时安全回退到普通代码块渲染。

## 测试策略

- 识别：典型框线图命中；普通源代码、单行文本和仅含单个框线字符不命中。
- 网格：中英文混排的多行图具有相同右边界列；组合字符不增加列数。
- 框线：常用 11 个轻线字符映射到正确的连接方向和几何线段。
- 渲染：网格块中同列竖线发出相同 x 坐标的绘制命令。
- 回归：活动代码块走普通代码渲染路径；既有 Markdown 和 code block 测试保持通过。

## 验收标准

给定包含中文标签和 Unicode 框线的多行代码块，预览中的左右边框、分隔线和交叉点按源文本逻辑列对齐；普通代码块与编辑中的代码块显示行为保持不变。
