# mmap 节点拖拽排序与层级调整设计

日期：2026-07-12  
状态：已确认

## 1. 背景与根因

当前 `MindmapView` 已具备整节点选中与键盘层级调整能力，但节点选中只绘制一条 `1px` 的焦点描边，卡片填充、层级和阴影均不变化，复杂导图中难以辨认。

鼠标输入链路也仅支持两类语义命中：标题文字的 `TextCaret` 与卡片对应源码范围的 `SourceObject`。按住并移动鼠标会被解释为标题文本选择；卡片目标在移动期间被直接忽略。因此，画布没有拖拽会话、落点候选、排序预览或用于移动子树的源码事务。

现有 `Cmd+[` / `Cmd+]` 只能改变节点的标题层级标记，不能重新排列节点在同一父节点下的顺序。需要把节点移动抽象为通用的画布拖拽协议，由 mmap 根据自身树结构生成一次原子源码事务；不得把 MMF 节点树或索引泄漏进 `app` 或 `ui`。

## 2. 目标

- 让整节点选中态在任意主题和密集导图中一眼可辨。
- 从节点卡片非标题区域开始拖动，在拖动期间显示节点投影、引导线和实时落点反馈。
- 从拖动投影的左侧寻找最近的合法节点作为锚点。
- 投影与锚点横坐标接近时，将节点插入锚点的同级序列；否则将节点移动为锚点的子节点。
- 同级插入根据释放位置相对锚点垂直中心的位置确定前置或后置。
- 被拖节点的整个子树、属性与备注原样移动；一次拖放只产生一个 Undo 单元。
- 根节点固定：不可拖动，也不可作为同级插入目标。
- 保持 `ui → app → markdown` 的依赖方向和现有统一编辑事务模型。

## 3. 非目标

- 多节点拖拽、框选、跨文档拖放和系统剪贴板拖放。
- 通过拖拽编辑标题、属性或备注内容。
- 修改根节点或创建第二个根节点。
- 自动滚动、折叠节点、拖拽手柄及新的导图布局模式。
- 为 mmap 在 `app` 中新增专用树状态或事件分支。

## 4. 已确认交互

### 4.1 启动与视觉反馈

1. 鼠标按下卡片的非标题区域时，照常选中该节点并记录为潜在拖拽源。
2. 指针移出按下点超过现有 `5px` 抖动阈值后，进入拖拽态；标题区域继续只做光标定位与文本选择。
3. 原节点以弱化透明度保留在原位，拖动投影卡片跟随指针。
4. 从拖动投影卡片的左侧中心绘制引导线到当前锚点卡片的右侧中心，明确表达“向左寻找父级或同级参照”的关系。
5. 指针释放前实时展示有效或无效落点；取消、无候选或非法候选均不改源码。

### 4.2 左侧锚点与落点规则

候选锚点为当前投影位置左侧、且不属于拖动子树的节点。候选按其卡片右侧中心到投影左侧中心的欧氏距离排序，取最近者；根节点可作为子级锚点，但永远不是同级排序锚点。

设拖动投影左侧横坐标为 `drag_x`，候选卡片左侧横坐标为 `anchor_x`，布局层级间距为 `level_indent`。当：

```text
abs(drag_x - anchor_x) <= level_indent × 0.35
```

落点为同级排序：

- 指针纵坐标小于锚点卡片垂直中心：移动到锚点之前；
- 指针纵坐标大于等于锚点卡片垂直中心：移动到锚点之后。

其他情况为子级落点：将拖动节点追加为锚点最后一个直接子节点。该规则让水平位置表达层级意图，垂直位置只在同级模式下表达前后顺序。

同级候选必须与拖动节点原父节点相同；否则同级落点无效。这样不会因为视觉上接近的不同分支而生成跨父级、但层级标记未变化的错误结构。

### 4.3 非法落点

以下情形没有有效落点，投影与引导线使用主题的弱化/错误反馈色，释放后取消：

- 拖动根节点；
- 锚点是拖动节点自身或其任意后代；
- 同级落点指向根节点；
- 同级落点已经是拖动节点当前位置（例如移到自身相邻边界而不产生顺序变化）；
- 当前 MMF 源码无法解析，或拖拽期间文档 generation 已改变。

## 5. 选中与拖拽视觉规范

### 5.1 整节点选中

`NodeSelected` 渲染为三层、按以下顺序叠加：

1. 卡片内的半透明 `selection` 强调层；
2. 向外扩展一个语义化焦点间距的圆角描边，宽度为常规边框的两倍；
3. 使用 `focus_ring` 的高对比外描边。

普通节点边框仍保留，避免选中态只依赖颜色差异。新增的间距、描边宽度和拖拽透明度均归入 `MindmapGeometry` 或 `MindmapCanvasTheme`，不得在 canvas 中写魔法值。

### 5.2 拖拽反馈

- 原节点：正常布局位置保留，但使用主题化的 `drag_source_alpha`。
- 拖动投影：使用选中卡片样式与 `drag_preview_alpha`，不参与布局或命中。
- 同级落点：在锚点卡片上方或下方绘制横向插入线；锚点保留浅色强调。
- 子级落点：强调锚点卡片，绘制从锚点右侧到投影左侧的引导线。
- 无效落点：不显示插入线，投影与引导线使用 `drag_invalid` 颜色。

## 6. 架构边界

### 6.1 `ui::plugin`

新增不认识 MMF 的纯数据协议，描述自绘插件的结构化拖放：

```rust
pub enum CanvasDragPhase {
    Start,
    Update,
    Drop,
    Cancel,
}

pub struct CanvasDragRequest {
    pub phase: CanvasDragPhase,
    pub source_range: Range<usize>,
    pub pointer_x: f32,
    pub pointer_y: f32,
    pub offset_x: f32,
    pub offset_y: f32,
    pub source_generation: u32,
}

pub enum CanvasDragResponse {
    Ignore,
    Preview(CanvasDragPreview),
    Apply(EditTransaction),
}
```

`CanvasDragPreview` 只包含投影矩形、引导线、目标强调和有效性等通用绘制数据；其中不含 `Node`、父子索引或 MMF 语法。`app` 只保存此通用会话状态并把请求转发给活动自绘插件。

### 6.2 `app`

`app` 负责识别卡片非标题区域按下、复用 `PLUGIN_SELECTION_DRAG_THRESHOLD_PX` 切换拖拽阶段、转发统一 `CanvasDragRequest`、请求重绘，并仅在插件返回 `Apply(EditTransaction)` 时执行既有事务校验与 Undo 记录。

`app` 不判断锚点、层级或源码范围的语义；鼠标释放、失焦、切换标签和 generation 变化都发送 `Cancel`，保证不会留下悬挂预览。

### 6.3 `markdown::MindmapView`

`MindmapView` 持有可丢弃的 `MindmapDragState`，用互斥枚举表达无拖拽、拖拽预览和无效预览，而不是多个布尔值。它基于 `LayoutTree`、`HitMap`、当前 `Tree` 与 `LayoutConstants`：

- 从 `source_range` 确认拖拽节点；
- 排除根节点、源节点及源子树；
- 计算最近左侧锚点与同级/子级落点；
- 为 canvas 生成投影、引导线和插入线；
- 在 `Drop` 阶段生成局部 `EditTransaction`；
- 在 `Cancel`、源码更新、解析失败或事务后清除拖拽状态。

## 7. 源码移动事务

拖放不得重序列化整棵 `Tree`，而是用解析器已确认的范围构造局部事务。

### 7.1 读取与删除

拖动源使用 `subtree_source_range` 加上与相邻标题分隔符一致的删除范围，完整保留标题、节点属性、备注和所有后代。移动前从原位置删除该文本块；任何插入位置都先以删除后源码坐标重新计算，避免源节点位于目标之前时产生偏移错误。

### 7.2 同级排序

- 前置：插入到锚点标题行起始处；
- 后置：插入到锚点 `subtree_source_range.end` 处；
- 移动块的标题层级与锚点层级相同；若原层级不同，对源节点及全部后代的 `heading_marker_range` 统一增删 `#`，保持相对深度不变。

### 7.3 子级移动

移动块插入到锚点 `subtree_source_range.end`，成为其最后一个直接子节点。源节点及全部后代的标题层级统一调整为“锚点层级 + 1”及其原相对深度。插入文本遵从原文档的换行风格，且不破坏节点属性、备注、代码围栏或全局属性。

### 7.4 原子性与选择

事务只包含非重叠 replacement，并携带提交时的 `source_generation`。app 沿用现有事务验证，失败则整笔拒绝。成功后选中移动完成后的节点子树；Undo/Redo 各只恢复或重做一次完整移动。

## 8. 测试与验收

### 8.1 纯函数测试

- 候选选择：最近左侧节点、相同距离的稳定 DFS 决胜、排除源子树与根节点规则。
- 落点分类：横坐标阈值、锚点上/下方的同级前置/后置、子级追加。
- 非法状态：根节点、后代锚点、空候选、过期 generation。
- 编辑计划：同父排序、跨父移动为子级、移动含属性/备注/多层后代的子树、换行风格、单步 Undo/Redo。

### 8.2 渲染与集成测试

- `NodeSelected` 同时输出强调填充和加粗焦点描边。
- 拖动预览输出投影、引导线以及对应的同级插入线或子级强调；无效落点不输出可提交指示。
- app 的鼠标按下、跨阈值移动、释放仅在合法 `Drop` 时执行一次编辑事务。
- 标题区域拖动仍为文本选择，不能启动节点移动。
- 失焦、切换标签、取消和源码更新均清除拖拽预览且不改文档。
- 完成后运行 `cargo test -p textora-markdown --lib`、`cargo test -p textora-app --lib -- mmap_`、`cargo check -p textora-app`；重大改动的最终集成阶段运行 `./scripts/verify.sh`。

## 9. 取舍

已确认采用“拖拽投影 + 左侧锚点”，而非将目标卡片切为上/中/下三区或引入专用拖拽手柄。该方式直接映射导图从左到右的父子层级，保持标题直接编辑不受干扰，也不需要让用户学习额外控件。
