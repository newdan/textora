# Notora 编辑区设计

日期：2026-08-03

状态：已确认

## 1. 目标

为 Notora 右侧编辑区建立稳定的信息与交互层级，让用户可以在同一上下文中完成标题编辑、笔记状态确认、目录与标签管理，以及正文编辑。

本设计遵循以下原则：

- 文档内容、笔记属性和正文编辑命令具有清晰边界；
- 标题只有一个真源，不在标题栏与正文之间产生重复状态；
- 工作区位置只表达当前活动工作区内部的目录；
- 正式标签由头部属性区维护，不再从正文 hashtag 推导；
- 加密属性在创建时确定，编辑区只显示状态，不提供修改入口；
- 新建笔记通过面板一次确认类型、位置和存储方式；加密选项在密钥服务和安全验收完成前不可用；
- `ui` 只接收纯数据输入，领域状态到 UI 输入的映射由 `notora-app` 完成。

## 2. 决策优先级

本文档覆盖 [`2026-08-03-notora-layout-localization-content-tags-design.md`](./2026-08-03-notora-layout-localization-content-tags-design.md) 中“正文标签语法”和“保存与索引数据流”关于标签真源的设计。

从本文档开始：

- 头部标签是笔记正式标签的唯一编辑入口；
- 正文中的 `#hashtag` 只是普通正文和全文搜索文本；
- 工作区扫描不得再用正文 hashtag 覆盖 `note_tags`；
- 已经存在于 catalog 中的标签关联应在升级时保留为正式标签。

本文档不改变固定三栏布局、中文界面和编辑区最小宽度等其他既有决策。

## 3. 整体结构

编辑区从上到下分为五个区域：

```text
┌────────────────────────────────────────────────────┐
│ 产品设计复盘                               标题栏   │
│ 创建 08-03 10:20 · 修改 5 分钟前 · 已保存  ☆ 🔒 🗑 │
│ 位置  当前工作区 / 产品 / Notora   标签  设计/UI  │
├────────────────────────────────────────────────────┤
│ ↶ ↷  H1  B  I  S  <>  •  1.  ☑  🔗   预览  ⋯    │
├────────────────────────────────────────────────────┤
│                                                    │
│                    编辑器正文                       │
│                                                    │
└────────────────────────────────────────────────────┘
```

五个区域分别是：

1. 可直接编辑的标题栏；
2. 创建与修改时间、保存状态和笔记操作区；
3. 当前工作区内的位置与正式层级标签属性区；
4. 只包含正文编辑命令的编辑器菜单；
5. 编辑器主体。

标题、状态和属性区属于文档头部。编辑器菜单在正文滚动时保持可用；当垂直空间不足时，文档头部可以折叠为包含标题、保存状态、星标和加密状态的紧凑栏。

## 4. 标题栏

### 4.1 标题真源

Markdown 和 Mindmap 文档的第一个一级标题是唯一正式标题。标题栏是该一级标题的可视化编辑入口，不建立独立的标题副本。

普通编辑模式下：

- 标题栏显示并编辑第一个 H1 的文本；
- 编辑器主体不重复显示由标题栏承载的 H1；
- 修改标题栏会更新底层文档中的 `# 标题`；
- 外部文件变更修改 H1 后，标题栏同步刷新；
- 文档没有 H1 时，首次输入标题会在文档顶部创建 H1；
- 其他 H1 属于正文内容，不参与标题栏同步。

规范化后的 Markdown 结构为：

```markdown
# 标题

正文内容
```

源码模式显示完整 Markdown，包括第一个 H1；普通编辑模式由标题栏承载该 H1。

文档类型的展示规则固定如下：

- Markdown 普通编辑模式由标题栏承载第一个 H1，正文不重复绘制该 H1；
- Mindmap 的标题栏仍编辑同一个第一个 H1，但画布保留根节点，因为该节点是思维导图结构的一部分，不是重复的装饰标题；
- TXT 使用第一行作为标题，正文继续遵循 TXT 编辑器的行结构；
- 源码模式始终显示完整源码，包含 Markdown/Mindmap 的第一个 H1；
- 文档没有可投影标题时，标题栏的首次提交按文档类型的规范化规则在源码中创建标题。

TXT 文档没有 H1，继续使用第一行作为标题。工作区外部文件优先显示文件名，不强制修改其正文结构。

### 4.2 标题编辑交互

- 标题栏使用无边框单行输入样式；
- `Enter` 确认当前输入并把焦点移到正文；
- `Escape` 撤销本次尚未提交的标题输入；
- 失焦后进入正常自动保存流程；
- 标题修改与正文修改共享 dirty、保存中、已保存和保存失败状态；
- 空标题在编辑期间显示“无标题”占位，最终保存时生成 `# 无标题`；
- 修改标题不自动修改文件名；
- 现有“重命名”动作只表示重命名文件。

## 5. 状态与操作区

状态区左侧展示时间和保存状态，右侧展示星标、加密状态和删除操作：

```text
创建 2026/08/03 10:20 · 修改 5 分钟前 · 已保存    ☆  🔒 已加密  🗑
```

### 5.1 时间与保存状态

- 创建时间不可编辑；
- 修改时间默认显示相对时间，悬停显示完整时间；
- 保存状态至少包含保存中、已保存和保存失败；
- 保存失败必须具有可辨识的错误状态，不能只依赖修改时间表达。

### 5.2 星标

- 星标是可操作的笔记元数据；
- 未星标使用轮廓图标，已星标使用填充图标；
- 操作完成后刷新卡片列表、星标导航和当前编辑区状态。

### 5.3 加密状态

加密属性在创建笔记时确定，创建后不可修改。编辑区中的加密图标只显示持久化属性，不表示当前运行时是否已经解锁。

显示状态：

- `🔒 已加密`；
- `🔓 未加密`。

加密状态控件必须满足：

- 不响应点击；
- 不进入键盘焦点；
- 不显示按钮式悬停效果；
- 使用默认指针而不是可点击指针；
- 悬停提示“加密状态在创建笔记时确定，创建后不可更改”；
- 已加密笔记即使当前可编辑，仍显示“已加密”。

领域模型使用互斥状态表达持久化属性：

```rust
pub enum NoteEncryption {
    Unencrypted,
    Encrypted,
}
```

未来如需表达运行时访问状态，应使用独立枚举，不得在 `NoteEncryption` 上叠加多个布尔字段。

### 5.4 删除

- 普通笔记的删除表示移入回收站；
- 永久删除只在回收站状态中提供；
- 永久删除必须二次确认；
- 删除操作与星标、加密状态之间应保留明显间距，降低误触风险；
- 窄窗口下可以将删除收进“更多”菜单。

## 6. 位置属性

编辑区使用“位置”而不是“工作区”作为控件名称：

```text
位置  当前工作区 / 产品 / Notora ▾
```

其语义严格限定为当前活动工作区内部的目录选择：

- 当前活动工作区名称只读；
- 目录选择面板只展示当前工作区目录树；
- 工作区根目录是合法位置；
- 选择其他目录会移动笔记文件；
- 移动前必须先完成当前自动保存；
- 目标存在同名文件时不得覆盖，用户必须重命名或取消；
- 移动完成后笔记保持打开，`NoteId` 不变；
- catalog、卡片列表、目录导航和当前选中状态同步更新；
- 本控件不支持跨工作区移动；
- 外部文件和回收站笔记不显示位置选择器。

## 7. 正式层级标签

### 7.1 标签真源

头部属性区是正式标签的唯一编辑入口：

```text
标签  [产品/Notora ×] [技术/Rust/UI ×] [+ 添加]
```

正式标签属于 Notora catalog 元数据，不写入正文，也不通过 Markdown front matter 双向同步。

正文中的 hashtag：

- 不自动创建正式标签；
- 不自动关联或移除正式标签；
- 仍作为普通正文参与全文搜索；
- 工作区重新扫描时不得影响 `note_tags`。

### 7.2 层级表达

第一阶段使用 `/` 分隔标签层级，完整路径作为标签的规范名称：

```text
产品/Notora/编辑器
技术/Rust/UI
```

父级导航节点由完整路径动态计算，不要求第一阶段引入独立的父子关系表。

标签输入规则：

- `/` 是唯一层级分隔符；
- 自动移除分隔符两侧的多余空格；
- 禁止空层级，例如 `产品//编辑器`；
- 禁止只包含分隔符或空白的标签；
- 同一笔记不得关联重复的完整路径；
- 输入时优先补全已有标签和当前路径下的子标签；
- `Enter` 接受当前完整路径；
- 标签胶囊支持显式移除；
- 标签超过一行时折叠剩余项并显示数量，用户可以展开查看。

### 7.3 迁移

从正文 hashtag 标签模型升级时：

- 保留 catalog 中已有的 `note_tags` 关联；
- 现有扁平标签直接成为正式顶层标签；
- 不因升级重新解析正文或创建新的关联；
- 升级完成后，扫描和保存链路不再用 hashtag 集合替换正式标签；
- 标签变更通过明确的 metadata action/effect 持久化；
- 标签变更完成后刷新搜索索引、标签导航和当前卡片查询。

## 8. 编辑器菜单

编辑器菜单只包含修改正文的命令，不放置移动、删除、星标或加密等笔记级属性。

Markdown 菜单建议按以下顺序分组：

```text
撤销/重做
标题级别
粗体/斜体/删除线/行内代码
项目列表/编号列表/任务列表/引用/代码块
链接/图片
预览/分栏/专注模式/更多
```

菜单根据文档类型提供不同输入：

- Markdown：提供完整 Markdown 编辑命令；
- TXT：只提供撤销、重做、查找等通用命令；
- Mindmap：提供节点、层级、展开和收起等专属命令。

窄窗口下优先保留高频命令，其余命令进入“更多”菜单；不得通过缩小点击目标来容纳全部命令。

## 9. 新建笔记

新建笔记时必须同时确定：

```text
文档类型    TXT / Markdown / Mindmap
保存位置    当前工作区 / 目标目录
存储方式    普通笔记 / 加密笔记
```

创建完成后：

- 文档类型按既有规则保持稳定；
- 保存位置可以在当前工作区内修改；
- 加密属性不可修改；
- 不应把三种类型和两种加密状态展开成六个平级菜单项；
- 现有“新建笔记”入口应打开轻量创建面板，集中选择类型、位置和存储方式。

创建面板的提交状态必须保留在产品层草稿中：提交中不可重复提交，失败保留类型、位置
和存储方式以便重试，Escape 清空草稿；回收站状态不能打开创建面板。

## 10. 文档状态差异

### 10.1 普通工作区笔记

展示完整标题栏、时间与保存状态、星标、加密状态、删除、位置、标签、编辑器菜单和正文。

### 10.2 外部文件

- 标题优先显示文件名；
- 显示文件路径和手动保存状态；
- 不显示位置选择、正式标签、星标和加密状态；
- 删除操作不进入 Notora 工作区回收站。

### 10.3 回收站笔记

- 正文只读；
- 不允许修改标题、位置和标签；
- 操作区提供恢复和永久删除；
- 永久删除必须二次确认。

### 10.4 没有选中笔记

- 展示编辑区空状态；
- 不渲染可以产生笔记操作的空标题栏和属性控件。

## 11. 响应式行为

- 宽编辑区展示全部时间、属性和常用编辑命令；
- 中等宽度优先缩短时间文本，标签折叠为单行，低频编辑命令进入“更多”；
- 最窄模式保留标题、保存状态、星标和加密状态；
- 创建时间和删除操作可以进入信息提示或“更多”菜单；
- 紧凑模式下删除从头部主操作位移入编辑器菜单的低频/“更多”命令；
- 位置与标签属性允许分成两行，不得截断当前目录或标签而导致含义不明；
- 所有可点击目标维持一致的最小命中区域。

## 12. 架构边界

`ui` 层定义不包含 Notora 领域类型的纯数据输入，例如：

```rust
pub struct EditorHeaderInput {
    pub title: String,
    pub title_editable: bool,
    pub created_label: String,
    pub modified_label: String,
    pub save_status: SaveStatusInput,
    pub starred: bool,
    pub encryption: EncryptionStatusInput,
}

pub struct EditorPropertiesInput {
    pub location: Option<LocationInput>,
    pub tags: Vec<TagChipInput>,
    pub editable: bool,
}
```

具体命名在实施阶段按现有 UI 组件体系确定，但必须满足：

- `ui` 不依赖 `DocumentView`、`NotoraState`、`NoteId`、`WorkspaceId` 或 `TagId`；
- `notora-app` 从领域状态和 EditorRuntime 提取数据并构造 UI 输入；
- widget action 使用通用组件 action，由 `notora-app` 映射为 `NotoraAction`；
- 标题、位置和标签持久化通过 action/effect 边界执行；
- 文件系统和 SQLite 操作不得发生在 UI widget 内。

## 13. 验收标准

### 13.1 标题

- 修改标题栏后，底层 Markdown 第一个 H1 与标题一致；
- 外部修改第一个 H1 后，重新加载可以更新标题栏；
- 普通编辑模式不重复展示标题 H1；
- Mindmap 普通编辑模式保留作为树根的第一个 H1，标题栏与根节点内容同步；
- 没有 H1 的文档可以通过标题栏创建 H1；
- 修改标题不会重命名文件。

### 13.2 位置

- 只能选择当前活动工作区内的目录；
- 移动后 `NoteId` 和当前编辑会话保持稳定；
- 同名目标不会被覆盖；
- 移动完成后导航、卡片和 catalog 一致。

### 13.3 标签

- 头部可以创建、补全和移除层级标签；
- 正文 hashtag 变化不会改变正式标签；
- 工作区重扫不会覆盖正式标签；
- 升级前已有的标签关联不会丢失；
- 标签变更后导航、搜索和卡片标签摘要一致。

### 13.4 加密状态

- 已加密与未加密状态均有明确只读展示；
- 加密状态不能点击、聚焦或通过编辑区修改；
- 创建笔记时可以选择普通或加密存储；
- 创建完成后不存在切换加密属性的产品 action。

### 13.5 文档状态

- 普通笔记、外部文件、回收站笔记和空状态只显示各自合法的控件；
- 回收站笔记不能通过标题、位置或标签控件产生修改；
- 窄窗口下编辑区不出现控件重叠或不可理解的截断。
