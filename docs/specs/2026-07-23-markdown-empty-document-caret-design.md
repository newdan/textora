# Markdown WYSIWYG 空文档输入光标修复设计

## 背景

新建空 Markdown 文档后，WYSIWYG 编辑区域不显示输入光标。Markdown 编辑插件声明 `handles_own_rendering() == true` 且 `shows_cursor() == false`，因此光标由 `textora-markdown` 自行绘制，app 层不应叠加光标。

## 目标

- 新建内容为空的 `.md` 文档时，在字节位置 0 显示输入光标。
- 光标使用普通 Markdown 正文的字体尺寸、行高、编辑区左侧起点与闪烁状态。
- 保持非空 Markdown 文档、Markdown 预览模式和 app 原生编辑器行为不变。

## 方案

采用插件层根因修复：先在 `MarkdownEditorView` 的渲染边界增加空文档回归测试，模拟新建文档的首次状态同步与渲染，断言绘制列表中存在使用主题光标颜色且与插件编辑区域有可见交集的矩形。光标以插入点为中心绘制，因此位于编辑区左边界时允许半个光标宽度落在边界外。

失败测试用于区分两类根因：

1. 插件未收到或未保留字节位置 0 的光标状态；
2. 空布局无法生成有效的光标几何，或生成的矩形落在编辑区域之外。

确认根因后，只修改对应状态同步或空文档几何分支。不会在 app 层增加空文档特判，也不会为整个 Markdown 布局引入合成文本块。

## 数据流

1. app 将空字符串源码和 `SetCursorByte(0)` 同步给 Markdown 编辑插件。
2. `MarkdownEditorView` 构建空文档布局并计算字节位置 0 的光标矩形。
3. 插件在光标闪烁可见阶段向 `DrawList` 写入一个光标填充矩形。
4. app 按现有插件渲染流程提交该绘制列表。

## 测试与验证

- 新增失败测试：空 Markdown 编辑视图首次渲染后应绘制与编辑区域有可见交集的光标。
- 运行新增测试，确认修复前因目标缺失而失败，修复后通过。
- 运行 `textora-markdown` 相关单元测试和编译检查。
- 若修改跨越多个模块或影响公共布局行为，升级为运行 `./scripts/verify.sh`；否则保持最小验证范围。

## 非目标

- 不改变光标颜色、宽度或闪烁周期。
- 不调整 Markdown 正文布局、段落间距或空行语义。
- 不修改预览模式的交互行为。
