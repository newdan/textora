# 同父节点连线共享拐点轴设计

## 背景

思维导图目前在渲染每条连接线时，依据该线起点和终点的水平中点计算竖向拐点轴。该规则不表达“同一父节点的直接子连线属于同一分支束”的结构语义；当终点位置或布局细节变化时，兄弟连线可能在不同位置转弯。

## 目标

- 同一父节点到其所有直接子节点的连接线使用完全相同的竖向拐点轴。
- 保留现有的圆角折线、由父到子的线宽渐变、缩放和拖拽引导线外观。
- 将路由决定保存在思维导图布局结果中，渲染层只消费已确定的几何数据。

## 非目标

- 不改变节点卡片尺寸、层级水平间距或子节点纵向排布。
- 不统一不同父节点之间的拐点位置。
- 不调整连接线颜色、透明度或粗细主题配置。

## 方案比较

1. 在渲染阶段按连接线起终点继续独立计算中点。实现最少，但无法表达同父节点共享路由，不能解决问题。
2. 在布局阶段为每个父节点计算其直接子连接线的共享拐点轴，并把该轴写入每个子节点的 `LayoutNode`。渲染器传入该轴生成圆角路径。该方案将树结构语义放在布局层，且能以纯几何测试覆盖，采用此方案。
3. 在渲染阶段按相同起点临时分组并缓存拐点轴。该方案耦合绘制顺序与渲染状态，难以复用于拖拽预览，不采用。

## 架构与数据流

`layout::assign_positions` 已知父卡片右侧连接起点和下一层节点的左侧 x 坐标。它为每个父节点的所有直接子节点计算同一个 `connector_turn_x`：父连接起点与该层子节点左边缘之间的水平中点。该值随每个子 `LayoutNode` 一起保存；根节点没有入边，因此该字段为空。

`canvas::draw_connector` 将布局提供的拐点轴传给 `connector_centerline`。路径仍从父卡片右侧水平前进、围绕共享轴转为竖向、再转回水平并到达子卡片左侧。圆角半径仍受可用水平距离、垂直距离和线宽上限约束；空间不足时保留当前的直线降级行为。

拖拽引导线没有固定树父子关系，继续使用它自身起终点的中点，不读取 `LayoutNode` 的共享轴。

## 测试与验收

- 在 `layout.rs` 添加包含至少三个直接子节点的布局测试，断言它们的 `connector_turn_x` 相等，并位于父连接起点与子节点左边缘之间。
- 在 `canvas.rs` 添加路径测试，传入显式拐点轴，断言圆角路径的竖向段位于该轴，且不回退为直线。
- 运行 Markdown crate 的相关单元测试和 `cargo check -p textora-markdown`。

验收标准是：同一父节点的所有直接子连接线在同一条竖直轴处转弯；不影响其他父节点的独立路由，也不改变现有拖拽预览行为。
