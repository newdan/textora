# mmap 右侧风格面板与文件级主题设计

## 背景

当前 mmap 画布直接使用应用级 `Theme` 中的 `mindmap` 配色。不同 mmap 文件无法选择各自的视觉主题，用户也没有在导图界面中浏览或切换主题的入口。

本设计为 mmap 增加右侧“风格”面板。第一阶段只提供内置主题选择；主题写入 mmap 文件的全局 TOML 属性，因此同一窗口中打开的不同 mmap 文件可以使用不同主题，保存和分享文件后主题仍然保留。

## 目标

1. 仅在 mmap 视图中显示“风格”按钮。
2. 点击按钮后在画布右侧显示固定宽度的风格面板，不覆盖导图内容。
3. 通过两列导图缩略图直观比较并选择主题。
4. 每个 mmap 文件独立保存主题，主题选择不影响应用外壳、普通编辑器或其他文件。
5. 主题是固定视觉，不跟随应用浅色或深色模式变化。
6. 打开面板或切换主题时保持当前布局、缩放和导图视觉中心。
7. 保持 `ui` 与应用状态解耦：`ui` 只接收纯数据输入并输出语义动作。

## 非目标

- 不提供自定义配色或“新建配色”按钮。
- 不支持导入、下载或编辑用户主题。
- 不提供布局、节点尺寸、圆角、间距、字号或连线粗细设置。
- 不允许拖拽改变风格面板宽度。
- 不改变应用标题栏、侧边栏、状态栏及其他编辑器的全局主题。
- 不把面板开关、折叠状态或宽度写入 mmap 文件。

## 方案比较

### 方案 A：固定右侧面板

标题栏提供“风格”按钮，面板在内容区右侧占据固定宽度，画布视口相应缩窄。

优点：不会遮挡节点；选择主题时可持续观察完整画布；后续增加布局、节点和连线分区时不需要重做容器结构。

缺点：打开面板会减少画布可用宽度，需要明确保持视觉中心的视口规则。

### 方案 B：覆盖式抽屉

面板浮在画布上方，不改变画布尺寸。

优点：容器布局改动较小，打开面板时画布尺寸不变。

缺点：遮挡右侧节点，主题对比时无法观察完整效果；导图较大时尤其明显。

### 方案 C：可拖拽检查器

面板固定在右侧，但允许用户拖拽改变宽度并持久化宽度。

优点：可适配更复杂的长期风格编辑功能。

缺点：第一阶段只有主题选择，拖拽、最小宽度、命中区域和持久化会引入不必要的状态与测试成本。

本设计采用方案 A。

## 界面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 文件名                              [风格] [切换到源码视图] │
├──────────────────────────────────────────┬───────────────────┤
│                                          │ 风格           ×  │
│                                          ├───────────────────┤
│                 mmap 画布                │ 配色方案          │
│                                          │ [当前方案摘要]    │
│                                          │ [预览]  [预览]    │
│                                          │ [预览]  [预览]    │
│                                          │ [预览]  [预览]    │
├──────────────────────────────────────────┴───────────────────┤
│ 状态栏                                                       │
└──────────────────────────────────────────────────────────────┘
```

### 标题栏入口

- “风格”按钮只在当前插件为 mmap 时显示。
- 按钮位于现有“切换到源码视图”按钮左侧，使用调色板或画笔图标。
- 面板关闭时，tooltip 为“显示风格面板”；面板打开时，tooltip 为“隐藏风格面板”。
- 面板打开时按钮使用当前应用外壳的强调色，表达界面状态；该强调色不来自当前 mmap 主题。
- 点击按钮切换面板；点击面板右上角关闭按钮执行同一关闭动作。

### 面板容器

- 面板位于标题栏下方、状态栏上方、画布右侧。
- 逻辑宽度固定为 `280px`，实际绘制尺寸乘以 DPI。
- 面板与画布之间使用一条低对比度分隔线。
- 面板使用应用外壳主题绘制背景和文字，不随 mmap 画布主题改变。
- 面板默认关闭；开关状态只保存在当前标签页会话中。切换标签页时，每个标签页恢复自己的开关状态。
- 面板开关不写入文件、工作区或全局设置。

## 主题选择器

### 当前方案摘要

“配色方案”分区顶部显示当前方案摘要：

- 左侧显示方案的主要分支色条。
- 中间显示中文方案名称。
- 右侧显示展开或收起箭头。
- 初次打开面板时预设网格默认展开；点击摘要可折叠或重新展开预设网格。
- 当前方案摘要只控制网格显隐，不改变主题。

### 缩略图网格

- 使用两列网格；首批 6 个主题排列为两列三行。
- 每张缩略图约 `120 × 76px`，具体尺寸由面板内边距和列间距统一计算。
- 所有缩略图使用同一棵固定的三级微型导图，只改变画布、根节点、普通节点、分支和连线配色。
- 缩略图不显示常驻名称；悬停 tooltip 显示方案名称，以保留足够的预览面积。
- 当前主题使用深色或强调色粗边框和选中标记。
- 悬停只改变卡片边框，不临时应用主题，避免指针移动造成画布闪烁。
- 单击缩略图后立即更新当前 mmap 的画布和源缓冲区，不增加“应用”按钮。
- 键盘焦点进入网格后，可使用方向键移动选择焦点，按 Enter 或 Space 应用主题，按 Escape 关闭面板。

### 首批内置主题

| 稳定 ID | 显示名称 | 视觉方向 |
|---|---|---|
| `warm-night` | 暖夜 | 保留当前 mmap 的深色暖调 |
| `dawn` | 晨曦 | 浅色背景与珊瑚红分支 |
| `amber` | 琥珀 | 浅色背景与橙黄色分支 |
| `meadow` | 青禾 | 浅色背景与绿色分支 |
| `tide` | 潮汐 | 浅色背景与蓝青色分支 |
| `iris` | 鸢尾 | 浅色背景与紫粉色分支 |

稳定 ID 是文件格式的一部分，不随界面语言或显示名称变化。每个主题包含画布、节点、连线、分支调色板及语义状态颜色，但不包含几何配置。

## 文件格式与编辑语义

主题保存在 MMF 全局 TOML 属性块中：

````markdown
```toml mindmap
version = 1
layout = "auto"
theme = "tide"
```
````

- 已有全局属性块时，只更新已有 `theme` 值或插入新的 `theme` 字段。
- 文件没有全局属性块时，创建标准的 `toml mindmap` 块，并保留根标题和其余源码内容。
- 选择主题是一次普通文档编辑：立即更新内存中的源缓冲区、增加 generation，并将文档标记为未保存。
- 只有用户执行正常保存后，主题才写入磁盘。
- 相同主题再次被选择时不产生编辑事务，也不改变未保存状态。
- 旧文件没有 `theme` 字段时，使用内置默认主题 `warm-night`，但不自动修改文件。只有用户主动选择主题时才插入字段。

## 分层架构

### `ui`：纯主题数据与风格面板

`ui` 定义不依赖文档或 app 状态的纯数据边界：

- `MindmapColorScheme`：画布、节点、连线、分支和语义状态配色，不包含几何。
- `MindmapStyleOption`：稳定 ID、显示名称、缩略图所需的预览颜色和选中状态。
- `MindmapStylePanelInput`：面板可用状态、当前选择状态和可用方案列表。
- `MindmapStylePanelAction`：关闭面板、切换预设网格、选择主题。

互斥状态使用枚举表达，例如默认、已选择、未知 ID 和元数据无效，不使用多个布尔字段拼装状态。风格面板只消费输入并产生语义动作，绝不访问 `DocumentView`、`Workspace`、插件内部状态或文件系统。

内置 mmap 主题注册表也是纯数据，不执行目录扫描或其他 I/O。应用全局 `ThemeRegistry` 继续负责应用外壳主题，不能因 mmap 文件选择而改变。

### `app`：标签页状态与动作路由

`DocItem` 保存仅随标签页会话存在的风格面板显示状态。app 每帧根据活动插件、标签页状态及插件查询结果构造标题栏和风格面板输入。

用户选择主题后的动作流为：

```text
MindmapStylePanelAction::SelectTheme(theme_id)
  → app 验证活动标签页仍为 mmap
  → 向活动 ViewPlugin 发送设置 mmap 主题的语义消息
  → markdown 层规划并执行一次源缓冲区编辑
  → 文档 generation 与 dirty 状态更新
  → 下一帧查询新主题并重绘面板与画布
```

app 不解析 MMF TOML，不持有 mmap AST，也不复制内置主题颜色。它只负责把 UI 动作路由到活动插件，并把插件暴露的纯状态映射为 UI 输入。

### `textora-markdown`：MMF 解析、编辑和绘制

MMF 解析结果暴露当前主题选择及其必要的源码范围。MMF 编辑模块提供“设置全局主题”这一单一职责的编辑计划：更新字段、插入字段或创建全局属性块。

`MindmapView` 根据解析出的稳定 ID 从纯内置注册表解析颜色方案。绘制时只用所选方案覆盖 mmap 的颜色输入；几何继续使用既有配置。因此主题切换不会使布局、命中图或静态连接线几何缓存失效，只触发颜色重绘。

## 视口行为

风格面板打开或关闭时，画布可见矩形宽度发生变化，但必须保持：

- 当前 zoom 不变。
- 打开面板前位于画布可见区域中心的内容点，在新可见区域中仍位于中心。
- 不执行自动适配、回到根节点或重建布局。
- 画布滚动条根据新的可见矩形更新范围与滑块尺寸。

主题切换本身不改变可见矩形，因此不得修改 pan、zoom 或滚动条会话。

## 异常处理

### 未知主题 ID

文件中的主题 ID 不在当前版本的内置注册表时：

- 画布使用内置默认主题，保证文件仍可查看和编辑。
- 面板顶部显示“找不到主题：`<id>`，已使用默认主题”。
- 保留源文件中的未知 ID，不自动覆盖；用户主动选择新主题后才替换。

### 无效 MMF 元数据

全局 TOML 无法解析时：

- 沿用现有无效 mmap 的诊断画布。
- 风格面板仍可打开，以便用户理解功能状态。
- 主题缩略图禁用，显示“请先修复文件元数据”。
- 不尝试在无效 TOML 上叠加编辑或创建第二个全局属性块。

### 编辑失败或状态过期

若用户点击缩略图后活动标签页已经改变、插件不再是 mmap，或源码 generation 与编辑计划不一致，则丢弃该动作并重新读取当前状态，不修改其他标签页。编辑失败不得只更新面板选中态而不更新源缓冲区。

## 测试策略

### `ui` 组件测试

- 风格按钮只在输入声明为 mmap 可用时布局和命中。
- 打开状态使用强调色，按钮和关闭按钮产生一致的切换动作。
- `280px` 面板中 6 个缩略图按两列三行布局，卡片不越界。
- 缩略图命中返回对应稳定 ID；当前主题边框和选中标记正确。
- 悬停不产生主题选择动作。
- 键盘方向键、Enter、Space 和 Escape 行为正确。
- 默认、已选择、未知 ID、元数据无效四类状态的文案和禁用状态正确。

### MMF 解析与编辑测试

- 解析存在和不存在 `theme` 的全局属性块。
- 更新已有 `theme` 字段时只替换值范围，保留其余 TOML 和正文。
- 在已有全局属性块中插入 `theme`，不改变其他属性顺序或内容。
- 没有全局属性块时创建标准块，根标题及后续内容字节保持不变。
- 重复选择当前主题产生 no-op。
- 无效 TOML 不生成主题编辑计划。
- 未知主题 ID 可被解析并原样保留。

### mmap 绘制测试

- 6 个稳定 ID 均解析为对应固定颜色方案。
- 选定主题不随应用浅色或深色模式变化。
- 主题切换改变画布、节点、连线和分支颜色，但不改变布局矩形。
- 主题切换保留连接线几何缓存，只更新提交颜色。
- 缺少或未知主题时稳定回退到默认方案。

### app 集成测试

- 普通文本、Markdown 和小说视图不显示风格按钮。
- 两个 mmap 标签页独立保存面板开关状态和文件主题。
- 选择主题只修改活动 mmap，更新 dirty 状态和标题栏未保存指示。
- 保存并重新打开文件后恢复所选主题。
- 打开或关闭面板保持 zoom 和原视觉中心内容点。
- 切换标签页、切换到源码视图以及关闭标签页时不把动作错误路由到其他文档。

### 全面验证

本功能会涉及 `ui`、`app` 和 `textora-markdown` 多层协作，实施时必须拆分阶段，并在最终运行：

```text
./scripts/verify.sh
```

## 实施阶段建议

本功能预计修改超过 3 个文件，按项目约束拆为以下子任务：

1. **MMF 文件级主题协议**：内置颜色方案、全局属性解析、源码编辑计划与 markdown 层测试。
2. **纯 UI 风格面板**：标题栏入口、两列缩略图、纯输入/动作类型与 widget 测试。
3. **app 集成与视口保持**：标签页会话状态、插件消息路由、右侧 dock 布局和跨标签页集成测试。

每个阶段提交前必须通过对应 crate 的编译和测试，全部完成后再执行全面验证。
