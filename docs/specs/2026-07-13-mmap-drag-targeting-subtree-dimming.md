# mmap 拖拽目标匹配与子树置灰

## 目标

让 mmap 节点拖拽始终以被拖卡片的左边界选择目标节点，并在拖拽期间将源节点及其完整子树置灰。

## 背景与根因

现有实现已用拖拽预览卡片的左边界判定同级或子级，但候选节点筛选和“指针落在卡片内”的优先命中仍使用鼠标位置。抓取宽节点的不同位置会改变候选节点，导致目标层级与卡片实际几何位置不一致。

拖拽反馈只覆盖源卡片的背景，未覆盖后代卡片、文字、选中框和子树内部连接线，不能表达整棵子树正在移动。

## 拖拽目标规则

1. 以被拖卡片的 `left` 和垂直中心作为唯一候选几何基准；鼠标抓取点不参与候选横向匹配。
2. 每个候选使用卡片 `right` 和垂直中心参与距离排序；距离相同按 DFS 索引稳定排序。
3. 自身和全部后代永远不作为候选；根节点只能作为父级候选，不能作为同级插入锚点。
4. 当 `dragged.left <= candidate.right` 时，生成候选节点所在层级的前插或后插目标；纵向中心决定前后。
5. 当 `dragged.left > candidate.right` 时，生成候选节点的子级目标；纵向位置决定插入到第一个直接子节点前或末尾。
6. 落点仍须校验源码 generation、禁止拖根节点、禁止移动到自身后代以及禁止相邻同级的空操作。

## 拖拽视觉规则

1. 通用 `CanvasDragPreview` 保持纯 UI 数据，新增源子树卡片的屏幕矩形列表；不携带 mmap 节点或解析树状态。
2. markdown 层在建立预览时，将源节点和全部后代的布局矩形投影到该列表。
3. 渲染层根据该列表识别源子树：子树卡片、标题文字、选中框和内部连接线均使用 `drag_source_alpha` 降低透明度。
4. 浮动预览只绘制被抓取的根卡片；不复制子树内容，目标框、引导线与插入线保持既有语义。

## 范围与约束

- 仅修改 mmap 的候选计算与拖拽渲染，不调整源码移动事务、布局算法或 app 层事件转发。
- `ui` 只消费 `CanvasDragPreview` 的纯几何输入，不能依赖 markdown 或 app 状态。
- 新增测试覆盖不同抓取点、同级/子级边界、后代排除和整棵源子树的置灰命令。
